# 安全优化测试用例

生成日期：2026-06-12  
需求来源：`终版整理安全问题需求及解决方案.md`  
说明：安全用例仅允许在测试环境、Mock 环境或明确授权环境执行。涉及资金、密钥、内网 URL、恶意脚本、凭证失败频控的场景，执行前必须确认授权与回滚方案。

## 1. 资金与支付安全

### 1.1 越权退款与退款金额

#### TC-SEC-FIN-001 【Critical·Security】普通用户调用退款接口被拒绝 [SmokeTest]

| 字段 | 内容 |
|:--|:--|
| **测试点** | 越权退款：任意登录用户不可对任意订单发起退款 |
| **优先级** | Critical |
| **前置条件** | 测试环境存在用户 A、用户 B、用户 B 的可退订单或 payment_intent_id；用户 A 已登录 |
| **操作步骤** | 1. 使用用户 A token 调用退款接口并传入用户 B 的 order_no/payment_intent_id/amount <br> 2. 查看接口响应 <br> 3. 查询用户 B 订单、支付单、退款流水和余额 |
| **预期结果** | 1. 接口返回 403 或等价权限拒绝 <br> 2. 用户 B 订单状态、支付状态、退款流水、余额均不变 <br> 3. 安全日志记录越权拒绝，不记录敏感卡号或密钥 |

#### TC-SEC-FIN-002 【Critical·Security】退款金额以服务端订单可退金额为准 [SmokeTest]

| 字段 | 内容 |
|:--|:--|
| **测试点** | 退款金额拒收前端 amount，按原订单实付与可退余额计算 |
| **优先级** | Critical |
| **前置条件** | 管理员具备退款权限；存在实付金额为固定值的测试订单 |
| **操作步骤** | 1. 使用管理员身份发起退款，请求中传入大于实付金额的 amount <br> 2. 再传入小于、等于、异常格式 amount 进行对比 <br> 3. 查询退款请求发送到支付渠道的金额和本地退款流水 |
| **预期结果** | 1. 系统不信任前端 amount <br> 2. 超额或异常金额被拒绝，合法退款按服务端可退金额计算 <br> 3. 本地退款流水与支付渠道金额一致 |

#### TC-SEC-FIN-003 【Critical·Security】重复退款被幂等拦截

| 字段 | 内容 |
|:--|:--|
| **测试点** | 退款幂等键和重复请求防护 |
| **优先级** | Critical |
| **前置条件** | 存在一笔可退款测试订单；管理员具备退款权限 |
| **操作步骤** | 1. 对同一订单连续提交两次相同退款请求 <br> 2. 并发提交相同退款请求 <br> 3. 查询支付渠道请求次数、本地退款流水和订单可退余额 |
| **预期结果** | 1. 仅第一笔合法退款生效 <br> 2. 重复请求返回幂等结果或明确拒绝 <br> 3. 不产生重复退款流水，不导致余额或订单可退金额为负 |
