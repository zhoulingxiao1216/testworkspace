## 三、核心验收口径

| 主题 | 验收口径 |
|:--|:--|
| P0 阻断规则 | P0 任一未修复、核心链路失败或仍可匿名/越权触发时，安全上线结论必须为暂缓上线。 |
| 鉴权优先 | 匿名、普通用户、无权限管理员、跨用户数据访问必须按预期返回 401/403 或等价拒绝，不得产生副作用。 |
| 服务端可信 | 资金、退款、充值、提现、sender、group、URL、Schema、Excel 导出文本等关键值不得信任前端入参。 |
| 幂等与审计 | 退款、支付回调、余额调整、售后退款、代客登录等必须具备幂等、经办人和可追溯审计。 |
| XSS/注入防护 | HTML、v-html、innerHTML、Excel 导出、Lodop 消息等不执行恶意 payload；历史数据加载路径同样净化。 |
| 密钥与敏感数据 | 私钥、验证码、邮件正文、Token、Secret 不得公开静态访问、明文长期留存或在响应/URL 中泄漏。 |
| 受控执行 | 安全验证只在测试环境、Mock 环境或授权环境执行；生产环境只允许非破坏性配置核验和日志核验。 |

## 四、严重度画像

| 严重度 | 条目数量 | 主要风险 | 上线策略 |
|:--|--:|:--|:--|
| P0 | 8 | 资金完整性、支付伪造、密钥泄露、后台匿名写、地址 IDOR、IM 身份伪造 | 必须全部修复并回归通过 |
| P1 | 7 + 备注 2 点 | 高危鉴权、聊天 IDOR、存储型 XSS、SSO 开放重定向、凭证撞库、邮箱枚举 | 原则上上线前修复；若延期必须有明确隔离与风险接受 |
| P2 | 5 | Excel 公式注入、内容 XSS、扩展 DOM XSS、扩展 SSRF-like、验证码/邮件留存 | 可按风险窗口修复，但需纳入回归 |
| P3 | 2 | 代客登录审计、Lodop eval 纵深防御 | 可作为纵深防御跟进，不应影响 P0/P1 结论 |

## 五、主要风险与待确认项

| 风险 | 影响 | 建议 |
|:--|:--|:--|
| 安全测试环境与账号矩阵未提供 | 影响越权、角色、资金、IM 和后台写接口测试 | 提供普通用户、他人用户、管理员、无权限管理员、客服/IM 用户等账号。 |
| 资金链路真实扣款风险 | 退款、充值、提现、支付回调不可在生产直接攻击验证 | 使用沙箱、Mock 支付单、测试支付渠道和可回滚账户。 |
| IM WebSocket 与 Chrome 扩展环境依赖 | 需要可控 WS 服务、测试群、打包扩展和安全 payload 注入能力 | 先做代码审计和接口 Mock，再做受控联调。 |
| 密钥轮换验证依赖第三方 | WorldTrade 密钥迁移和回调验签需与万里汇侧协调 | 执行前确认沙箱密钥、回调样例和轮换窗口。 |
| 部分修复合并到其他计划 | P1-8、P0-7、P1-7 与 claude-plan 相邻 | 交接清单中标记合并执行，避免重复缺陷和重复用例。 |
