###✅ P0-1 越权退款：任意登录用户可对任意单退任意额  〔Critical · api-all · 源 SEC-04? 实为退款链路 / T5 / 蔡哥#24〕

- **需求（问题）**：退款接口 `refund` 落在用户态 `pay` 中间件组，只挂 `UserTokenMiddleware`（无管理员/角色校验）；退款金额 `amount` 直接取自前端请求，未按订单从服务端计算；也无订单归属校验。任意登录用户可对任意 `payment_intent_id` 退任意金额。
- **代码大概位置**：
  - 路由分组只有用户 token：[api-all/config/middleware.php:103](../../api-all/config/middleware.php:103)（`pay` 组 = `UserTokenMiddleware`/`UserHeaderMiddleware`）。
  - [api-all/app/pay/controller/PaymentController.php:288](../../api-all/app/pay/controller/PaymentController.php:288) `refund()` 直接 `$data=$request->post()` 透传 `order_no/payment_intent_id/amount`。
  - [api-all/app/pay/controller/PaymentNotifyController.php:98](../../api-all/app/pay/controller/PaymentNotifyController.php:98) 同样实现。
  - [api-all/app/service/payment/driver/StripePayment.php:494](../../api-all/app/service/payment/driver/StripePayment.php:494) `Refund::create([... 'amount'=>convertAmount($refundData['amount'])])` 金额来自前端。
- **解决方案**：退款接口移到管理端（`admin_b2b`）并加角色校验，或在方法内强制管理员鉴权；退款金额一律服务端按原订单实付计算，拒收前端 `amount`；加退款归属校验（订单属主/操作人）与退款幂等键，防重复退款。
- **验收**：普通用户调 `refund` 返回 403；退款金额以服务端订单为准；重复退款被幂等拦截。

### P0-2 万里汇支付回调未强制验签即可置为已支付  〔Critical · api-all · 源 SEC-04 / 扫描 api-all#1〕

- **需求（问题）**：`WanliPayment::notify()` 仅当 `Signature` 与 `Request-Time` 两个 header **都非空**时才验签，两者缺失则**跳过验签**，继续按 body 的 `requestId/tradeId` 找支付单并置 `STATUS_PAID`、把 `Quote` 置支付成功、触发建单。`wanliNotify` 又在用户 token 的 action 白名单内（免 token）。攻击者拿到/猜中一个待支付 `tradeId+requestId`、不带签名 header，即可把未支付订单刷成已支付。
- **代码大概位置**：
  - [api-all/app/service/payment/driver/WanliPayment.php:862](../../api-all/app/service/payment/driver/WanliPayment.php:862) `if(!empty($signature) && !empty($requestTime))` 才验签，否则不拒绝，:884 起直接置 `STATUS_PAID`。
  - [api-all/app/middleware/UserTokenMiddleware.php:95](../../api-all/app/middleware/UserTokenMiddleware.php:95) `actionWhitePathList()` 含 `wanliNotify`。
  - 注释打桩签名/示例数据待清理：[api-all/app/pay/controller/PaymentNotifyController.php:67](../../api-all/app/pay/controller/PaymentNotifyController.php:67)。
- **解决方案**：**缺 `Signature`/`Request-Time` 一律拒绝**，验签失败拒绝（把「提供才校验」改成「强制前置」）；验签通过后再把回调金额、币种、渠道、报价号、当前状态与本地待支付单严格比对才更新；删除注释里的打桩签名。Stripe 回调 `constructEvent()` 已正确验签，不动。
- **验收**：无签名/错签名/金额币种不匹配/重复回调全部被拒且不改状态；合法签名回调仍正常建单（回归）。

### P0-3 万里汇 WorldTrade 私钥位于公开静态目录  〔Critical · api-all · 源 SEC-17 / 扫描 api-all#4〕

- **需求（问题）**：`config/static.php` 开启 public 静态服务且静态文件中间件为空（`'middleware'=>[]`）；`public/storage/certificates/worldtrade/sandbox/` 下存在 `private_key.pem`（1708 字节，`-rw-r--r--` 全局可读），`public/generate_worldtrade_keys.php` 还会往该目录写密钥。视部署私钥可被 `GET /storage/certificates/.../private_key.pem` 直接下载，危及万里汇签名完整性。（运行时实际读取路径为 `config/cert/...`，但 `public/` 下是同一把私钥副本，暴露成立。）
- **代码大概位置**：
  - 文件存在：`api-all/public/storage/certificates/worldtrade/sandbox/private_key.pem`（另有 `public_key.pem`）。
  - [api-all/config/static.php:18](../../api-all/config/static.php:18) 开静态、中间件空。
  - `api-all/public/generate_worldtrade_keys.php`（写密钥脚本，应移除/迁移）。
  - 读取方：[api-all/app/service/payment/driver/WanliPayment.php:34](../../api-all/app/service/payment/driver/WanliPayment.php:34) + [api-all/config/payment.php](../../api-all/config/payment.php)。
- **解决方案**：把所有私钥移出 `public/`（受限权限的非静态路径或密钥管理）；删除现有公开 `.pem` 并**轮换**可能暴露的密钥（与万里汇侧协调）；加静态中间件/网关规则拒绝 `.pem/.key/.env` 与证书目录；移除或迁移 `generate_worldtrade_keys.php`。
- **验收**：`public/` 下无私钥；直接请求 `.pem` 被拒；万里汇签名/回调用新密钥仍正常。

### P1-1 api_tb/AuthController::refreshToken 未鉴权刷新淘宝 token  〔High · api-all · 源 SEC-10 / 扫描 api-all#7〕

- **需求（问题）**：`api_tb` 命名空间只挂 `UserHeaderMiddleware`+`SiteMiddleware`（后者只要求带 `site`），`AuthController` 类无中间件注解。`refreshToken()` 取当前生效淘宝 token、调第三方刷新、插新 token、把旧 token 置 `status=400`。任何能带 `site` 的匿名请求都能扰乱/接管采购账号 token 生命周期，且不记 admin_id。（注：同命名空间的下单/采购接口已加 `AdminTokenMiddleware`，见 §0.3，本条只剩 token 刷新无鉴权。）
- **代码大概位置**：[api-all/config/middleware.php:91](../../api-all/config/middleware.php:91)（`api_tb` 无 `UserTokenMiddleware`）；[api-all/app/api_tb/controller/AuthController.php:90](../../api-all/app/api_tb/controller/AuthController.php:90) `refreshToken()`（`login`/`callback` 同样无鉴权）。
- **解决方案**：把 token 刷新移到定时任务，或要求管理员/服务级鉴权 + 重放保护 + 绑定已认证主体的审计；响应只回操作状态，绝不回 token 明文。
- **验收**：无鉴权调用 `refreshToken` 被拒；授权途径刷新仍正常。
