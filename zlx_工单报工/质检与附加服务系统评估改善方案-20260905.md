## 0. 总体结论

当前系统对 QC/VAS 的支持程度是：**部分支持**。

系统已经具备三类基础能力：

1. **检品/附加项配置与计费快照**：`b2b_check_config`、`b2b_fjx_config`、`b2b_order_check_fjx` 已承载检品、普通附加项、设计类附加项、自定义附加项的选择、价格、数量与订单快照。
2. **设计类附加项的设计/打印状态与入库前拦截**：贴纸、吊牌、FBA、洗标有设计端保存、后台打印状态、PDA/后台入库前拦截。
3. **WMS/PDA 的扫码作业基础**：入库、质检、配货、打包、发货已有商品码/箱码/包裹码扫描、语音提示、蓝牙打印等能力。

但系统还缺少面向仓库现场生产的 **统一 VAS 工单执行层**。目前的附加项更像“收费与展示配置”，不是“可扫码领取、可防错校验、可完工记账、可绩效统计、可被全链路拦截”的生产任务。

核心短板：

- 没有“到货扫码后自动打印 QC/VAS 工票”的物理分流机制。
- 剪标、换标、换包装、拍照等实体 VAS 没有统一任务状态。
- 当前强拦截主要检查设计类附加项的 `design_status` / `print_status`，不能证明实体操作已完成。
- 换吊牌/贴标签缺少“旧商品码 + 新标签码”的双扫码比对。
- 员工产出数据分散在质检数量日志、库存日志、发货日志、商品问题工单、特殊附加项日志中，缺少统一绩效事件表。
- 耗材与人工成本尚未按实际完工事件自动归集到订单成本或财务结算。

一句话：**系统已有 QC/VAS 的配置、收费、展示、部分打印和局部拦截，但缺少工票化、扫码化、防错化、绩效化的现场执行闭环。**

## 3. 现场操作痛点与系统盲区（Pain Points & Gaps）

### 3.1 附加项从“收费配置”到“现场任务”中间断层

`b2b_order_check_fjx` 保存的是 `check_config`、`fjx_config`、`user_fjx_config` JSON 快照：`63:69:api-all/app/model/B2B/OrderCheckFjx.php`。这适合展示和计费，但不适合现场管理：

- 不能扫码领取。
- 不能分配工位。
- 不能记录每件/每批谁做了。
- 不能记录开始、暂停、完成、返工。
- 不能被后续流程按“未完成任务”统一拦截。

### 3.2 VAS 指令展示隐蔽，现场容易漏做

后台 `FjxDetail.vue` 能展示检品/附加项，但它是管理端订单详情组件，不是现场工位屏。WMS 质检页能看到设计类附加项摘要，但缺少“下一步必须做什么”的强引导。现场人员如果依赖订单详情、纸质单据、弹窗或口头沟通，漏做概率会很高。

### 3.3 缺少到货自动打票与物理分流

当前 WMS 打印能力已存在，但打印对象主要是箱码、配货单、装箱单；后台打印对象主要是标签/贴纸/FBA/洗标模板。未发现“到货扫码后，系统根据订单附加项自动打印 QC/VAS 工票”的流程。

直接后果：

1. 到货后无法即时按“检品、剪标、换标、换包装、拍照、设计打印”等工位分流。
2. 现场必须人工识别订单附加项。
3. 周转箱/商品离开收货区后，系统无法通过工票追踪当前应该在哪个工位。
4. 丢票、漏票、错票后没有系统自动复位机制。

### 3.4 设计/打印完成不等于实体操作完成

当前入库拦截关注贴纸、吊牌、FBA、洗标的 `design_status` 和 `print_status`：`71:139:api-all/app/admin_b2b/service/OrderDetailUpdateService.php`。但现场真正风险在于：

- 标签是否贴到了正确商品。
- 旧标是否已剪掉。
- 新吊牌是否对应当前 SKU/颜色/尺码。
- 洗标/FBA 标是否按客户模板贴好。
- 包装是否按指定 OPP、折叠、压缩、气泡膜完成。

打印完成只能证明“标签纸出来了”，不能证明“商品被正确处理”。

### 3.5 换标/贴标缺少双扫码防错

换吊牌/贴标签场景最容易发生“把 A 商品挂上 B 标签”。目前设计端能生成条码与保存设计，但没有现场动作要求：

```text
扫描旧商品码 -> 扫描新标签码 -> 系统比对预期 -> 允许确认贴标/换标
```

缺少这一步，会导致错误在打包/出库后才被客户发现，返工成本极高。

### 3.6 拍照与 VAS 完工未绑定

系统已有缺陷照片上传：`1311:1348:api-all/app/admin_pda/controller/OperationalGenuineController.php`、`58:72:global-wms/pages/guide/entering/components/CaptureUpload.vue`。但它更像问题备注，不是“拍照服务已完成”的生产凭证。对于客户付费拍照、商品报告、换包装前后对比等，需要：

- 明确拍摄角度/张数要求。
- 自动绑定订单明细、VAS 任务、员工、时间。
- 完成后生成绩效事件。
- 未完成时禁止入库/打包/发货。

### 3.7 绩效统计依赖二次加工，不能实时计件

现有日志分散在 `b2b_order_quantity_log`、`b2b_order_admin_remark`、`b2b_special_fjx_log`、`b2b_ship_order_log`、`b2b_ku_stock_operate_log`、`b2b_work_order_*`。这些数据可以审计，但不能直接作为统一绩效引擎。管理者想看“今天每人每类 VAS 完成件数、耗时、良率、成本”时，需要人工导出、Excel 汇总或额外写临时报表。

## 4. 定制化改善方案（Improvement Plan）

## 4.1 现场作业极简 SOP 与交互设计

### 4.1.1 推荐标准 SOP：到货扫码到完工记账

```text
到货区
  1. 扫描包裹码 / 采购单 / 商品码
  2. 系统读取订单明细、检品项、普通附加项、设计附加项、自定义附加项
  3. 自动生成 VAS 工单和任务
  4. 自动打印 QC/VAS 工票
  5. 周转箱按工票上的工位标识分流

QC / VAS 工位
  6. 员工扫描工票二维码领取任务
  7. 大屏只显示当前任务：商品图、SKU、数量、必须动作、注意事项
  8. 按任务类型执行：检品 / 剪标 / 换标 / 贴纸 / 吊牌 / 洗标 / FBA / 换包装 / 拍照 / 商品报告
  9. 需要防错时执行双扫码：旧商品码 + 新标签码
  10. 需要证据时自动打开拍照/上传，按固定角度提交
  11. 脚踏 / Enter / 扫完成码 完成当前件或当前批
  12. 系统写入完工事件、绩效日志、耗材日志

入库 / 打包 / 出库
  13. 每个关键节点调用 VAS Guard
  14. 若存在未完成任务，直接拦截并提示工票号、工位、剩余动作
  15. 全部任务完成后允许入库、打包、清算、发货
```

### 4.1.2 工票内容设计

建议新增一张 **QC/VAS 工票**，尺寸可按 80mm 热敏/标签纸设计。

工票必须包含：

- 大二维码：`vas_work_order_no` 或 `vas_task_no`。
- 商品图缩略图 + SKU / MySKU / 颜色 / 尺码。
- 订单号、订单明细号、用户主账号。
- 数量：应做数量、已做数量、剩余数量。
- 服务图标：QC、剪标、换标、换包装、拍照、贴纸、吊牌、洗标、FBA。
- 工位流向：如 `QC -> 换标 -> 拍照 -> 入库`。
- 强制要求：是否需要拍照、是否需要新旧条码比对、是否需要主管复核。
- 异常码：可扫码进入异常上报。
- 重打标识：第几次打印、打印人、打印时间。

### 4.1.3 PDA / 工位端 UI 简化建议

现场 UI 应从“管理表单”改为“生产工位屏”。

```text

│ 扫码输入区：等待扫描工票 / 商品码 │
├──────────────────────────────┤
│ 商品图  SKU / 颜色 / 尺码 / 数量 │
├──────────────────────────────┤
│ 当前动作：剪标  剩余：12 件       │

│ 防错区：旧码已扫 ✓  新码待扫       │
├──────────────────────────────┤
│ 证据区：正面 ✓ 背面 ✓ 标签特写 待拍 │
├──────────────────────────────┤
│ [异常]        [完成/下一件]       │
└──────────────────────────────┘
```

交互原则：

1. **扫码驱动**：默认焦点永远在扫码输入，不要求员工点输入框。
2. **单任务大屏**：一次只展示一个 SKU/一类动作，不让现场人员在复杂列表中找信息。
3. **高对比提示**：绿色允许、红色禁止、黄色待复核。
4. **语音反馈**：`领取成功`、`条码不匹配`、`还需拍标签图`、`已完成 1 件`。
5. **脚踏兼容**：脚踏开关映射 Enter，触发“完成当前件/拍照确认/下一件”。
6. **快捷键**：Enter 完成，Esc 异常，F2 重打工票，F3 切换数量模式。
7. **离线/重试友好**：每个完工事件带 `idempotency_key`，网络抖动不重复计件。
8. **无需二次选择员工**：优先取登录人；多人共用账号时保留现有 `offline_admin_id` 思路，但在领取任务时绑定真实员工工号。

```php
function arrivalScan(string $scanCode, int $adminId): array
{
    $orderDetail = OrderDetailResolver::resolveByScanCode($scanCode);
    if (!$orderDetail) {
        return adminErrorMsg('未找到订单明细');
    }

    $snapshot = OrderCheckFjx::findDataJson([
        'order_detail_id' => $orderDetail['id'],
    ]);

    $taskDrafts = VasTaskFactory::fromOrderAddonSnapshot($orderDetail, $snapshot);
    if (empty($taskDrafts)) {
        return adminSuccessMsg(['work_order_no' => null, 'task_list' => []]);
    }

    Db::beginTransaction();
    try {
        $workOrder = VasWorkOrderService::firstOrCreateForOrderDetail($orderDetail, $adminId);
        VasWorkOrderService::syncTasks($workOrder, $taskDrafts, $adminId);
        VasWorkOrderService::markTicketPrinted($workOrder, $adminId);

        OperatorPerformanceLogService::record([
            'source_type' => 'vas_work_order',
            'source_id' => $workOrder['id'],
            'operator_admin_id' => $adminId,
            'action_code' => 'ticket_printed',
            'quantity' => 1,
            'idempotency_key' => 'ticket:' . $workOrder['work_order_no'],
        ]);

        Db::commit();
    } catch (Throwable $e) {
        Db::rollBack();
        throw $e;
    }

    return adminSuccessMsg([
        'work_order_no' => $workOrder['work_order_no'],
        'task_list' => VasWorkOrderService::formatTasks($workOrder['id']),
        'print_payload' => VasTicketPrinter::buildPayload($workOrder['id']),
    ]);
}
```

#### B. 换标/贴标双扫码校验

```php
function verifyBarcode(string $taskNo, string $oldBarcode, string $newBarcode, int $adminId): array
{
    $task = VasTask::findByTaskNo($taskNo);
    if (!$task || $task['status'] >= 300) {
        return adminErrorMsg('任务不存在或已结束');
    }

    if ((int)$task['barcode_check_required'] !== 1) {
        return adminErrorMsg('当前任务不需要条码比对');
    }

    $oldMatched = BarcodeCompareService::match($oldBarcode, $task['expected_old_barcode']);
    $newMatched = BarcodeCompareService::match($newBarcode, $task['expected_new_barcode']);

    VasTaskProof::insertData([
        'task_id' => $task['id'],
        'order_detail_id' => $task['order_detail_id'],
        'proof_type' => 'barcode',
        'scanned_old_barcode' => $oldBarcode,
        'scanned_new_barcode' => $newBarcode,
        'compare_result' => ($oldMatched && $newMatched) ? 'match' : 'mismatch',
        'admin_id' => $adminId,
    ]);

    if (!$oldMatched || !$newMatched) {
        OperatorPerformanceLogService::recordMismatch($task, $adminId, $oldBarcode, $newBarcode);
        return adminErrorMsg('条码不匹配，请停止操作并交主管复核');
    }

    OperatorPerformanceLogService::record([
        'source_type' => 'vas_task',
        'source_id' => $task['id'],
        'task_id' => $task['id'],
        'order_detail_id' => $task['order_detail_id'],
        'operator_admin_id' => $adminId,
        'action_code' => 'retag_barcode_verified',
        'service_type' => $task['service_type'],
        'quantity' => 0,
        'idempotency_key' => 'barcode:' . $taskNo . ':' . md5($oldBarcode . '|' . $newBarcode),
    ]);

    return adminSuccessMsg(['match' => true]);
}
```

```php
    Db::beginTransaction();
    try {
        $task = VasTask::lockByTaskNo($taskNo);
        if (!$task) {
            return adminErrorMsg('任务不存在');
        }

        VasTaskPolicy::assertCanComplete($task, $adminId);
        VasTaskPolicy::assertQuantityWithinRemaining($task, $quantity);
        VasTaskPolicy::assertProofReady($task);
        VasTaskPolicy::assertBarcodeVerified($task);

        $nextDoneQty = bcadd($task['quantity_done'], $quantity, 3);
        $finished = bccomp($nextDoneQty, $task['quantity_required'], 3) >= 0;

        VasTask::updateData(['id' => $task['id']], [
            'quantity_done' => $nextDoneQty,
            'status' => $finished ? 300 : 200,
            'finished_at' => $finished ? date('Y-m-d H:i:s') : null,
        ]);

        $rate = VasRateService::resolveRate($task);
        $cost = VasCostService::calculate($task, $quantity, $rate, $payload['material_list'] ?? []);

        OperatorPerformanceLogService::record([
            'source_type' => 'vas_task',
            'source_id' => $task['id'],
            'task_id' => $task['id'],
            'order_detail_id' => $task['order_detail_id'],
            'operator_admin_id' => $adminId,
            'offline_admin_id' => $payload['offline_admin_id'] ?? 0,
            'station_code' => $payload['station_code'] ?? '',
            'action_code' => 'vas_task_completed',
            'service_type' => $task['service_type'],
            'quantity' => $quantity,
            'duration_seconds' => VasTaskService::calcDurationSeconds($task),
            'unit_piece_rate' => $rate['piece_rate'],
            'labor_cost' => $cost['labor_cost'],
            'material_cost' => $cost['material_cost'],
            'billable_amount' => $cost['billable_amount'],
            'idempotency_key' => $payload['idempotency_key'],
        ]);

        VasMaterialService::recordConsumption($task, $payload['material_list'] ?? [], $adminId);
        VasWorkOrderService::refreshWorkOrderStatus($task['work_order_id']);

        Db::commit();
    } catch (Throwable $e) {
        Db::rollBack();
        throw $e;
    }

    return adminSuccessMsg([
        'remaining_qty' => VasTaskService::remainingQty($task['id']),
        'next_task' => VasTaskService::findNextTask($task['work_order_id']),
    ]);
}
```

```php
function checkBeforeStage(array $orderDetailIds, string $stage): array
{
    $unfinishedTasks = VasTask::query()
        ->whereIn('order_detail_id', $orderDetailIds)
        ->whereIn('status', [100, 150, 200, 400])
        ->whereIn('required_before_stage', VasStage::stagesBeforeOrEqual($stage))
        ->get()
        ->toArray();

    }

    return [
        'allow' => false,
        'message' => VasGuardMessageService::format($unfinishedTasks),
        'unfinished_task_list' => $unfinishedTasks,
    ];
}
```

## 5. 实施优先级 Roadmap

### P0：核心拦截与打票闭环

目标：先把“漏做”和“错标”挡住。

1. 新增 `b2b_vas_work_order`、`b2b_vas_work_order_task`、`b2b_vas_task_proof`、`b2b_operator_performance_log` 基础表。
2. 将 `b2b_order_check_fjx` 中已选检品/附加项解析成可执行任务。
3. 到货扫码后自动生成并打印 QC/VAS 工票。
4. 在入库、箱入库、打包完成、发货确认前接入统一 `VasGuardService`。
5. 对换标/贴标类任务启用新旧条码双扫码校验。
6. 先实现最小工位接口：扫码领单、完成任务、异常上报、重打工票。
7. 现有设计类 `design_status` / `print_status` 拦截保留，并映射成 VAS 任务前置条件，避免一次性切换风险。

验收标准：

- 有 VAS 的商品未完成任务时，不能入库/打包/发货。
- 到货扫码能打印工票。
- 换标任务扫错新标签会被系统阻止。
- 每次完工都有 `operator_performance_log`。

### P1：现场极简交互与拍照闭环

目标：让现场人员不再找页面、找订单、看复杂表格。

1. WMS 新增 `VAS 工位模式` 页面。
2. 支持大字体、高对比、语音提示、扫码自动跳转、Enter/脚踏完成。
3. 支持按服务类型分工位：QC、剪标、换标、拍照、包装、设计打印。
4. 拍照服务改成任务驱动：必须拍哪些角度、是否合格、是否补拍。
5. 工票支持重打、作废、异常复核。
6. 管理端新增现场 WIP 看板：待处理、处理中、异常、超时、各工位负载。

验收标准：

- 员工扫描工票后只需按系统提示操作。
- 拍照凭证自动绑定订单明细、任务、员工。
- 主管能实时看到哪个工位积压。

### P2：自动绩效、耗材与成本结算

目标：把生产数据转成管理数据和财务数据。

1. 新增 `b2b_vas_service_rate_config`，维护计件单价、标准工时、耗材规则。
2. 新增 `b2b_vas_material_consumption_log`，任务完成时自动记录贴纸、吊牌、OPP、气泡膜等耗材。
3. 建立员工产出日报、班组产能、服务类型产能、良率/返工率报表。
4. 将实际人工/耗材成本回写订单成本分析。
5. 与客户结算联动：客户收费按选择/合同，内部成本按实际完工事件归集，形成毛利差异。
6. 加入 SLA：超时任务、返工次数、错标率、异常原因趋势。

验收标准：

- 能自动输出“张三今日剪标 150 件、换标 80 件、拍照 200 张、返工 3 件”。
- 能看到每个订单的 VAS 人工成本、耗材成本、客户收费、毛利。
- 能按服务类型分析瓶颈和质量问题。

## 6. 风险与落地注意事项

1. **先兼容旧快照，不要直接替换。** 现有 `b2b_order_check_fjx` 是计费与展示核心，新增 VAS 工单应先从快照派生，不能一开始反向改造所有附加项逻辑。
2. **商品问题工单不要复用为生产工单。** 现有 `b2b_work_order` 已服务客户确认/内部问题流转，建议新增 VAS 工单，避免把生产计件和售后问题混在一张表。
3. **强拦截要分阶段灰度。** P0 可先对高风险服务启用：吊牌/贴纸/FBA/洗标/剪标/换标/拍照。低风险包装附加项可先提示后拦截。
4. **绩效事件必须幂等。** PDA 网络抖动、重复扫码、重复点击很常见，所有完工/打印/拍照事件必须有 `idempotency_key`。
5. **条码比对规则要可配置。** 不同客户可能用 MySKU、SKU、FNSKU、JAN、EAN 或自定义码，不能硬编码单一字段。
6. **脚踏开关本质是键盘输入。** 前端可先支持 Enter/Space 快捷键，再适配 USB 脚踏，无需复杂硬件接口。
7. **报表口径要冻结。** 绩效金额应来自完工当时快照，不要随配置价格变化影响历史工资。
8. **隐私与客诉证据分层。** 员工绩效照片、客户可见照片、内部缺陷照片需要不同权限和展示范围。
