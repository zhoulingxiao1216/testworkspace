## 1. 业务背景

当前业务是跨境代购/代采履约场景。客户在前台下单后，系统生成代购订单及订单明细商品 ID，例如 `D000010471`。国内商家发货后，仓库先按国内快递单号完成包裹签收，再由质控小组完成初检、质检、附加项处理、尾检，最后进入仓库入库。

当前现场已形成比较明确的岗位分工：

1. 到货中台电脑负责快递签收登记，记录快递签收表。
2. 签收后的快递被分散给各个质控小组，小组包含初检、质检、尾检人员。
3. 初检人员拆包，扫描快递单号跳转到关联代购订单详情页，填写到货数量。
4. 初检发现颜色、尺码、规格不符时，创建工单并提交采购或业务判断；异常商品数量进入待定区域。
5. 商品随商品流转单进入质检工作台。
6. 质检人员根据客户选择的检品方式执行检品，发现问题时反馈给初检人员，由初检创建工单。
7. 质检通过物理方式区分正品和不良品，例如红色捆绳表示不良。
8. 质检会撕下商品流转单后半部分，后半部分包含商品 ID、不良数和商品 ID 二维码。
9. 贴纸、吊牌、剪标、换包装等附加项当前可能由质检人员处理，但主要依赖纸质流转单手写勾选和填写工号。
10. 尾检人员根据流转单选择对应质检人员工号并登记不良数，登记不良后同步更新正品数。
11. 如包含贴纸、吊牌，尾检人员打开商品对应打印按钮，人工检查贴纸、吊牌与商品包装信息是否一致。
12. 尾检完成后交由仓库入库，入库操作流程后续再补充。

这个流程的问题不是岗位分工完全缺失，而是很多关键事实仍停留在纸面、手写、口头流转和尾检二次录入中，导致现场效率、准确性、责任追踪和绩效统计受到限制。

## 2. 产品定位

本 PRD 建议建设一套轻量的“商品 ID 二维码报工与 QC/VAS 数字化”能力。

产品定位：

> 以订单明细商品 ID 为核心识别码，以商品流转单二维码为现场入口，把初检、质检、附加项、尾检中的关键数量和责任人记录数字化，减少手写和二次录入，实现正品/不良/待定/附加项完成情况的实时追踪。

本系统不是第一版就替代现有完整工单系统，也不是取消初检、质检、尾检分工，而是在现有流程上做“扫码入口 + 报工记录 + 数量校验 + 尾检复核 + 绩效统计”。

## 3. 产品目标

### 3.1 业务目标

1. 降低现场人员查单、找商品、手写工号、手写勾选的操作成本。
2. 明确每个商品、每个附加项、每次质检动作由谁完成、完成多少、何时完成。
3. 将不良、待定、规格不符等异常从纸面记录变成系统事件。
4. 让尾检从“代替前序岗位录入数据”转为“复核、纠偏、放行”。
5. 为员工绩效统计、附加项成本核算、订单履约追溯提供基础数据。

### 3.2 体验目标

1. 现场人员优先扫码操作，尽量少切换页面、少手动搜索、少输入文字。
2. PDA 或工位端页面大字体、高对比度、强提示，只展示当前岗位最需要的信息。
3. 常用动作一键完成，例如“确认正品”“登记不良”“完成贴纸”“尾检通过”。
4. 异常场景有明确提示和下一步流转，不让异常商品混入正品流。

### 3.3 管理目标

1. 管理人员可以实时看到每个质控小组和员工的产出。
2. 财务或运营可以按日期、人员、附加项、商品、订单统计数量。
3. 商品从签收、初检、质检、附加项、尾检到入库的关键节点可追溯。

## 4. 范围说明

### 4.1 本期包含

1. 商品流转单增加商品 ID 二维码。
2. 扫商品 ID 进入质检/附加项报工页。
3. 初检到货数量、待定数量的结构化记录。
4. 质检人员扫码记录检品数量、正品数量、不良数量。
5. 贴纸、吊牌、剪标、换包装、拍照等附加项扫码报工。
6. 尾检扫码复核初检、质检、附加项完成情况。
7. 不良、待定、规格不符等异常的基础处理逻辑。
8. 员工产出和商品附加项完成情况的基础看板。

### 4.2 本期不包含

1. 不重做完整采购/业务/客户沟通工单流程。
2. 不做复杂自动派工和排班优化。
3. 不做完整计件工资结算规则。
4. 不做完整耗材库存扣减和财务成本分摊。
5. 不把国内快递签收直接等同于商品到货确认。
6. 不强制取消纸质商品流转单，第一版允许纸质单和系统记录并行。
7. 仓库入库详细流程待后续反馈后再补充。

## 5. 角色与职责

| 角色 | 当前职责 | 系统增强方向 |
|---|---|---|
| 到货签收人员 | 扫快递单号，登记包裹签收 | 只确认包裹到仓，不直接确认商品到货 |
| 初检人员 | 拆包、核对商品、填写到货数量、创建异常工单 | 扫快递单号/商品 ID，记录到货数、待定数、异常原因 |
| 质检人员 | 按客户检品方式质检，区分正品和不良 | 扫商品 ID 报工，记录检品数量、不良数量、问题事件 |
| 附加项处理人 | 贴纸、吊牌、剪标、换包装、拍照等 | 扫商品 ID 报工，记录实际完成项和数量 |
| 尾检人员 | 登记质检工号、不良数，复核贴纸/吊牌 | 扫商品 ID 复核系统记录，确认一致后放行 |
| 采购/业务 | 处理规格不符、待定、不良等工单 | 接收异常工单并给出处置结论 |
| 仓库入库人员 | 商品入库 | 只接收尾检通过且数量状态正常的商品 |
| 管理/财务 | 统计员工产出和服务成本 | 查看自动统计报表和异常追溯 |

## 6. 核心概念

| 概念 | 说明 |
|---|---|
| 商品 ID | 订单明细级商品识别码，例如 `D000010471`，用于定位一张代购订单中的某一款商品 |
| 国内快递单号 | 国内包裹运输单号，用于包裹签收和匹配代购订单，不直接代表商品明细已到货 |
| 商品流转单 | 跟随实物在初检、质检、附加项、尾检之间流转的纸质或电子凭证 |
| 商品 ID 二维码 | 印在商品流转单上，扫码后进入该商品的作业页面 |
| 初检待定数量 | 初检发现规格不符、颜色尺码不符、需要业务/采购判断的数量 |
| 不良数量 | 检品发现质量问题，不能直接作为正品流转的数量 |
| 正品数量 | 可以继续进行附加项、尾检和入库的商品数量 |
| 报工 | 工作人员完成某项作业后记录员工、数量、时间、结果的动作 |
| 尾检复核 | 入库前最后一道检查，确认实物、流转单、系统记录一致 |

## 7. 当前痛点

### 7.1 数据采集滞后

质检人员实际完成检品后，工号和不良数可能仍由尾检根据纸质单二次录入。系统无法实时知道质检人员当前完成了多少件，也无法实时发现漏检、错填或未报工。

### 7.2 附加项责任不清

贴纸、吊牌、剪标、换包装、拍照等附加项当前可能由质检人员在流转单上用笔勾选并填写工号。系统难以统计实际处理人，也难以判断某个附加项是否已经完成。

### 7.3 纸质流转单承担过多系统事实

商品 ID、不良数、附加项勾选、员工工号等关键事实依赖纸面传递。纸面污损、漏填、错填、后半部分撕下丢失，都会造成后续统计和追溯困难。

### 7.4 尾检负担偏重

尾检不仅要做最终复核，还承担前序岗位数据录入职责。尾检一旦积压，会影响入库效率；尾检录入错误也会污染前序员工绩效。

### 7.5 包裹签收和商品到货容易混淆

国内快递签收只说明包裹到仓，并不能证明包裹里某个订单明细商品已经正确、足量到货。若系统直接按快递签收自动到货，会存在少发、错发、混包、规格不符等风险。

## 8. 目标流程总览

### 8.1 总流程图

```text
国内包裹到仓
  -> 到货中台扫码签收快递单号
  -> 系统记录包裹签收，并匹配代购订单
  -> 快递分配给质控小组
  -> 初检拆包并扫描快递单号
  -> 初检核对实物与订单商品信息
  -> 初检填写到货数量、待定数量
  -> 系统生成/打印商品流转单与商品 ID 二维码
  -> 商品进入质检工作台
  -> 质检扫描商品 ID 二维码
  -> 系统展示客户选择的检品方式和待处理附加项
  -> 质检提交检品结果，记录正品、不良、问题事件
  -> 附加项处理人扫码报工，记录贴纸/吊牌/剪标/换包装/拍照完成数量
  -> 商品流转到尾检工作台
  -> 尾检扫描商品 ID 二维码，复核系统记录、纸面信息与实物
  -> 尾检通过后释放给仓库入库
```

### 8.2 包裹签收与商品到货边界

```text
快递签收 = 包裹到仓事实
商品到货 = 初检拆包后确认某个商品 ID 的到货数量
```

产品规则：

1. 快递签收成功后，不自动更新商品到货数量。
2. 初检拆包并核对实物后，才允许确认商品到货数量。
3. 商品 ID 二维码在商品到货确认后生成或生效。
4. 如果一个快递包裹关联多个订单或多个商品，必须由初检人工确认对应商品和数量。

## 10. 关键业务规则

### 10.1 商品 ID 二维码规则

1. 商品 ID 来源于代购订单明细，例如 `D000010471`。
2. 二维码应明确表达用途，推荐在现场使用商品流转单二维码。
3. 第一版二维码至少支持进入商品作业页，展示商品、订单、规格、数量、检品方式、附加项。
4. 商品 ID 二维码不能替代国内快递单号签收码。
5. 商品 ID 二维码应跟随商品或周转箱流转，尾检前不得丢失。

### 10.2 到货数量规则

1. 国内快递签收后，只形成包裹到仓记录。
2. 初检拆包后，才确认订单明细商品的到货数量。
3. 到货数量不得超过合理可到货数量；如超过，必须提示并要求说明。
4. 待定数量从可流转数量中隔离，直到工单给出处置结论。
5. 初检完成后，可进入质检的数量应为到货数量扣除待定数量后的数量。

### 10.3 初检异常规则

1. 颜色、尺码、规格、款式与代购订单不符时，初检必须填写待定数量。
2. 待定数量必须有异常原因，必要时上传照片。
3. 待定商品不得继续进入正常质检、附加项和入库流程。
4. 待定商品由现有工单流程交给采购或业务处理。
5. 工单结果可以是作正品入库、作不良退换货、客户确认接受、补发或其它处置。

### 10.4 质检规则

1. 质检人员扫码商品 ID 后，只展示该商品对应的检品方式和必要信息。
2. 质检提交时必须记录质检人员、检品数量、正品数量、不良数量。
3. 正品数量与不良数量应与本次检品数量匹配。
4. 发现不良时，系统应记录发现人、时间、数量、问题类型。
5. 现场仍可保留红色捆绳区分不良品，作为物理防错手段。
6. 质检发现的问题仍可按现有规则交由初检人员创建工单，但系统必须保留质检发现事件。

### 10.5 附加项规则

1. 贴纸、吊牌、剪标、换包装、拍照等附加项必须在系统中报工。
2. 附加项报工数量不得超过当前可处理正品数量。
3. 未在订单中配置或客户未选择的附加项，不允许随意报工。
4. 同一商品同一附加项可以多次报工，但累计数量不得超过允许数量。
5. 附加项处理人可以是质检人员，也可以是独立岗位人员，但必须记录实际处理人。
6. 贴纸、吊牌等容易出错的项目，尾检必须复核一致性。

### 10.6 尾检规则

1. 尾检人员扫码商品 ID 后，系统展示初检、质检、附加项完成情况。
2. 尾检只复核前序数据，不应默认替前序岗位补录所有数据。
3. 系统记录不完整时，尾检可以退回对应岗位补录或处理。
4. 正品、不良、待定、附加项数量不一致时，不允许直接通过。
5. 尾检通过后，商品才释放给仓库入库。
6. 贴纸、吊牌信息不一致时，尾检必须拦截并记录异常。

## 11. 页面与交互需求

### 11.1 初检工作台

目标：帮助初检人员快速确认到货数量和待定数量。

核心能力：

1. 扫快递单号进入关联订单。
2. 展示订单商品图片、规格、颜色、尺码、SKU、应采购数量、已到货数量。
3. 支持选择商品并填写本次到货数量。
4. 支持填写待定数量和异常原因。
5. 支持生成商品流转单和商品 ID 二维码。
6. 支持将待定商品发起或关联工单。

交互要求：

1. 扫码后优先展示候选商品，不要求人工反复搜索。
2. 数量输入控件要大、清晰，支持加减或数字键盘。
3. 异常原因使用快捷选项，减少手打文字。
4. 提交后明确提示“已生成流转单”“待定数量已隔离”。

### 11.2 质检工作台

目标：让质检人员直接记录自己的检品产出。

核心能力：

1. 扫商品 ID 二维码进入当前商品质检页。
2. 展示客户选择的检品方式。
3. 展示本次可质检数量、已质检数量、剩余数量。
4. 支持提交正品数量、不良数量、问题说明。
5. 支持记录问题照片或异常说明。
6. 支持把异常事件推送给初检处理。

交互要求：

1. 页面只显示当前商品和当前岗位要做的内容。
2. 常用操作按钮固定，例如“全部正品”“有不良”“提交并下一件”。
3. 不良原因使用快捷标签。
4. 扫码成功、提交成功、数量异常要有明显提示。

### 11.3 附加项报工工作台

目标：把手写勾选和手写工号改成系统报工。

核心能力：

1. 扫商品 ID 二维码进入附加项列表。
2. 只展示该商品需要处理的附加项。
3. 支持选择附加项并填写完成数量。
4. 支持贴纸、吊牌、剪标、换包装、拍照等项目。
5. 支持记录实际处理人员。
6. 支持查看每个附加项应做、已做、剩余数量。

交互要求：

1. 默认显示待完成项目，已完成项目折叠或置灰。
2. 支持一键完成当前剩余数量。
3. 数量超限时必须强提示并阻止提交。
4. 贴纸/吊牌类项目应提示后续尾检复核。

### 11.4 尾检工作台

目标：尾检从二次录入转为复核和放行。

核心能力：

1. 扫商品 ID 二维码进入尾检复核页。
2. 展示初检到货数、待定数、质检人员、质检结果、附加项完成情况。
3. 支持确认尾检通过。
4. 支持发现差异后退回初检、质检或附加项岗位。
5. 支持贴纸/吊牌一致性复核。
6. 支持尾检完成后释放入库。

交互要求：

1. 页面用红、黄、绿明显区分异常、待处理、已通过。
2. 尾检只需核对和确认，不应重复填写大量前序信息。
3. 未完成附加项、不良数量未确认、待定未处理时，按钮不可通过。

## 12. 异常处理逻辑

| 异常场景 | 触发时机 | 系统处理 | 责任岗位 |
|---|---|---|---|
| 快递单号无法匹配订单 | 到货签收或初检扫码 | 标记为未匹配包裹，进入人工认领或私人物品处理 | 到货签收/初检 |
| 快递单号匹配多个订单 | 初检扫码 | 展示候选订单，不自动确认商品到货 | 初检 |
| 包裹内多款商品 | 初检拆包 | 按商品逐一确认到货数量并生成对应商品流转单 | 初检 |
| 实物颜色尺码不符 | 初检核对 | 填写待定数量，创建或关联工单，禁止进入正常流转 | 初检/采购/业务 |
| 到货数量少于采购数量 | 初检确认 | 记录部分到货，剩余数量继续等待或走采购处理 | 初检/采购 |
| 到货数量多于采购数量 | 初检确认 | 要求填写说明，进入异常待确认 | 初检/业务 |
| 商品 ID 二维码无法识别 | 质检/附加项/尾检扫码 | 提示重新扫码或手动输入商品 ID，记录异常扫码事件 | 当前岗位 |
| 质检发现不良 | 质检处理 | 记录不良数量、问题类型、发现人，通知初检建工单 | 质检/初检 |
| 质检未报工但流转到尾检 | 尾检复核 | 尾检不可通过，退回质检补报工 | 尾检/质检 |
| 附加项未完成 | 尾检复核 | 尾检不可通过，退回附加项处理 | 尾检/附加项处理人 |
| 附加项报工数量超限 | 附加项提交 | 阻止提交并提示剩余可报数量 | 附加项处理人 |
| 贴纸/吊牌信息不一致 | 尾检复核 | 标记异常，退回重新打印或重新处理 | 尾检/附加项处理人 |
| 纸质流转单丢失或污损 | 任意环节 | 通过商品 ID、快递单号或订单号补打流转单，记录补打原因 | 当前岗位/组长 |
| 员工工号填写或选择错误 | 报工/尾检 | 支持有权限人员更正，并保留更正记录 | 组长/管理员 |
| 网络或扫码设备异常 | 任意扫码环节 | 支持短时间手动输入商品 ID 或离线记录，恢复后补同步 | 当前岗位/组长 |

## 13. 数量流转规则

### 13.1 核心数量关系

```text
包裹签收数量不等于商品到货数量。
商品到货数量由初检拆包后确认。
待定数量从正常流转数量中隔离。
质检不良数量从正品数量中扣除。
附加项只能对当前可处理正品数量报工。
尾检通过数量才允许释放给仓库入库。
```

### 13.2 示例

场景一：初检发现规格不符。

```text
商品 ID：D000010471
拆包到货：10 件
初检待定：2 件，原因是颜色/尺码不符
进入正常质检数量：8 件
后续贴纸、吊牌、剪标、换包装最多只能对 8 件报工
待定 2 件等待工单结论，不进入正常入库
```

场景二：质检发现不良。

```text
进入质检：8 件
质检正品：7 件
质检不良：1 件
质检人员记录不良事件
不良品用红色捆绳区分
尾检复核后，正品 7 件可继续入库，不良 1 件进入异常处理
```

场景三：附加项未完成。

```text
当前可处理正品：7 件
客户要求贴纸：7 件
系统已记录贴纸完成：5 件
尾检扫码发现贴纸剩余 2 件未完成
尾检不可通过，退回贴纸处理
```

## 15. 验收标准

### 15.1 基础流程验收

1. 快递签收后，系统只记录包裹签收，不自动确认商品到货。
2. 初检扫描快递单号后，可以进入关联订单并确认商品到货数量。
3. 初检确认商品到货后，可以生成包含商品 ID 二维码的商品流转单。
4. 质检扫描商品 ID 二维码后，可以进入该商品质检页。
5. 附加项处理人扫描商品 ID 后，可以看到待完成附加项并报工。
6. 尾检扫描商品 ID 后，可以看到前序记录并完成复核。

### 15.2 数量规则验收

1. 待定数量不能进入正常质检和入库流程。
2. 质检不良数量会从可入库正品数量中扣除。
3. 附加项累计报工数量不能超过当前可处理正品数量。
4. 尾检发现数量不一致时，不允许直接通过。
5. 未完成必做附加项时，不允许尾检放行。

### 15.3 绩效统计验收

1. 系统可以统计某员工某天完成了多少件初检。
2. 系统可以统计某员工某天完成了多少件质检。
3. 系统可以统计某员工某天完成了多少件贴纸、吊牌、剪标、换包装、拍照等附加项。
4. 系统可以按商品 ID 查看每项作业的应做、已做、剩余。
5. 尾检代录前序人员工号的比例应明显下降。

目标：先把商品 ID 二维码作为现场主入口跑通，解决手写和二次录入问题。

## 17. 风险与约束

| 风险 | 说明 | 应对策略 |
|---|---|---|
| 现场抵触新增扫码动作 | 一线人员担心增加操作步骤 | 把扫码设计成进入页面和自动带数据，不做额外负担 |
| 纸质单短期无法取消 | 现场仍依赖纸质流转单分拣和交接 | 第一版保留纸质单，只减少手写事实 |
| 质检人员未及时报工 | 仍可能出现先做事后补录 | 尾检未看到系统记录时不可通过 |
| 异常商品责任不清 | 质检发现、初检建工单之间存在责任断点 | 系统记录发现事件，再由初检确认工单 |
| 附加项处理人混岗 | 质检人员可能同时处理贴纸、吊牌 | 允许混岗，但每个附加项必须单独报工 |
| 商品 ID 码丢失 | 流转单撕下或污损 | 支持按订单/快递单补打并记录补打原因 |
| 自动到货误判 | 快递签收不能代表商品正确到货 | 第一版不做自动到货，只做候选展示和人工确认 |

## 18. 待确认问题

1. 商品流转单是在初检确认到货后立即打印，还是在到货中台签收后预打印，再由初检修正数量？
2. 质检人员是否允许直接提交异常事件，还是必须只通知初检，由初检录入？建议至少允许质检记录发现事件。
3. 贴纸、吊牌、剪标、换包装、拍照这些附加项是否都有明确计件口径？例如按件、按 SKU、按套、按张。
4. 实际员工身份以登录账号为准，还是支持扫描员工工牌切换实际处理人？
5. 尾检是否有权限更正前序数量，还是只能退回前序岗位更正？建议第一版默认退回，管理人员可更正。
6. 待定商品经工单判定为“作正品入库”后，是否需要重新走质检和尾检？建议必须至少走尾检复核。
7. 入库环节是否需要强制校验尾检通过、附加项完成、不良/待定已隔离？建议作为入库流程补充时的核心规则。

## 19. 初版结论

建议 A 适合作为第一版落地方案，但产品定位应从“扫码报工工具”升级为“商品 ID 驱动的 QC/VAS 现场数字化入口”。

第一版最重要的原则是：

```text
快递签收不等于商品到货确认；
商品 ID 二维码不替代快递单号，而是承接初检后的商品级流转；
初检负责到货和待定，质检负责检品和不良发现，附加项处理人负责实际完成记录，尾检负责复核与放行；
纸质流转单可以保留，但手写工号、手写勾选、不良数二次代录要逐步被扫码报工替代。
```

当第一版完成后，系统应至少能回答四个问题：

1. `D000010471` 当前到了多少件、待定多少件、正品多少件、不良多少件？
2. `D000010471` 需要哪些检品和附加项，哪些已完成，哪些未完成？
3. 每项作业分别是谁在什么时候完成的，完成了多少？
4. 商品现在能不能尾检通过并入库，如果不能，卡在哪个异常或未完成项目？
