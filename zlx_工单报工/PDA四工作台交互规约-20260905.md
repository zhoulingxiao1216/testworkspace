# PDA 四工作台交互规约

版本：v0.1 初版  
日期：2026-09-05  
关联文档：`商品ID二维码报工与QCVAS数字化初版PRD-20260905.md`  
适用范围：初检工作台、质检工作台、附加项报工工作台、尾检工作台。  
设计目标：极简、高对比度、扫码优先、防错优先、适合仓库现场连续作业。

---

## 1. 总体交互原则

1. 扫码优先：所有工作台默认等待扫码，不要求现场人员先搜索订单。
2. 一屏一任务：一个页面只完成当前岗位最核心动作，不展示无关字段。
3. 大字号数量：数量、状态、商品 ID、异常提示必须大字号展示。
4. 强状态提示：可操作、已完成、待定、不良、需退回、可入库必须用颜色和短语明确表达。
5. 少输入：异常原因使用快捷标签，数量支持快捷加减和“一键剩余数量”。
6. 强拦截：数量超限、未报工、附加项未完成、待定未处理、贴纸吊牌不一致时不能通过。
7. 即时反馈：扫码、提交、拦截、退回、放行都必须有声音或震动反馈。

---

## 2. 通用页面框架

所有 PDA 工作台采用统一三段式布局：

```text
顶部固定区：工位名称 + 扫描框 + 当前状态
中部内容区：商品/订单关键信息 + 大字号数量区
底部操作区：主操作按钮 + 异常/退回按钮
```

### 2.1 通用视觉状态

| 状态 | 颜色 | 用途 |
|---|---|---|
| 可操作 | 绿色 | 当前商品可继续处理 |
| 当前处理 | 蓝色 | 当前岗位正在处理 |
| 待确认 | 黄色 | 待定、部分完成、需要确认 |
| 异常/禁止 | 红色 | 不良、数量错误、禁止通过 |
| 不可操作 | 灰色 | 已完成、无权限、不可重复提交 |

### 2.2 通用声音/震动反馈

| 场景 | 反馈 |
|---|---|
| 扫码成功 | 短促成功音 + 绿色闪屏 |
| 提交成功 | 成功音 + 状态更新提示 |
| 重复扫码 | 黄色提示音 + 提示当前状态 |
| 数量超限 | 红色弹窗 + 长音 + 震动 |
| 禁止通过 | 红色全屏提示 + 长音 |
| 可入库放行 | 成功音 + 语音“尾检通过，放行入库” |

## 3. 初检工作台

### 3.1 页面布局描述

```text
[顶部固定区]
初检工作台
扫描快递单号 / 商品ID
当前状态：待拆包 / 已匹配 / 异常待定

[包裹信息区]
快递单号
匹配订单数
订单号 / 店铺
质控小组

[商品核对区]
商品图片
商品ID
颜色 / 尺码 / 规格
应到数量 / 已到数量 / 剩余应到

[数量操作区]
本次到货数量
待定数量
异常原因快捷标签
拍照入口

[底部固定操作区]
确认到货并打印流转单
创建/关联工单
补打流转单
下一包裹
```

### 3.2 核心输入/输出字段

| 类型 | 字段 |
|---|---|
| 输入 | 快递单号、商品 ID、本次到货数量、待定数量、异常原因、照片 |
| 输出 | 订单号、店铺、商品图片、颜色、尺码、规格、应到数量、已到数量、剩余应到数量 |
| 系统判断 | 是否匹配订单、是否多商品、是否超收、是否有待定、是否需要工单 |

### 3.3 主操作按钮与状态控制

主按钮：

```text
确认到货并打印流转单
```

快捷按钮：

```text
全部到货
部分到货
有待定
创建工单
补打流转单
下一包裹
```

强控制规则：

1. 快递单号未匹配订单时，不允许确认商品到货。
2. 一个快递单号匹配多个商品时，必须选择商品 ID 后才能填写到货数量。
3. 到货数量大于应到数量时，弹出红色强拦截提示，必须填写原因。
4. 待定数量大于 0 时，必须选择异常原因，建议要求拍照。
5. 待定数量未创建或关联工单时，不允许进入正常流转。

### 3.4 物理/声音防错机制

| 场景 | 反馈 |
|---|---|
| 扫码成功 | 短促成功音 + 绿色闪屏，“已匹配订单” |
| 未匹配快递 | 红色长音 + 语音“未匹配订单” |
| 数量超限 | 红色强弹窗 + 震动 + 语音“数量超出，请复核” |
| 待定未填原因 | 黄色提示 + 提交按钮置灰 |
| 打印成功 | 语音“流转单已打印” |

## 4. 质检工作台

### 4.1 页面布局描述

```text
[顶部固定区]
质检工作台
扫描商品ID二维码
当前状态：待质检 / 部分质检 / 已质检 / 异常

[商品识别区]
商品ID
商品图片
订单号
颜色 / 尺码 / 规格

[检品任务区]
客户选择的检品方式
可质检数量
已质检数量
剩余数量

[结果录入区]
本次检品数量
正品数量
不良数量
问题类型快捷标签
拍照入口

[底部固定操作区]
全部正品
有不良
提交并下一件
通知初检
```

### 4.2 核心输入/输出字段

| 类型 | 字段 |
|---|---|
| 输入 | 商品 ID、检品数量、正品数量、不良数量、不良原因、照片 |
| 输出 | 商品图片、商品规格、检品方式、可质检数量、已质检数量、剩余数量 |
| 系统判断 | 是否可质检、是否超数量、是否存在待定、是否需要通知初检建工单 |

### 4.3 主操作按钮与状态控制

主按钮：

```text
提交并下一件
```

高频快捷按钮：

```text
全部正品
有不良
拍照
通知初检
```

状态控制规则：

1. 商品存在待定未处理数量时，只允许处理可质检数量，不展示待定部分为可操作数量。
2. `正品数 + 不良数` 必须等于本次检品数量。
3. 本次检品数量不能超过剩余可质检数量。
4. 不良数量大于 0 时，必须选择问题类型，建议上传照片。
5. 质检异常先记录“异常发现事件”，正式工单仍由初检确认。

### 4.4 物理/声音防错机制

| 场景 | 反馈 |
|---|---|
| 扫商品 ID 成功 | 成功音 + 语音“进入质检” |
| 扫到快递单号 | 错误音 + 提示“请扫描商品 ID” |
| 全部正品提交 | 绿色闪屏 + 语音“质检完成” |
| 有不良提交 | 红色状态条 + 语音“请隔离不良品” |
| 数量不平 | 红色弹窗，“正品数加不良数不等于检品数” |
| 不良未拍照 | 黄色拦截提示 |

## 5. 附加项报工工作台

### 5.1 页面布局描述

```text
[顶部固定区]
附加项报工
扫描商品ID / VAS二维码
当前状态：待处理 / 部分完成 / 已完成 / 待尾检复核

[商品摘要区]
商品ID
商品图片
可处理正品数
当前已完成附加项数

[附加项任务列表]
贴纸：应做 / 已做 / 剩余
吊牌：应做 / 已做 / 剩余
剪标：应做 / 已做 / 剩余
换包装：应做 / 已做 / 剩余
拍照：应做 / 已做 / 剩余

[当前操作区]
选择附加项
本次完成数量
凭证/照片
处理人工号

[底部固定操作区]
完成当前剩余
提交报工
下一商品
```

### 5.2 核心输入/输出字段

| 类型 | 字段 |
|---|---|
| 输入 | 商品 ID、附加项类型、本次完成数量、实际处理人、照片/凭证 |
| 输出 | 可处理正品数、每项应做数量、已做数量、剩余数量、是否需尾检复核 |
| 系统判断 | 是否配置该附加项、是否已完成、是否超报、是否需要贴纸/吊牌校验 |

### 5.3 主操作按钮与状态控制

主按钮：

```text
提交报工
```

快捷按钮：

```text
完成当前剩余
贴纸完成
吊牌完成
剪标完成
换包装完成
拍照完成
上传凭证
```

状态控制规则：

1. 未配置的附加项不展示，或展示为灰色不可点。
2. 附加项累计完成数量不能超过可处理正品数。
3. 已完成项目置灰并显示“已完成”。
4. 贴纸、吊牌类项目提交后标记“待尾检复核”。
5. 处理人未确认时不允许提交，混岗场景建议支持扫员工工牌。

### 5.4 物理/声音防错机制

| 场景 | 反馈 |
|---|---|
| 扫 VAS 码成功 | 成功音 + 语音“进入附加项报工” |
| 无待处理附加项 | 绿色提示“无需附加项” |
| 附加项超量 | 红色弹窗 + 震动，“超出可处理正品数” |
| 贴纸/吊牌提交 | 语音“请等待尾检复核” |
| 重复报工 | 黄色提示“该项已完成，确认是否追加” |

## 6. 尾检工作台

### 6.1 页面布局描述

```text
[顶部固定区]
尾检工作台
扫描商品ID二维码
当前状态：可入库 / 不可入库 / 待退回 / 异常

[放行状态区]
是否可入库
当前拦截原因
红/黄/绿状态条

[汇总核对区]
初检到货数
待定数
质检人员
质检正品数
质检不良数
附加项完成状态
贴纸/吊牌状态

[复核操作区]
实物数量确认
不良品确认
贴纸/吊牌一致性确认
包装信息确认

[底部固定操作区]
尾检通过
退回质检
退回附加项
退回初检
标记异常
补打流转单
```

### 6.2 核心输入/输出字段

| 类型 | 字段 |
|---|---|
| 输入 | 商品 ID、尾检结果、退回原因、贴纸/吊牌复核结果、备注 |
| 输出 | 到货数、待定数、正品数、不良数、质检人员、附加项完成状态、是否可入库 |
| 系统判断 | 是否质检已报工、附加项是否完成、数量是否一致、异常是否关闭、是否可入库 |

### 6.3 主操作按钮与状态控制

主按钮按状态显示：

```text
可入库：尾检通过
不可入库：查看拦截原因
```

退回按钮：

```text
退回质检
退回附加项
退回初检
标记贴纸/吊牌异常
补打流转单
```

强拦截规则：

1. 质检未报工，不允许尾检通过。
2. 质检人员缺失，不允许尾检通过。
3. 附加项未完成，不允许尾检通过。
4. 待定数量未处理，不允许尾检通过。
5. 不良数量未隔离，不允许尾检通过。
6. 贴纸/吊牌信息不一致，不允许尾检通过。
7. 系统数量与实物数量不一致时，必须退回或由主管更正。

### 6.4 物理/声音防错机制

| 场景 | 反馈 |
|---|---|
| 可入库 | 绿色全宽提示 + 成功音，“可以入库” |
| 被拦截 | 红色全屏提示 + 长音，“禁止通过” |
| 附加项未完成 | 黄色提示，“请退回附加项处理” |
| 质检未报工 | 红色提示，“请退回质检补报工” |
| 贴纸/吊牌不一致 | 红色提示 + 必填退回原因 |
| 尾检通过 | 成功音 + 语音“尾检通过，放行入库” |

## 7. 落地建议

第一版 PDA 不建议做复杂表格。每个岗位只保留五个问题：

```text
扫什么？
看什么？
填几个数量？
点哪个按钮？
异常时退给谁？
```

推荐落地顺序：

1. 先上线商品 ID 扫码进入作业页。
2. 再上线质检扫码报工和附加项扫码报工。
3. 然后上线尾检扫码复核与强拦截。
4. 最后补齐语音、震动、工牌扫码、拍照凭证和离线兜底。

最终体验目标：

```text
现场人员少搜索、少输入、少手写；
系统自动记录人、货、数量、时间；
异常被及时隔离；
尾检只做复核和放行。
```
