# PDA 四工作台原型设计说明与页面布局规约

版本：v0.1 详细原型说明  
日期：2026-09-05  
关联文档：`商品ID二维码报工与QCVAS数字化初版PRD-20260905.md`、`PDA四工作台交互规约-20260905.md`  
适用终端：PDA 工业终端、手持扫码终端、小屏工位终端  
使用场景：仓库一线人员单手持 PDA 连续扫码作业，要求大字体、强对比、少输入、强防错。  
页面目标：帮助初检、质检、附加项处理、尾检人员快速扫码核对信息，并准确记录数量、责任人与异常状态。

---

## 1. 全局设计规约

### 1.1 屏幕与操作假设

| 项目 | 规约 |
|---|---|
| 设备 | 5 至 6.5 英寸 PDA，支持实体扫码键或外接扫码枪 |
| 操作姿势 | 单手持机，拇指主要操作屏幕下半区 |
| 字号 | 关键数量不低于 28px，商品 ID/状态不低于 18px，普通字段不低于 14px |
| 触控尺寸 | 主按钮高度建议 56px 至 64px，次按钮不低于 44px |
| 布局 | 顶部固定状态，中部滚动内容，底部固定操作区 |
| 色彩 | 高对比底色，绿色可通过，黄色待确认，红色拦截，灰色不可操作 |
| 输入 | 优先扫码，其次数量加减器，再次数字键盘，尽量不用长文本输入 |

### 1.2 通用页面骨架

```text
+------------------------------------------------+
| Header：工位名 | 工号 | 网络 | 当前状态        |
+------------------------------------------------+
| 扫描框 / 扫码提示 / 当前码                     |
+------------------------------------------------+
| 主信息展示区：商品/包裹/订单/数量/任务         |
|                                                |
| 可滚动，但首屏必须露出关键状态和主按钮         |
+------------------------------------------------+
| 底部固定操作区：次操作      主操作             |
+------------------------------------------------+
```

### 1.3 通用状态色

| 状态 | 展示颜色 | 展示文案示例 |
|---|---|---|
| 待扫码 | 深色底 + 白字 | 请扫描快递单号 / 请扫描商品 ID |
| 可操作 | 绿色 | 可处理、可质检、可尾检、可入库 |
| 当前处理中 | 蓝色 | 正在初检、正在质检、正在报工 |
| 待确认 | 黄色 | 有待定、部分完成、需确认 |
| 异常拦截 | 红色 | 禁止通过、数量超限、未完成 |
| 已完成 | 灰色或绿色描边 | 已质检、已报工、已尾检 |

### 1.4 通用声音与物理反馈

| 场景 | 声音/物理反馈 | 屏幕反馈 |
|---|---|---|
| 扫码成功 | 短促成功音 | 绿色边框闪烁 0.5 秒 |
| 提交成功 | 成功音，可选语音播报 | Toast + 状态变更 |
| 扫错码 | 错误短音 | 红色提示条，说明应扫什么码 |
| 数量超限 | 长错误音 + 震动 | 红色强弹窗，不允许继续 |
| 发现异常 | 警示音 | 黄色或红色异常面板展开 |
| 尾检放行 | 成功音 + 语音“尾检通过” | 绿色全宽通过态 |
| 尾检拦截 | 长错误音 + 震动 | 红色全屏拦截原因 |

## 2. 初检工作台

### 2.1 页面目标

帮助初检人员完成“拆包确认”：从国内快递单号进入关联订单，核对实物与订单商品信息，填写到货数量与待定数量，必要时创建或关联工单，并生成商品流转单。

### 2.2 界面布局 ASCII 示意图

```text
+------------------------------------------------+
| 初检工作台        工号: A102   WiFi  待拆包     |
+------------------------------------------------+
| [ 扫描快递单号 / 商品ID ]             [扫码]   |
| 当前快递: SF1234567890                         |
+------------------------------------------------+
| 匹配状态：已匹配 1 个订单                      |
| 订单号: B2B20260905001     店铺: XX旗舰店      |
| 平台单号: 1688-99887766                        |
+------------------------------------------------+
| 商品核对                                       |
| [商品图 96x96]  商品ID: D000010471             |
| 颜色: 黑色   尺码: L   规格: 10件/包           |
| 应到: 10      已到: 0       剩余: 10           |
+------------------------------------------------+
| 本次数量                                       |
| 到货数量   [-]   10   [+]    [全部到货]        |
| 待定数量   [-]    0   [+]    [有待定]          |
| 异常原因: [颜色不符] [尺码不符] [少发] [破损] |
| [拍照] [创建/关联工单]                         |
+------------------------------------------------+
| [下一包裹]        [确认到货并打印流转单]       |
+------------------------------------------------+
```

### 2.3 从上到下布局规约

#### 顶部 Header 区

1. 左侧显示工位名称：`初检工作台`。
2. 中间显示当前登录工号或姓名：`工号: A102`。
3. 右侧显示网络状态、扫码设备状态、当前主状态。
4. 当前状态可为：`待扫码`、`已匹配`、`多商品`、`有待定`、`已完成`、`异常`。

#### 主信息展示区

默认展开：

1. 快递单号。
2. 匹配订单数。
3. 订单号。
4. 店铺。
5. 商品图片。
6. 商品 ID。
7. 颜色、尺码、规格。
8. 应到数量、已到数量、剩余数量。
9. 本次到货数量、待定数量。

默认折叠：

1. 平台商品链接。
2. 客户备注全文。
3. 历史到货记录。
4. 历史工单记录。

高亮字段：

1. 商品 ID：黑底白字或蓝底白字。
2. 本次到货数量：大字号。
3. 待定数量：黄色或红色。
4. 异常原因：黄色标签。

#### 关键操作区

1. 扫描框固定在 Header 下方，扫码后自动填入，不要求点击输入框。
2. 数量采用大字号步进器，支持 `-`、`+`、数字键盘、`全部到货`。
3. 待定数量大于 0 时，自动展开异常原因区。
4. 底部固定双按钮：左侧为次操作 `下一包裹`，右侧为主操作 `确认到货并打印流转单`。

### 2.4 组件与字段矩阵表

| 组件名称 | 类型 | 字段名 | 默认值 | 交互规则 |
|---|---|---|---|---|
| 工位标题 | 文本 | station_name | 初检工作台 | 固定显示 |
| 登录工号 | 文本/徽标 | operator_code | 当前登录人 | 未登录时禁止操作 |
| 网络状态 | 图标/文本 | network_status | 在线 | 离线时允许暂存但标记风险 |
| 扫描框 | 扫码输入 | scan_code | 空 | 支持快递单号、商品 ID；扫码后自动查询 |
| 快递单号 | 文本 | package_no | 扫码后填充 | 高亮展示，支持复制/重扫 |
| 匹配订单数 | 状态标签 | match_count | 0 | 0 红色、1 绿色、多于 1 黄色 |
| 商品图片 | 图片 | product_image | 占位图 | 点击可放大 |
| 商品 ID | 高亮文本 | goods_uuid | 空 | 例如 `D000010471`，必须大字号 |
| 规格信息 | 文本组 | sku_spec | 空 | 颜色、尺码、规格分行展示 |
| 应到数量 | 数字 | expected_qty | 0 | 只读 |
| 已到数量 | 数字 | arrived_qty | 0 | 只读 |
| 剩余数量 | 数字 | remaining_qty | 0 | 只读，低于 0 红色 |
| 本次到货数量 | 数量加减器 | current_arrive_qty | 0 | 不能小于 0，超过剩余需原因 |
| 待定数量 | 数量加减器 | pending_qty | 0 | 大于 0 必填原因 |
| 异常原因 | 标签多选 | exception_reason | 空 | 待定数量大于 0 时必填 |
| 拍照入口 | 按钮 | proof_images | 空 | 异常时建议必传 |
| 创建/关联工单 | 按钮 | work_order_ref | 空 | 待定数量大于 0 时显示 |
| 确认并打印 | 主按钮 | submit_and_print | 禁用 | 数量合法且商品确认后激活 |
| 下一包裹 | 次按钮 | next_package | 启用 | 清空当前页，回到待扫码 |

### 2.5 关键状态变化与防错逻辑

| 状态 | 触发条件 | 页面反馈 | 按钮逻辑 |
|---|---|---|---|
| 默认空状态 | 未扫码 | 提示“请扫描国内快递单号” | 主按钮禁用 |
| 已匹配单商品 | 快递单号匹配唯一商品 | 绿色状态“已匹配” | 可填写数量 |
| 匹配多个商品 | 一个快递关联多个商品 | 黄色状态“请选择商品” | 未选商品前主按钮禁用 |
| 未匹配订单 | 快递单号无订单 | 红色提示“未匹配订单” | 禁止到货确认 |
| 数量超限 | 本次到货数大于剩余应到 | 红色弹窗 + 震动 | 必须填原因或主管确认 |
| 有待定 | 待定数量大于 0 | 黄色面板展开 | 必填原因，建议拍照和工单 |
| 可提交 | 到货数量合法，待定规则满足 | 主按钮变绿色 | 点击后打印流转单 |
| 已提交 | 提交成功 | 成功音 + 打印提示 | 页面准备下一件 |

## 3. 质检工作台

### 3.1 页面目标

帮助质检人员按客户选择的检品方式完成检品，并即时记录检品数量、正品数量、不良数量、问题类型和实际质检人员，减少尾检二次代录。

### 3.2 界面布局 ASCII 示意图

```text
+------------------------------------------------+
| 质检工作台        工号: Q018   WiFi  待质检     |
+------------------------------------------------+
| [ 扫描商品ID二维码 ]                  [扫码]   |
| 当前商品: VAS/D000010471                        |
+------------------------------------------------+
| 商品信息                                       |
| [商品图 96x96]  D000010471                     |
| 黑色 / L / 10件装                              |
| 检品方式: 全检 + 外观检查                      |
+------------------------------------------------+
| 数量状态                                       |
| 可检: 8        已检: 0        剩余: 8          |
| 本次检品  [-]  8  [+]  [全部剩余]              |
+------------------------------------------------+
| 检品结果                                       |
| 正品  [-]  8  [+]                              |
| 不良  [-]  0  [+]     [发现不良]               |
| 问题: [破损] [污渍] [线头] [规格不符] [其它]  |
| [拍照] [通知初检]                              |
+------------------------------------------------+
| [有不良]              [确认全部正品/提交下一件]|
+------------------------------------------------+
```

### 3.3 从上到下布局规约

#### 顶部 Header 区

1. 左侧显示 `质检工作台`。
2. 中间显示当前质检人员工号。
3. 右侧显示网络、扫码状态、当前质检状态。
4. 状态可为：`待扫码`、`可质检`、`部分质检`、`有不良`、`已完成`、`不可质检`。

#### 主信息展示区

默认展开：

1. 商品 ID。
2. 商品图片。
3. 颜色、尺码、规格。
4. 客户选择的检品方式。
5. 可质检数量。
6. 已质检数量。
7. 剩余数量。
8. 本次检品数量。
9. 正品数量。
10. 不良数量。

默认折叠：

1. 客户备注。
2. 检品标准详细说明。
3. 历史质检记录。
4. 历史异常事件。

高亮字段：

1. 检品方式：蓝色标签。
2. 可质检数量和剩余数量：大字号。
3. 不良数量：红色大字号。
4. 问题类型：红色或黄色标签。

#### 关键操作区

1. 扫商品 ID 后自动进入商品质检页。
2. `全部剩余` 会把本次检品数量设为剩余可检数量。
3. `确认全部正品` 会自动设置：本次检品数 = 剩余数量，正品数 = 剩余数量，不良数 = 0。
4. `有不良` 会展开不良录入区，并要求填写不良数量和问题原因。
5. 底部右侧主按钮根据状态变化：`确认全部正品`、`提交并下一件`、`已完成`。

### 3.4 组件与字段矩阵表

| 组件名称 | 类型 | 字段名 | 默认值 | 交互规则 |
|---|---|---|---|---|
| 工位标题 | 文本 | station_name | 质检工作台 | 固定显示 |
| 质检人员 | 文本/工牌 | inspector_code | 当前登录人 | 可支持扫员工码切换实际人员 |
| 扫描框 | 扫码输入 | goods_code | 空 | 只接受商品 ID 或 VAS 码 |
| 商品图片 | 图片 | product_image | 占位图 | 点击放大 |
| 商品 ID | 高亮文本 | goods_uuid | 空 | 必须高亮 |
| 规格信息 | 文本组 | sku_spec | 空 | 与实物核对 |
| 检品方式 | 标签组 | qc_method | 空 | 默认展开，显示客户选择内容 |
| 可质检数量 | 大数字 | available_qc_qty | 0 | 只读，不含待定数量 |
| 已质检数量 | 数字 | inspected_qty | 0 | 只读 |
| 剩余数量 | 大数字 | remaining_qc_qty | 0 | 为 0 时主按钮变已完成 |
| 本次检品数量 | 数量加减器 | current_qc_qty | 0 | 不得超过剩余数量 |
| 正品数量 | 数量加减器 | genuine_qty | 0 | 与不良数合计等于本次检品数 |
| 不良数量 | 数量加减器 | bad_qty | 0 | 大于 0 时展开原因和拍照 |
| 问题类型 | 标签单选/多选 | bad_reason | 空 | 不良大于 0 时必填 |
| 拍照入口 | 按钮 | proof_images | 空 | 不良时建议必传 |
| 通知初检 | 按钮 | notify_initial_qc | 隐藏 | 有异常时显示 |
| 有不良 | 次按钮/危险按钮 | open_bad_panel | 启用 | 展开异常录入 |
| 提交并下一件 | 主按钮 | submit_qc | 禁用 | 数量平衡且不超限后激活 |

### 3.5 关键状态变化与防错逻辑

| 状态 | 触发条件 | 页面反馈 | 按钮逻辑 |
|---|---|---|---|
| 默认空状态 | 未扫码 | 提示“请扫描商品 ID 二维码” | 主按钮禁用 |
| 扫到快递单号 | 码类型错误 | 红色提示“请扫描商品 ID” | 禁止继续 |
| 可质检 | 商品存在且有剩余可检数量 | 绿色状态“可质检” | 可录入数量 |
| 有待定隔离 | 商品存在待定数量 | 黄色提示“待定数量已隔离” | 只允许处理可质检数量 |
| 数量不平 | 正品数 + 不良数不等于本次检品数 | 红色提示 | 提交禁用 |
| 数量超限 | 本次检品数大于剩余数量 | 红色弹窗 + 震动 | 提交禁用 |
| 不良未填原因 | 不良数大于 0 且原因空 | 黄色拦截 | 提交禁用 |
| 质检完成 | 剩余数量为 0 | 绿色提示“质检完成” | 主按钮变灰或进入下一件 |

## 4. 附加项报工工作台

### 4.1 页面目标

帮助贴纸、吊牌、剪标、换包装、拍照等附加项处理人扫码完成独立报工，记录实际处理人、附加项类型、完成数量和必要凭证，替代纸面勾选与手写工号。

### 4.2 界面布局 ASCII 示意图

```text
+------------------------------------------------+
| 附加项报工        工号: V026   WiFi  待处理     |
+------------------------------------------------+
| [ 扫描 VAS/商品ID ]                   [扫码]   |
| 当前商品: VAS/D000010471                        |
+------------------------------------------------+
| 商品摘要                                       |
| [商品图 80x80]  D000010471                     |
| 可处理正品: 7      已完成项: 2/4               |
+------------------------------------------------+
| 待处理附加项                                   |
| [贴纸] 应做7 已做5 剩2   待尾检复核            |
| [吊牌] 应做7 已做0 剩7   需扫码核对            |
| [剪标] 应做7 已做7 剩0   已完成                |
| [拍照] 应做1 已做0 剩1   待处理                |
+------------------------------------------------+
| 当前报工：贴纸                                 |
| 本次完成  [-]  2  [+]  [完成剩余]              |
| 实际处理人: V026     [扫员工码]                |
| [上传凭证] [扫描贴纸/吊牌码]                   |
+------------------------------------------------+
| [下一商品]                  [提交报工]         |
+------------------------------------------------+
```

### 4.3 从上到下布局规约

#### 顶部 Header 区

1. 左侧显示 `附加项报工`。
2. 中间显示实际处理人工号。
3. 右侧显示网络、扫码设备、当前附加项状态。
4. 状态可为：`待扫码`、`待处理`、`部分完成`、`已完成`、`待尾检复核`、`异常`。

#### 主信息展示区

默认展开：

1. 商品 ID。
2. 商品图片。
3. 可处理正品数。
4. 附加项总进度。
5. 待处理附加项列表。
6. 当前选中附加项。
7. 本次完成数量。
8. 实际处理人。

默认折叠：

1. 已完成附加项明细。
2. 历史报工记录。
3. 附加项详细说明。
4. 客户备注全文。

高亮字段：

1. 可处理正品数：绿色大数字。
2. 剩余数量：大数字。
3. 已完成项：绿色标签。
4. 待尾检复核：黄色标签。
5. 异常/超限：红色标签。

#### 关键操作区

1. 默认只展示该商品已配置或客户已选择的附加项。
2. 点击某个附加项后，下方出现该附加项报工区。
3. `完成剩余` 自动填入当前附加项剩余数量。
4. 贴纸/吊牌类附加项显示 `扫描贴纸/吊牌码`。
5. 混岗时，允许扫描员工工牌切换实际处理人。
6. 底部固定左侧 `下一商品`，右侧 `提交报工`。

### 4.4 组件与字段矩阵表

| 组件名称 | 类型 | 字段名 | 默认值 | 交互规则 |
|---|---|---|---|---|
| 工位标题 | 文本 | station_name | 附加项报工 | 固定显示 |
| 实际处理人 | 文本/工牌 | operator_code | 当前登录人 | 可扫员工码切换 |
| 扫描框 | 扫码输入 | goods_or_vas_code | 空 | 支持 `VAS/D000010471` 和商品 ID |

## 5. 尾检工作台

### 5.1 页面目标

帮助尾检人员在入库前完成最后复核：确认初检、质检、附加项、异常、贴纸/吊牌、实物数量均一致。尾检不再主要代录前序岗位数据，而是执行系统拦截、退回和放行。

### 5.3 从上到下布局规约

#### 顶部 Header 区

1. 左侧显示 `尾检工作台`。
2. 中间显示尾检人员工号。
3. 右侧显示网络、扫码设备、当前尾检状态。
4. 状态可为：`待扫码`、`可入库`、`不可入库`、`待退回`、`已退回`、`已通过`。

#### 主信息展示区

默认展开：

1. 商品 ID。
2. 放行状态。
3. 拦截原因。
4. 初检到货数。
5. 待定数。
6. 质检人员。
7. 质检正品数。
8. 质检不良数。
9. 可入库数量。
10. 附加项完成状态。
11. 贴纸/吊牌状态。
12. 复核勾选项。

默认折叠：

1. 历史退回记录。
2. 工单详情。
3. 附加项报工明细。
4. 照片凭证。

高亮字段：

1. 放行状态：全宽大字号，绿色或红色。
2. 拦截原因：红色大字号。
3. 可入库数量：绿色大数字。
4. 未完成附加项：红色标签。
5. 待定数量：黄色标签。
6. 不良数量：红色标签。

#### 关键操作区

1. 扫商品 ID 后，系统直接展示是否可入库。
2. 如果不可入库，主区域优先展示第一条拦截原因。
3. 根据拦截原因动态推荐退回按钮，例如 `退回质检`、`退回附加项`、`退回初检`。
4. 尾检通过前必须完成复核勾选，例如实物数量一致、不良隔离确认、贴纸/吊牌一致。
5. 底部左侧显示推荐退回动作，右侧显示 `尾检通过`。
6. 不满足通过条件时，`尾检通过`置灰，并提示具体原因。

## 6. 四工作台关键差异汇总

| 工作台 | 扫什么 | 看什么 | 填什么 | 主按钮 | 拦截重点 |
|---|---|---|---|---|---|
| 初检 | 快递单号/商品 ID | 订单、商品、规格、应到数量 | 到货数、待定数、异常原因 | 确认到货并打印流转单 | 未匹配、超收、待定无原因 |
| 质检 | 商品 ID 二维码 | 检品方式、可检数、商品信息 | 检品数、正品数、不良数 | 提交并下一件 | 数量不平、超检、不良无原因 |
| 附加项 | VAS 码/商品 ID | 待做附加项、应做已做剩余 | 附加项完成数、处理人 | 提交报工 | 未配置、超报、处理人缺失 |
| 尾检 | 商品 ID 二维码 | 前序记录、数量、附加项、贴纸吊牌 | 实物确认、复核结果、退回原因 | 尾检通过 | 未报工、未完成、数量不一致 |

## 7. 原型验收检查清单

1. 每个页面首屏能看到工位名、扫描框、商品 ID 或待扫码提示、核心状态、主按钮。
2. PDA 单手操作时，主要按钮位于屏幕下半区，拇指可触达。
3. 所有数量输入都有加减器和快捷填充按钮。
4. 所有红色拦截都必须告诉用户“为什么不能继续”和“下一步退给谁”。
5. 质检和附加项处理完成后，系统能立即形成员工产出记录。
6. 尾检页面不能成为大表单录入页，只能是复核、退回、放行页。
7. 异常原因优先使用标签，不要求现场人员输入长文本。
8. 扫错码、重复扫码、数量超限必须有声音或震动反馈。
9. 商品图片、商品 ID、颜色、尺码、规格必须在初检和质检首屏可见。
10. 贴纸/吊牌类附加项必须在尾检页有醒目复核状态。

## 8. 最终设计原则

第一版 PDA 原型不要追求信息完整，而要追求现场动作闭环：

```text
初检：扫包裹，确认商品和数量，隔离待定，打印流转单。
质检：扫商品，按检品方式报工，记录正品和不良。
附加项：扫商品，按项目报工，防止超报和漏做。
尾检：扫商品，看系统是否允许入库，不合格就退回。
```

所有页面都应围绕一个问题设计：

```text
现场人员此刻要做的下一步是什么？
```

只要页面能稳定回答这个问题，操作就会变轻，错误也会明显下降。
