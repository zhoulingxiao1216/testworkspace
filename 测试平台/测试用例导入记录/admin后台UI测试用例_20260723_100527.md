# admin后台UI 测试用例

> 设计依据：`superpowers.md`、`测试点大纲.md`、`后端业务页面PRD.html`、`页面/后端UI设计规范.html`、本地页面原型与截图资产。  
> 覆盖范围：全局 UI 规则、列表搜索表格分页、弹框抽屉反馈、报价与吐槽、订单质检详情、仓储物流、管理配置、财务系统和回归门禁。  
> 用例总数：51 条，其中 Critical 22 条、High 26 条、Medium 3 条。

## 1. 全局 UI 与业务不变性 UI-GLOBAL

### 1.1 全局规则

#### TC-ADM-UI-GLOBAL-001 【Critical·Regression】UI 改造不改变业务
| 字段 | 内容 |
| :-- | :-- |
| **测试点** | UI 改造前后业务流程、接口字段、权限、金额计算和导出内容不变性验证。 |
| **优先级** | Critical |
| **前置条件** | 1. 已准备旧版或线上后台对照环境。<br>2. Admin-UI-Owner 与 Admin-Limited 均可登录。<br>3. 选择报价单、审核通过详情、商品入库、授权管理和财务审核各 1 个代表页面。 |
| **操作步骤** | 1. 在旧版环境记录页面入口、按钮显隐、接口请求字段、导出字段和关键金额。<br>2. 在改造环境执行相同查询、查看、导出和高风险操作前置动作。<br>3. 对比两端业务字段、权限拦截和计算结果。 |
| **预期结果** | 1. 页面样式和交互可变化，但接口字段、权限规则、金额计算、状态流转和导出字段保持一致。<br>2. Admin-Limited 无权限操作仍被前端和后端拦截。<br>3. 未发现 UI 改造引入的业务逻辑变化。 |

| **优先级** | High |
| **前置条件** | 1. 可访问至少 5 个已改造后台页面。<br>2. 已知项目 Element Plus 版本或以后端 UI 设计规范为验收依据。 |
| **操作步骤** | 1. 分别打开吐槽记录、报价单、商品入库、授权管理和财务审核页面。<br>2. 检查搜索、按钮、表格、分页、弹框和 Toast 的组件形态。<br>3. 触发悬浮、聚焦、选中、禁用、加载和失败状态。 |
| **预期结果** | 1. 控件形态与 Element Plus 或项目封装一致。<br>2. default、primary、success、info、warning、danger 语义色使用清晰。<br>3. 未出现手写伪按钮、伪下拉、伪分页或不可识别状态。 |
