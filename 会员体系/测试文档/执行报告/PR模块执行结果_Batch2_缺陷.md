# 定价规则模块 (PR) 执行报告 (Batch 2 - 修正补充)

**执行时间:** 2026-05-11
**执行环境:** 测试环境 (Layer 2-UI)

## 🚨 缺陷提报：BUG-PR-001

| 缺陷编号 | BUG-PR-001 |
|---|---|
| **关联用例** | TC-PR-013 |
| **缺陷等级** | **High (高危)** |
| **缺陷标题** | **付费等级（如企业会员）缺乏防损校验，允许将实际收取会员费配置为 0 元并成功落库** |
| **复现步骤** | 1. 登录管理端，进入“全球会员定价”配置页。<br>2. 选中任意一个**非免费**的付费等级Tab（如“企业会员”）。<br>3. 编辑任一套餐的“会员价格”，将其强制修改为 `0`，并确保“划线价”大于 0（避免触发倒挂拦截）。<br>4. 点击“保存全部”按钮。 |
| **预期结果** | 系统应当触发防损校验，弹出例如“会员价格必须大于 0”的错误拦截，阻止该次非法修改落库。 |
| **实际结果** | 没有任何报错提示。前台直接弹出“国家设置已保存”与“等级定价已保存”的双重成功 Toast，`0` 元的付费套餐配置成功写入后端。 |
| **影响面评估** | 该漏洞可能导致运营人员误操作，将高价值的付费等级变成免费白嫖，造成公司的直接财务损失（0元购漏洞）。 |

## 🚀 结论
通过专门针对“付费层级”的第二次探针复盘测试，正式确立了 **TC-PR-013 为 Fail**。
系统的表单网关缺失了针对核心付费属性的底线金额校验，我已生成上述标准的缺陷报告单。
