## 二、需求背景

全球站 1.0 上线后，业务部门在试用代购订单相关功能时反馈：当订单商品数量较多、商铺较多、采购状态复杂时，订单详情页缺少商品级筛选，进行中列表也缺少快速定位未确认金额订单与未购买订单的能力，导致采购定位问题商品和费用确认效率较低。

本次需求包含任务 `1001257`、`1001254`，核心目标是提升全球站后台 B2B 代购订单详情页和代购订单进行中列表的查询、定位与确认效率。

## 四、核心业务规则摘要

| 规则域 | 规则摘要 | 高风险点 |
|:--|:--|:--|
| 商品 ID 筛选 | 商品 ID 对应商品 SKU，支持精确匹配 | 不能模糊命中、不能跨订单串数据 |
| 商品状态筛选 | 待入库、部分入库、已入库按正品数量、已入库数量、发货数量判断 | 状态口径依赖数量字段，易误判 |
| 采购状态筛选 | 待采购、部分到货、暂不购买按采购数据更新和暂不购买动作判断 | 采购流程状态必须与详情操作一致 |
| 质检状态筛选 | 有不良、有待定、有退货、有换货、待检品按对应数量大于 0 判断 | 一个商品可能同时命中多种质检状态 |
| 采购差价负数 | 负数时不允许采购确认，提示“采购差价不允许为负数，请核对后再确认！” | 金额安全链路，必须防接口绕过 |
| 店铺返现二次确认 | 未确认前仅记录在店铺返现栏，不同步采购差价；确认后采购员不可修改 | 金额计算、权限锁定、数据持久化 |
| 金额是否确认筛选 | 订单中存在采购确认按钮未点击的商铺即归入未确认；未确认筛选还需满足采购数=不良数+正品数 | 订单级聚合判断，多商铺易误归类 |
| 购入数排序 | 点击购入数排序后，购入数量为空的订单排到最上方 | 空值、0、分页全量排序口径 |

## 五、影响面

| 影响对象 | 影响说明 | 测试策略 |
|:--|:--|:--|
| 代购订单详情页 | 新增筛选栏，影响商品列表展示、店铺分组、商品操作入口 | 覆盖默认值、选项、单条件、多条件、无结果、刷新返回 |
| 代购订单进行中列表 | 新增金额确认筛选与购入数排序 | 覆盖筛选、分页、排序、列表详情一致性 |
| 采购确认流程 | 采购差价负数可能阻断确认 | 覆盖 UI 拦截、接口拦截、状态不误更新 |
| 店铺返现/采购差价计算 | 返现确认前后影响采购差价口径 | 覆盖确认前后金额、权限、刷新持久化 |
| 权限与审计 | 不同角色对采购确认、返现确认、列表筛选权限不同 | 覆盖采购员、主管/管理员、无权限角色 |
| 非功能 | 大订单、多店铺、多商品下筛选和排序性能 | 覆盖多页、多店铺、大订单数据 |
