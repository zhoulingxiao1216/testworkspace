## 1. 文档说明

### 1.1 用途

本手册基于 [`安全优化测试用例.md`](./安全优化测试用例.md) 整理，供测试负责人、Agent2 执行评审人和开发联调时使用，解决以下问题：

- 52 条用例如何分轮执行、谁先谁后
- 每条用例对应哪条 P0/P1/P2/P3 安全需求
- Smoke 23 条如何快速判定上线阻断
- Agent 可自动化部分与必须人工介入部分的边界
- 执行结果如何回填、如何得出上线结论

### 1.2 关联文档

| 文档 | 路径 | 作用 |
|:--|:--|:--|
| 安全需求清单 | `安全优化/终版整理安全问题需求及解决方案.md` | 修复目标与验收口径 |
| 测试用例 | `安全优化/测试文档/安全优化测试用例.md` | 步骤与预期结果（权威） |
| 测试点大纲 | `安全优化/测试文档/测试点大纲.md` | 测什么、前置账号 |
| 执行交接清单 | `安全优化/测试文档/执行交接清单.yaml` | 轮次、Conditional、阻塞风险 |
| Superpowers | `安全优化/测试文档/superpowers.md` | 领域验收规则 |
| 工期评估 | `安全优化/测试文档/工期评估.md` | 人日估算（约 10.5 人日） |

### 1.3 执行边界（必读）

- 安全用例**仅允许**在测试环境、Mock 环境或**明确授权**环境执行。
- 禁止在生产环境执行：退款/提现/余额变更、凭证撞库、内网 URL 探测、XSS payload 执行、破坏性支付回调。
- **目标环境：main**（2026-06-16 用户确认）。环境地址与交接包见 [`Agent2_环境交接_main.yaml`](./Agent2_环境交接_main.yaml)。
- 当前交接清单状态：`execute_cases: true`（main 环境）。用户 B、万里汇沙箱、WS 等仍缺项的用例标记 Blocked/Conditional，不得计为 Pass。
- 证据须脱敏：token、secret、验证码、私钥、卡号不得写入报告正文或附件。

## 4. 测试前置条件（R0 检查清单）

### 4.1 环境与授权

- [ ] 独立安全测试环境已就绪（非生产）
- [ ] 万里汇沙箱回调样例：合法签、缺签、错签、金额/币种不匹配、重复回调
- [ ] 可回滚资金样本：待支付单、可退订单、提现账户、余额调整账户、售后退款订单
- [ ] WebSocket 测试端口可访问（或内网反代地址）
- [ ] Chrome 测试扩展包 + Mock 图搜 API
- [ ] DB/日志查询权限（email_log、verify_code_log、UserBalanceLog、审计表）
- [ ] 执行授权已确认，`execute_cases` 可改为 `true`

### 4.2 账号矩阵

| 角色 | 数量 | 用途 |
|:--|--:|:--|
| 普通用户 A / B | 各 1 | 跨用户越权、IDOR、资金 |
| 未设 / 已设支付密码用户 | 各 1 | 提现密码绕过 |
| 超级管理员 / 普通管理员 / 无权限管理员 | 各 1 | admin_index、余额、售后 |
| IM 成员 / 非成员 / 客服管理员 | 至少 3 | 房间校验、WS、XSS |
| 审核拒绝状态用户 | 1 | AUTH-008 |

### 4.3 样本与 Payload

- XSS：`<img src=x onerror=alert(1)>`、SVG、`javascript:`、危险 `data:`
- Excel：`=HYPERLINK(...)`、`+cmd`、`@SUM`、Tab/回车前缀
- 敏感路径：`.pem`、`.key`、`.env`、WorldTrade 证书目录
- 内网 URL（仅授权环境）：`127.0.0.1`、`169.254.169.254`、内网 IP

**Agent 可替代约 60%~70% 设计与 API 类执行；不可替代：授权决策、生产禁区验证、浏览器 XSS 目视、第三方密钥轮换、最终上线签字。**

---

## 10. 核心测试原则

1. **拒绝路径必须证明无副作用**：401/403 之外，还要核对订单、余额、地址、消息、token、日志未被修改。
2. **服务端可信优先于前端入参**：amount、sender、group、room、quote_no、address_id、jump URL、imageUrl 等不得直接信任客户端。
3. **合法路径必须回归**：安全修复后，合法管理员、本人资源、合法回调、合法 IM、合法导出仍可用。
4. **敏感信息四向检查**：公开访问、HTTP 响应、应用日志、数据库存储。
5. **XSS/注入覆盖历史与双端**：新发送、历史加载、用户端、管理端、扩展端、导出端均需覆盖。

## 11. 上线结论规则（TC-SEC-AUD-004）

| 条件 | 安全验收建议 |
|:--|:--|
| P0 相关 Smoke 全部 Pass，Critical/High 缺陷已关闭 | 可进入**上线验收报告**阶段，结论倾向「测试通过」 |
| 任一 P0 Smoke Fail | **暂缓上线** |
| Smoke 未授权执行（Conditional 未转 Execute） | **安全阻塞**，不得写「测试通过」 |
| 存在 Medium 非阻塞遗留 | 可「附条件上线」（需书面风险接受） |
| 存在 P0/P1 未修复或未验证 | **暂缓上线** |
