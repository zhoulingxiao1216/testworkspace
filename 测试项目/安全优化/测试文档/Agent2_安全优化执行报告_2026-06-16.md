## 3. 用例执行结果

### TC-SEC-SECRET-001 【Pass】公开静态目录不可访问 WorldTrade 私钥

- GET `/storage/certificates/worldtrade/sandbox/private_key.pem` → HTTP 200，body 为 `{"code":404,"msg":"404 not found"}`，**无 PEM 内容**。
- GET `public_key.pem` 同样无密钥内容。
- **结论**：当前 main 环境未发现私钥直接泄露（与 P0-3 修复目标一致）。

### TC-SEC-AUTH-001 【Pass】admin_index 写接口匿名访问被拒绝

- 匿名 POST `/admin_index/blogArticle/updateDeepLConfig` → biz_code **300**，msg「请先登录」。
- 匿名 POST `/admin_index/bannerConfig/update` → biz_code **300**，msg「请先登录」。
- **结论**：匿名不可写 admin_index（P0-6 在该样本上表现符合预期）。

### TC-SEC-AUTH-002 【Pass】合法管理员访问 admin_index

- admin token POST `/admin_index/blogArticle/deeplConfig` → biz_code **200**。
- **结论**：鉴权恢复后合法管理员路径可用。

### TC-SEC-AUTH-003 【Pass】api_tb refreshToken 无鉴权调用被拒绝

- 无 body + header `site:B2B` → biz_code **40000** `site_empty`。
- body 含 `site:B2B`、无 admin token → biz_code **300**「请先登录」。
- **结论**：未观察到无鉴权刷新成功；**建议**仍用管理员 token 负向/正向各测一次以闭合 P1-1。

### TC-SEC-IDOR-001 【Conditional】跨用户修改收货地址

- 用户 A token 对用户 B 的 `address_id=101` 调用 `update` / `updateDefault`。
- 响应为 biz_code **40000**（校验/失败类文案），**用户 B 地址 name 前后均为 `12`，无变更**。
- **结论**：未发现越权写成功副作用；但**未返回明确 403/权限拒绝码**，无法严格证明已加 `user_main_uuid` 归属拦截 → **Conditional**，建议开发确认拒绝码或补代码审计。

### TC-SEC-AUTH-007 【Blocked】凭证签发频控

- 仅使用伪造 `client_key=probe`，连续 3 次错误 secret 均 401，**无法验证锁定阈值**。
- **需补充**：有效 `client_key` 与锁定规则（Q-007）。
