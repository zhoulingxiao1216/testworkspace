# 新工单重构设计清单

> 日期：2026-07-07
> 依据：`docs/pm/工单处理/工单处理PRD.md`、`工单处理功能清单.md`、`工单处理流程图.md`、工单模板 / 创建工单 / 工单详情 / 我的待办原型图
> 目标：作为新工单项目重构的执行前技术方案，确认后按本文档拆分数据库、后端、管理端前端和联调任务。

## 1. 重构边界

### 1.1 本次要做

- 管理端代购订单详情商品行增加新工单入口：无工单显示“创建工单”，有工单显示“工单处理”、未完结数量角标和最新未完结状态。
- 管理端创建工单弹窗：关联商品信息、单选处理人、模板回填中文内容、问题内容、实物图、链接图。
- 管理端工单详情弹窗：顶部商品信息、左侧当前商品工单列表、中间当前处理区、右侧历史记录区。
- 管理端我的待办页面：按登录人关系和工单状态集中展示待处理工单，点击下一步打开同一个工单详情弹窗。
- 管理端工单模板页面：模板列表、搜索、复制、启用/停用、删除、新增/编辑、多语言内容维护。
- 后端新建工单主流程、状态机、权限校验、待办生成、历史记录聚合、客户确认发送与回传承接。
- 用户端客户确认页按 PRD “现有页面承接”处理，只对接新内部工单生成的确认链接 / 确认 ID 和客户回复回传数据。

### 1.2 本次不做

- 不迁移旧工单数据。
- 不复用旧工单接口、旧状态机、旧表结构作为新设计基础。
- 不删除或重做用户端客户确认页，不删除 `/user/todo/question` 现有页面、路由、接口封装和订单 / 商品入口。
- 不在客户确认页新增交互；客户侧只按现有页面能力回传客户选择结果和客户原文。
- 不做客户未回复催办能力。
- 不做模板自动翻译；多语言模板先按人工维护设计。

### 1.3 旧实现处理结论

- 旧管理端工单抽屉、工单详情弹窗、待定工单入口按废弃实现处理。
- 旧后端 `WorkOrderLog` 相关控制器、服务、模型按废弃实现处理。
- 旧数据库表不作为新系统设计基础：
  - `b2b_work_order_log`
  - `b2b_work_order_context`
  - `b2b_work_order_cate`
  - `b2b_work_order_scene`
  - `b2b_work_order_subject`
- 旧表真实删除属于破坏性数据库操作，不由 AI 自动执行；后续由人工按数据库变更流程确认。

## 2. 业务目标与核心规则

### 2.1 业务目标

- 建立“订单商品行内发起、订单内处理、我的待办集中提醒”的商品问题工单闭环。
- 一个工单同一时刻只有一个当前处理人，避免多人并行导致责任不清。
- 问题内容、内部处理、客户沟通、流转记录分类型展示，历史记录按时间倒序查看。
- 订单详情和我的待办共用同一套工单详情弹窗和后端动作接口，避免两个入口行为不一致。
- 工单模板支持多语言维护，但创建工单只回填中文；业务发送客户时才使用客户语言内容。

### 2.2 强制业务规则

| 规则ID | 规则 | 处理方式 |
| --- | --- | --- |
| RULE-001 | 创建工单必须绑定订单商品行。 | 主表保存订单号、订单商品行 ID、商品 ID、商品快照。 |
| RULE-002 | 工单编号只展示当前商品维度序号，例如 001、002。 | 后端生成 `display_no`，接口仍使用内部 `uuid`。 |
| RULE-003 | 创建工单只能选择一个处理人。 | 主表只保存 `current_handler_admin_id`，转交通过流转记录改变当前处理人。 |
| RULE-004 | 创建工单模板只回填中文。 | 创建接口保存模板中文快照；业务发送客户时再读取客户语言模板。 |
| RULE-005 | 非业务处理人提交意见后同步给业务处理。 | 生成内部处理记录、流转记录和业务待办。 |
| RULE-006 | 只有业务可发送客户确认。 | 后端校验业务角色或订单业务负责人关系。 |
| RULE-007 | 待客户确认阶段不可转交。 | 前端隐藏转交入口，后端拒绝转交接口。 |
| RULE-008 | 客户已回复后，业务确认同步不直接完结。 | 状态进入客户已确认，等待发起人最终完结。 |
| RULE-009 | 只有发起人可确认完结。 | 后端校验 `creator_admin_id`。 |
| RULE-010 | 关闭工单必须填写处理意见，可上传图片附件。 | 关闭动作复用处理意见结构，并生成历史记录。 |
| RULE-011 | 历史记录“全部”不展示流转记录。 | 聚合接口只合并工单内容、内部处理、客户沟通。 |
| RULE-012 | 图片附件分实物图和链接图。 | 附件保存 `image_group`，展示和发送客户时分组处理。 |

## 3. 状态机

### 3.1 工单状态

| 状态 | 建议值 | 说明 | 可进入动作 | 可用主动作 |
| --- | ---: | --- | --- | --- |
| 已删除 | 0 | 软删除，不对业务展示 | 软删 | 无 |
| 待处理 | 100 | 当前处理人需要处理 | 创建、转交、客户已回复后转内部处理 | 保存草稿、提交意见、发送客户确认、转交、关闭、确认完结 |
| 待客户确认 | 200 | 业务已发送客户确认，等待客户回复 | 发送客户确认、继续回复客户 | 查看、关闭、确认完结 |
| 客户已回复 | 300 | 客户提交选择结果和原文，等待业务同步 | 客户确认页回传 | 继续回复客户、确认同步、转交内部处理、关闭、确认完结 |
| 客户已确认 | 400 | 业务已将客户信息同步给提出人和相关处理人 | 确认同步 | 关闭、确认完结、查看 |
| 已完结 | 500 | 发起人确认完结或处理人关闭工单 | 确认完结、关闭工单 | 查看 |

### 3.2 状态流转

| 当前状态 | 动作 | 下一状态 | 业务记录 / 流转记录 | 待办变化 |
| --- | --- | --- | --- | --- |
| 无 | 创建工单 | 待处理 | 工单内容、流转记录 | 当前处理人新增待处理待办 |
| 待处理 | 保存草稿 | 待处理 | 草稿记录 | 不改变待办 |
| 待处理 | 非业务提交意见 | 待处理 | 内部处理、流转记录 | 当前处理人待办完成，订单业务新增待处理待办 |
| 待处理 | 业务发送客户确认 | 待客户确认 | 客户沟通、流转记录 | 当前处理人待办完成 |
| 待处理 | 转交 | 待处理 | 内部处理、流转记录 | 原处理人待办完成，新处理人新增待办 |
| 待客户确认 | 客户回复回传 | 客户已回复 | 客户沟通、流转记录 | 订单业务新增“同步客户信息”待办 |
| 客户已回复 | 继续回复客户 | 待客户确认 | 客户沟通、流转记录 | 业务同步待办完成 |
| 客户已回复 | 确认同步 | 客户已确认 | 客户沟通、流转记录 | 发起人和相关处理人新增确认结果待办 |
| 客户已回复 | 转交内部处理 | 待处理 | 内部处理、流转记录 | 新处理人新增待办 |
| 客户已确认 | 确认完结 | 已完结 | 完结、流转记录 | 相关待办完成 |
| 任意未完结状态 | 关闭工单 | 已完结 | 关闭、流转记录 | 相关待办完成 |

### 3.3 并发控制

- 主表保存 `version` 字段，每次状态变更递增。
- 所有处理动作提交时必须带 `version`。
- 后端发现版本不一致时返回 `code=400`，提示“工单状态已变化，请刷新后再处理”。
- 订单详情和我的待办同时打开同一工单时，以后端版本校验结果为准。

### 4.7 订单商品行聚合字段不落库

订单详情商品行需要展示以下工单摘要，建议由查询接口批量聚合，不写入订单商品表：

- `work_order_count`：当前商品全部工单数量。
- `unfinished_work_order_count`：未完结工单数量，状态不含 0 和 500。
- `latest_work_order_uuid`：最新未完结工单 UUID。
- `latest_work_order_status`：最新未完结工单状态。
- `latest_work_order_status_text`：状态文案。

聚合查询必须批量按 `order_detail_id` 获取，禁止在 PHP 循环中逐行查询工单数量。

## 5. 后端接口设计

所有接口响应固定为 `{ code, msg, data }`。分页参数固定 `page` / `pageSize`，列表响应固定 `list` / `total`。

### 5.1 订单详情工单摘要

| 接口 | 用途 | 关键入参 | 关键出参 |
| --- | --- | --- | --- |
| `POST /admin_b2b/workOrder/orderProductSummary` | 订单商品行批量工单摘要 | `order_no` 或 `order_detail_ids` | 每个商品行的工单数量、未完结数量、最新状态、最新工单 UUID |

接入点：

- 代购订单详情商品行查询后批量调用或在原订单详情接口内聚合返回。
- 全商品列表若需要展示新工单入口，也使用同一聚合服务。

### 5.2 工单主流程接口

| 接口 | 用途 | 关键入参 | 后端规则 |
| --- | --- | --- | --- |

## 9. 开发顺序

1. 实现工单详情聚合接口。

- 非业务不能发送客户确认。

## 11. 风险与回滚

| 风险 | 影响 | 控制方式 | 回滚方式 |
| --- | --- | --- | --- |
| 新旧工单接口混用 | 状态和历史记录错乱 | 新工单使用新接口和新表；旧接口不作为新流程依赖 | 回退新路由和页面入口 |
| 待办重复生成 | 我的待办数量不准 | 待办按 `work_order_uuid + admin_id + todo_type + status` 控制未处理唯一性 | 清理重复待办并修复生成规则 |
| 客户沟通重复展示 | 历史记录误导处理人 | 客户沟通按 `customer_confirm_uuid` 和记录 UUID 去重 | 回退聚合接口 |
| 流转记录缺失 | “流转记录”Tab 无法还原状态和处理人变化 | 每次状态动作统一调用 `WorkOrderFlowLogService` 写入流转记录 | 按业务记录和主表更新时间补录流转记录 |
| 两个入口同时提交 | 覆盖最新状态 | 主表 `version` 乐观锁 | 提示刷新，不写入旧提交 |
| 模板删除影响历史 | 历史工单内容丢失 | 工单保存模板名称和内容快照 | 恢复模板记录或从工单快照展示 |
| 用户端承接误改 | 影响现有客户确认页 | 本阶段不改页面；仅接口兼容 | 恢复用户端改动，后端兼容旧接口 |
