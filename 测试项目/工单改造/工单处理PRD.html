全球站项目：商品问题工单处理 PRD

1. 项目背景与目标

1.1 项目背景

当前代购订单在质检、采购、业务、客户确认之间存在大量商品问题确认场景，例如商品轻微瑕疵、色差、尺寸异常、供应商缺货、是否可继续发货等。原有处理方式依赖订单备注、口头沟通或分散记录，存在以下问题：

  • 商品问题与订单商品行绑定不清晰，员工无法快速判断哪个订单、哪个商品需要处理。
  • 发起问题后没有统一待办入口，处理人容易漏看、延迟处理或重复确认。
  • 客户为海外客户时，需要业务翻译并对客沟通，但内部处理人与对客沟通人边界不清。
  • 同一个商品可能产生多个问题工单，历史意见、客户回复和流转记录混杂，后续处理人阅读成本高。
  • 工单关闭、完结、同步客户信息等动作缺少权限约束，容易出现未同步、误关闭或状态断层。

1.2 优化目标

  • 建立“订单商品行内发起、订单内处理、待办集中提醒”的商品问题工单闭环。
  • 简化流程：创建工单时只选择一个处理人；处理人可提交意见、转交或关闭；只有业务可发送客户确认；发起人负责最终完结。
  • 保证信息清晰：问题内容、处理意见、客户沟通、流转记录按类别展示，历史记录按时间倒序查看。
  • 提升操作顺畅度：订单详情可直接弹窗处理工单，待办页面也可进入同一处理弹窗，避免员工在页面之间反复跳转。
  • 统一模板能力：支持工单模板、多语言内容维护，创建工单时模板只回填中文，业务发送客户时再使用客户语言内容。
  • 支持全量追溯：有权限人员可在“历史记录”模式查看所有订单工单历史，不再仅限本人创建或本人处理。
  • 支持同规格核对：同一商品规格即使商品ID不同，也可快速查看不同订单下的历史工单，辅助判断当前问题是否需要处理。

2. 【管理端】订单内工单处理与协同待办

2.0 代购订单详情页

① 核心业务逻辑介绍

代购订单详情是商品问题工单的主要业务入口。员工在商品行中发现问题后，可直接创建工单；商品已有工单时，可点击工单处理按钮进入工单详情弹窗。该页面不承载完整工单处理表单，只负责展示当前商品是否存在工单、未完结数量、当前状态和快速入口。

② 字段级别功能描述与异常流程

(1) 商品行工单入口区

字段/控件名称功能展现描述业务规则与异常边界处理
创建工单 / 工单处理商品无工单时显示“创建工单”；商品存在工单时显示“工单处理”。按钮与状态角标合并成一个整体控件，避免操作区割裂。点击“创建工单”打开创建工单弹窗；点击“工单处理”打开工单详情弹窗并默认选中当前商品最新未完结工单。无权限时按钮置灰并提示无处理权限。
工单数量角标展示当前商品未完结工单数量，红色气泡显示在工单处理按钮内。数量只统计未完结工单；工单完结后从数量中剔除。统计失败时不影响订单商品行展示，只隐藏角标。
工单状态标签在按钮下方展示当前商品最新工单状态，例如待处理、待客户确认、客户已回复、客户已确认、已完结。同一商品多工单时，以最新未完结工单作为状态摘要；全部完结时显示“暂无工单”或仅保留入口按钮。
内部备注保留订单商品原有内部备注入口。与工单记录相互独立，内部备注不自动生成工单。
特殊物品 / 黑名单 / 吐槽内部备注下方展示三个图标，分别代表特殊物品、黑名单、吐槽。仅作为商品辅助标识与快捷查看入口，不参与工单状态计算；图标无数据时可置灰。

(2) 工单编号与商品绑定

字段/控件名称功能展现描述业务规则与异常边界处理
工单编号工单编号只展示当前商品下的序号，例如 001、002、003。序号按商品维度递增，同一商品不可重复；不同商品可各自从 001 开始。
关联商品工单必须绑定订单商品行，后续处理均围绕该商品展开。商品从订单中删除、拆分或合并时，工单仍保留原关联商品快照，避免历史记录丢失。
创建时间工单创建时间在工单详情与我的待办中展示。订单详情商品行不展示创建时间，避免操作区拥挤。

③ 交互与跳转说明

  • 在订单详情点击“创建工单”后，页面以居中弹窗方式打开创建工单，不跳转页面。
  • 在订单详情点击“工单处理”后，页面以居中弹窗方式打开工单详情，并保留当前订单上下文。
  • 在商品没有工单时，首次创建成功后，商品行按钮从“创建工单”切换为“工单处理”，并显示红色数量角标。
  • 在待客户确认阶段，订单商品行仍可查看工单详情，但不可转交该工单。

④ 关联的隐藏后端模块及解决方案

关联模块影响点解决方案
订单商品行模块工单数量、状态与订单商品强绑定。工单主表保存订单号、商品ID、商品行ID和创建时商品快照；订单商品行查询时聚合未完结工单数量与最新状态。
工单编号服务工单编号改为商品维度序号。按商品ID生成递增序号，展示时只返回序号文本；后端仍保留内部唯一ID。
权限模块不同角色在订单详情可见入口不同。前端隐藏不可用动作，后端按当前登录人与工单当前处理人、发起人、业务角色二次校验。

2.0.1 创建工单弹窗

① 核心业务逻辑介绍

创建工单弹窗用于从订单商品行发起一个新的商品问题工单。创建时只能选择一个处理人，避免多人并行处理导致责任不清。问题内容使用纯文本加图片附件，不再使用富文本；图片附件分为实物图和链接图，均支持点击上传、拖拽上传、复制粘贴上传、预览大图和删除。

② 字段级别功能描述与异常流程

(1) 关联商品区

字段/控件名称功能展现描述业务规则与异常边界处理
商品图展示当前商品缩略图。图片加载失败时显示占位图，不阻断创建工单。
商品名称展示商品名称。名称过长时两行内展示，超出省略。
订单展示订单编号。点击订单号不在弹窗内跳转，避免创建流程中断。
商品ID展示商品ID，例如 D000005171。商品ID为工单与商品绑定的关键字段，不使用蓝色强调，和其他字段统一展示。
规格合并展示颜色与尺码，例如白色 / 3件套。颜色或尺码为空时展示“--”，不得影响工单创建。
MySKU / ASIN展示商品外部标识。缺失时展示“--”。
国家 / 业务 / 采购展示订单客户国家、业务员、采购人员。作为处理人选择与对客语言判断参考，不允许在弹窗中编辑。
历史工单展示当前商品规格在其他订单中的历史工单摘要。按商品名称、规格、颜色、尺码、属性等标准化后匹配；商品ID不同也可命中。创建工单弹窗内显示订单编号、客户编号、工单模板、创建时间和摘要，不展示状态；无历史工单时不展示该模块。

(2) 工单填写区

字段/控件名称功能展现描述业务规则与异常边界处理
处理人单选下拉框，只展示部门和人名，例如“采购 包瑞楠”“订单业务 唐芬芬”。必填。创建后工单进入该处理人的待办；后面的岗位说明不在下拉选项中展示，避免干扰识别。
工单模板下拉选择“自定义内容”“色差问题”“尺寸问题”等启用模板。默认“自定义内容”。选择模板后只回填中文模板内容；即使处理人是业务，也不得在创建阶段回填英文。
问题内容文本输入框，填写本次商品问题、处理诉求、需要确认内容。必填。输入和展示都必须保留换行，避免长文本挤成一段。
实物图上传质检、仓库拍摄的商品实物照片。非必填。支持点击、拖拽、粘贴上传；上传失败时保留已输入文字并提示重试。
链接图上传商品链接、商家页面、采购链接中的参考图片。非必填。与实物图独立存储和展示；不得混在同一组导致来源不清。

③ 交互与跳转说明

  • 选择工单模板后，问题内容自动替换为模板中文内容；用户可继续手动编辑。
  • 点击历史工单时，必须打开新的浏览器 Tab 页展示对应订单/工单详情，不关闭、不覆盖当前创建弹窗，方便先核对历史处理结果再决定是否继续创建。
  • 图片上传区域为一个整体组件，上传按钮与已上传图片同区展示；图片只展示缩略图，不额外显示“商品图”等默认文字。
  • 点击“提交并进入处理人待办”后，弹窗关闭，订单商品行工单按钮和角标立即刷新。
  • 提交失败时保持弹窗内容不清空，并在底部红色提示失败原因。

④ 关联的隐藏后端模块及解决方案

关联模块影响点解决方案
工单主表创建工单需要保存发起人、处理人、状态、关联商品快照、问题内容。初始状态为“待处理”，当前处理人为所选处理人，发起人为当前登录人。
附件服务图片来源分为实物图和链接图。附件表保存附件类型、排序、预览地址、原始文件信息；支持后续按类型展示。
模板服务模板回填中文内容，业务发送客户时再使用客户语言。创建工单只读取中文模板；客户语言内容在业务处理阶段读取或由业务编辑确认。
历史工单检索服务创建工单时需要快速定位历史工单。保存商品规格标准化字段，按规格Key跨订单查询历史工单；商品ID不同但规格一致时也返回。
人员权限服务创建工单处理人选择需要按部门角色过滤。质控部门只展示初检、组长、主管，其他质控角色不进入处理人下拉；该项为PRD规则，页面原型不单独新增说明模块。

2.0.2 工单详情弹窗

① 核心业务逻辑介绍

工单详情弹窗是工单处理的核心页面。页面分为三块：左侧当前商品工单列表，中间当前处理区，右侧历史记录区。员工处理工单时主要关注中间“当前处理”；历史信息按类别在右侧查看，减少从头翻阅所有记录的负担。

② 字段级别功能描述与异常流程

(1) 顶部关联商品信息区

字段/控件名称功能展现描述业务规则与异常边界处理
弹窗标题只展示“工单详情”。不再展示“商品问题工单”等副标题，保持页面简洁。
商品信息展示商品图、商品名称、订单、商品ID、规格、客户、国家、提出人、创建时间、当前处理人。字段重新排为两行展示；规格合并颜色和尺码。字段缺失时展示“--”。
关闭图标右上角仅保留 X 关闭弹窗。关闭弹窗不改变工单状态。

(2) 当前商品工单列表区

字段/控件名称功能展现描述业务规则与异常边界处理
当前商品工单标题后显示红色数量气泡，统计当前商品工单数。数量包含当前商品全部工单，已完结工单也保留在列表中用于查看。
新增工单按钮文案为“新增工单”。点击打开创建工单弹窗并带入当前商品。
工单卡片展示工单编号、状态、创建时间、处理人。卡片高度紧凑，编号过长时按序号展示；默认不高亮第一条，只有被选中时展示选中样式。
正在查看当前选中工单按钮显示“正在查看”，按钮颜色采用选中态。切换工单后，中间当前处理区和右侧历史记录同步切换。

(3) 当前处理区

状态当前处理展示可操作动作业务规则与异常边界处理
待处理-非业务处理人展示“本次处理意见”和图片附件。保存草稿、提交意见、转交、关闭工单、确认完结。“提交意见”将意见同步给业务处理；图片非必填。只有发起人可看到“确认完结”；其他人只能处理、转交或关闭。
待处理-业务处理人展示“发送客户内容”，内容默认可根据模板填充客户语言；图片分实物图和链接图。保存草稿、发送客户确认、转交、关闭工单、确认完结。业务可发送客户确认，也可转交其他处理人；发送客户时文字必填，图片非必填。
待客户确认展示等待客户确认内容，包括问题内容、实物图、链接图。关闭工单、确认完结。客户确认阶段不可转交；若客户迟迟未回复，本期不做催确认功能。
客户已回复展示客户选择结果、客户原文、客户内容翻译、默认同步人员。继续回复客户、确认同步、转交内部处理、关闭工单、确认完结。“确认同步”只同步给提出人和相关处理人，状态变为客户已确认，不直接完结。
客户已确认展示已同步客户信息和内部待确认结果。关闭工单、确认完结。发起人可确认完结；非发起人只能查看或继续内部处理。
已完结展示最终处理意见、图片附件和完结时间。只可查看。所有操作按钮隐藏，只保留右上角关闭弹窗。旧数据中的“已关闭”统一迁移展示为“已完结”。

(4) 图片附件区

字段/控件名称功能展现描述业务规则与异常边界处理
实物图展示或上传实物图。业务发送客户时可勾选是否随内容发送。非必填。勾选说明统一为“勾选后随内容发送给客户”。
链接图展示或上传链接图。业务发送客户时可勾选是否随内容发送。非必填。与实物图使用相同提示文案，上传后支持预览大图和删除。
图片预览点击缩略图查看大图。大图预览不改变表单内容；删除需二次确认或明显删除入口。

(5) 历史记录区

字段/控件名称功能展现描述业务规则与异常边界处理
全部默认展示工单内容、内部处理、客户沟通三类记录汇总，按时间倒序排列。流转记录不进入“全部”，避免操作日志干扰业务内容。不同类型用标签和轻微背景区分。
工单内容展示创建时的问题内容、模板标识、实物图、链接图。模板只展示名称，例如“色差问题”；自定义创建展示“自定义内容”。
内部处理展示处理人提交意见、转交意见、关闭意见及图片。支持从“上一环节意见”的查看详情高亮定位到对应记录。
客户沟通展示业务发送和客户回复。业务消息靠右绿色，客户消息靠左蓝色；同一条消息不得重复展示。
历史工单展示当前商品规格在不同订单中的历史工单。显示订单编号、客户编号、工单模板、创建时间、状态和摘要；工单模板以独立背景标签展示，例如“尺寸问题”，不展示“模板：”前缀；点击“查看”必须打开新的浏览器 Tab 页展示对应订单/工单详情，不覆盖当前工单详情弹窗。
流转记录单独展示状态变更、处理人变更、转交路径。按时间倒序展示，不进入“全部”聚合。

③ 交互与跳转说明

  • 左侧切换工单时，中间当前处理区、底部操作按钮、右侧历史记录同步刷新。
  • 当前处理区固定为处理主区域，员工在任意滚动位置都能明确本次需要填写的内容。
  • 点击“查看详情”时，右侧历史记录自动切换到对应分类，并高亮当前关联记录。
  • 点击“关闭工单”不是直接关闭，需要填写本次处理意见和图片附件；确认后同步给提出人和对应处理人。
  • 点击“确认完结”只有发起人可执行；例如发起人为质检主管李倩，当前登录人为李倩时必须展示确认完结入口。

④ 关联的隐藏后端模块及解决方案

关联模块影响点解决方案
工单状态机状态需覆盖待处理、待客户确认、客户已回复、客户已确认、已完结。后端统一状态流转，不允许前端自行改状态；提交时校验当前状态版本。
权限服务业务可发送客户确认，发起人可完结，当前处理人可处理或转交。每个动作后端做角色与关系校验，避免只靠前端隐藏按钮。
历史记录服务右侧历史记录需要按类型聚合且避免重复。内部处理、客户沟通、流转记录分表或分类型存储；聚合时按唯一记录ID去重。
同步待办服务提交意见、客户同步、关闭工单都可能生成相关人员待办。同步对象由动作规则计算，不由前端手填；重复同步时合并为最新待办。
历史工单服务工单详情需要跨订单查看历史工单。根据规格Key查询有权限范围内的历史工单，结果按创建时间倒序展示；排除当前工单避免重复。

4. 其他关联模块 (连带核心后端系统影响与阻击规范)

前端表现 / 用户侧操作潜在漏洞与防线断层风险点核心关联的后端微服务及硬性加固要求
订单详情和我的待办都可以打开同一工单详情弹窗。两个入口同时处理同一工单，可能出现状态覆盖或重复提交。工单提交接口必须校验状态版本号；状态已变化时提示刷新，不允许覆盖最新处理结果。
创建工单只选择一个处理人。如果后续仍保留多人处理旧逻辑，会造成待办重复和责任不清。工单主流程只保存一个当前处理人；协同信息通过转交记录或同步对象记录，不作为当前处理人。
只有业务可发送客户确认。非业务角色误发客户内容，可能导致翻译错误或客户沟通口径不一致。对客发送接口必须校验业务角色或订单业务负责人身份。
发起人才能确认完结。处理人提前完结会导致提出人未确认结果。完结接口必须校验发起人身份；非发起人只允许关闭、转交或提交处理意见。
客户已回复后点击确认同步，不直接完结。客户信息未同步给提出人和处理人就结束工单，内部无法追溯。确认同步生成同步记录和相关人员待办，状态变更为客户已确认。
关闭工单需要填写本次处理意见和图片附件。直接关闭会丢失关闭依据。关闭接口复用处理意见结构，保存文本、实物图、链接图，并同步给相关人员。
图片附件支持点击、拖拽、粘贴上传。不同上传入口可能产生重复附件或附件类型丢失。附件服务保存来源类型、附件分组、排序、去重标识和预览地址。
历史记录按全部、工单内容、内部处理、客户沟通、流转记录查看。全部列表如果混入流转日志会干扰业务阅读，若客户沟通重复会造成误判。聚合接口按记录类型返回；全部只合并工单内容、内部处理、客户沟通，并按唯一ID去重。
我的待办增加“全部工单”模式。若不做权限控制，普通员工可能看到无权限订单的工单。全部工单查询必须走数据权限服务，只返回当前用户组织、角色、订单权限允许查看的工单。
我的待办按创建时间段筛选。时间字段未索引会造成列表查询慢，结束日期边界处理错误会漏数据。工单主表创建时间需建立索引；结束日期按当天 23:59:59 计算。
创建工单和详情可查看历史工单。商品ID不同但规格相同，如果只按商品ID查会漏掉历史问题；如果规格匹配过宽会误召回无关商品。建立规格标准化Key，至少组合商品名称、颜色、尺码、属性；查询结果按权限过滤并按创建时间倒序。
创建和转交选择处理人时过滤质控角色。质控部门角色过多会导致误派，处理链路变长。质控部门只返回初检、组长、主管三个角色，其余质控角色不进入处理人下拉。
工单编号只展示 001、002、003。仅靠序号无法全局唯一，开发若误用序号作为主键会产生冲突。展示编号与内部ID分离；所有接口使用内部唯一ID，序号只作为商品维度展示字段。
工单模板支持多语言。模板停用、删除或语言缺失会影响历史工单和对客发送。历史工单保存内容快照；删除模板不删除历史引用；发送客户前校验目标语言内容是否存在。
