## 一、审计结论摘要

| 维度 | 审计结论 | 影响 |
| --- | --- | --- |
| 状态机 | PRD 已定义 5 个状态，但“关闭工单”和“确认完结”的边界仍存在语义混用。 | 影响完结、关闭、待办关闭和历史记录断言。 |
| 权限 | PRD 要求业务、发起人、当前处理人、全部工单权限均需后端校验。原型仅能体现前端按钮显隐。 | 需要真实接口和不同权限账号验证，不能只凭原型通过。 |
| 原型一致性 | 工单模板目标语言缺失、客户选择空值、完结权限等存在 PRD 与原型脚本差异。 | 需要产品/开发确认以 PRD 还是原型为准。 |
| 历史工单 | PRD 要求同规格不同商品ID召回，但规格 Key、匹配阈值和权限过滤方式未明确。 | 影响历史召回误匹配、漏匹配和越权测试数据准备。 |
| 客户确认回传 | 客户确认页不重做，但回传枚举、唯一确认ID、重复回调幂等未完全定义。 | 影响客户已回复、继续沟通和同步待办断言。 |
| 附件 | 支持点击、拖拽、粘贴、预览、删除，但格式、大小、数量、去重、失败码未定义。 | 影响上传异常和附件分组测试可执行性。 |

## 二、Blocking 问题

| 问题ID | 问题 | 证据来源 | 风险 | 测试处理 |
| --- | --- | --- | --- | --- |
| BQ-001 | “关闭工单”和“确认完结”是否是两个不同动作？关闭后是否直接进入已完结，还是需要发起人再次确认？ | PRD 2.0.2 写“关闭工单、确认完结”并列；PRD 后端风险又写“关闭接口复用处理意见结构”；原型按钮实际为“确认完结”。 | 若边界不清，会把处理人关闭误测为发起人完结，漏掉提出人最终确认。 | 用例拆成“关闭依据保存”和“发起人最终完结”两类；执行前需确认状态流。 |
| BQ-002 | 后端是否提供工单状态版本号 / ETag / updated_at 用于并发提交校验？接口字段名是什么？ | PRD 2.0.2、4 明确要求状态版本；原型为 localStorage 演示，无接口版本。 | 两入口同时处理会覆盖状态、重复发送客户确认或重复完结。 | 并发用例标 Critical；无版本字段时记录阻塞缺陷。 |
| BQ-003 | 全部工单模式的数据权限边界按组织、角色、订单归属、客户归属还是业务归属计算？ | PRD 2.1 只写“权限范围内所有订单工单”；功能清单 RULE-011 未定义权限粒度。 | 普通员工可能通过全部工单或历史工单看到无权限订单。 | 需要普通账号、同组织账号、跨组织账号、全量权限账号对照。 |
| BQ-004 | 历史工单规格 Key 的标准字段、标准化规则和匹配阈值是什么？商品名称、颜色、尺码、属性、SKU、MySKU 是否都参与？ | PRD 2.0.1 / 4 写“商品名称、规格、颜色、尺码、属性等标准化”。 | 只按商品ID会漏召回；按名称/颜色过宽会误召回；权限过滤也可能绕过。 | 历史召回用例必须准备同ID、不同ID同规格、近似规格、无权限订单四组数据。 |
| BQ-005 | 对客发送时目标语言模板缺失，是阻止发送并提示补充，还是允许回退中文？ | PRD 2.2 写“缺失时提示补充，不自动发送空内容”；原型模板预览文案写“该语言暂未填写，使用时会回退中文内容”。 | 可能向海外客户发送错误语言内容，影响客户沟通。 | 用例以 PRD 为准：不得静默回退；若实现回退中文需提缺陷或产品确认变更。 |

## 三、High 问题

| 问题ID | 问题 | 证据来源 | 风险 | 测试处理 |
| --- | --- | --- | --- | --- |
| HQ-001 | 客户选择结果枚举标准值是什么？是否包含“可以接受 / 不接受退货 / 不接受换货 / 其他”？ | PRD 写“可接受、不接受、退货等”；原型为“可以接受、不接受退货、不接受换货”。 | 枚举不一致会导致客户已回复状态和后续处理分支错误。 | 客户回传用例覆盖三类原型枚举，并保留枚举待确认。 |
| HQ-002 | 客户选择结果为空如何产生？现有原型选择框默认“可以接受”，无法模拟空选择。 | PRD 3.1 要求空选择不得进入客户已回复；原型默认值不为空。 | 空值校验可能没有后端兜底。 | 通过接口/回调模拟空 choice；UI 无法置空不算覆盖。 |
| HQ-003 | 发起人确认完结权限是否只看登录人，还是可根据“发起人=当前处理人”放行？ | PRD 要求只有发起人；原型 `canFinishTicket` 同时判断 proposer 与 currentHandler 同名。 | 非发起人可能被误判可完结。 | 用例增加“同名/同部门/当前处理人但非发起人”反向账号。 |
| HQ-004 | 提交意见同步给哪个业务：订单业务、商品业务、客户经理，还是工单当前业务处理人？ | PRD 写同步给业务处理；问题单旧 Q-003 未确认。 | 待办归属错误会导致业务漏处理。 | 用例要求核对业务待办收件人和同步记录，不只看状态。 |
| HQ-005 | 客户已确认后默认同步对象是否包含提出人、当前处理人、历史处理人、业务？ | PRD 写提出人和相关处理人；原型通过 records 反推最近一个非业务处理人。 | 同步遗漏会让相关人员看不到客户结论。 | 用例拆分单处理人、多次转交、业务继续沟通三种同步对象。 |
| HQ-006 | 工单编号商品维度序号在商品删除、拆分、合并后如何保持不可重复？ | PRD 2.0 要求展示序号与内部ID分离，商品快照保留。 | 接口若用展示序号做主键，会串单或误操作。 | 用例验证接口使用内部ID，展示序号仅展示。 |
| HQ-007 | 模板删除是否允许物理删除？被历史工单引用后是否只能停用/软删？ | PRD 2.2 写删除不影响历史；功能清单写删除从后续可选移除。 | 物理删除可能导致历史模板名/内容丢失。 | 用例以历史快照不丢失为准；若物理删除导致历史丢失提缺陷。 |
| HQ-008 | 附件格式、大小、数量、重复粘贴去重和失败码是什么？ | PRD 只定义上传方式和分组。 | 无法精确验证上传失败、去重和边界限制。 | 执行前向后端/运维确认；用例保留“超限/重复/失败恢复”场景。 |
| HQ-009 | 操作日志是否记录敏感动作：发送客户、客户回传、确认同步、转交、删除附件、关闭/完结？ | PRD 2.0.2 要流转记录，未明确定审计字段。 | 关键动作无法追溯，出错无法定责。 | 用例增加日志审计断言： actor、action、target、time、before/after 状态。 |
| HQ-010 | 客户确认链接或确认ID是否一次性、是否过期、重复回调是否幂等？ | PRD 3.1 写唯一确认链接或确认ID，未定义有效期和重复提交。 | 重复回调可能反复生成客户已回复记录或覆盖原文。 | 用例增加重复回调、错误ID、已完结后回调场景。 |

## 四、原型与需求差异记录

| 差异ID | PRD 规则 | 原型/脚本表现 | 风险判断 |
| --- | --- | --- | --- |
| DIFF-001 | 目标语言模板缺失时提示补充，不自动发送空内容。 | `工单模板.html` 展示“该语言暂未填写，使用时会回退中文内容”；`templateText` 返回目标语言或中文。 | 按 PRD 设计测试，原型回退中文应作为待确认/缺陷。 |
| DIFF-002 | 客户选择结果为空不得进入客户已回复。 | `replyForm.choice` 默认“可以接受”；页面选择框无空选项。 | 必须通过接口模拟空值，不能只测 UI。 |
| DIFF-003 | 只有发起人可确认完结。 | `canFinishTicket` 同时允许 proposer 与 currentHandler 同名时通过。 | 需用真实账号验证后端；前端条件不可作为合格依据。 |
| DIFF-004 | 工单详情状态机包含客户已确认。 | `flowSteps` 未单独显示客户已确认步骤，`stateMeta` 有客户已确认。 | UI 进度条和状态标签可能不一致，需专项验证。 |
| DIFF-005 | 历史工单需按权限过滤。 | 原型 `sameSpecTickets` 仅在本地 tickets 中按规格过滤，不能证明权限过滤。 | 必须接口验证无权限订单不返回。 |

## 五、执行门禁

- Blocking 问题未确认时，相关用例可以进入“设计完成 / 执行阻塞”状态，但不能作为通过结论。
- 权限、并发、历史工单、客户回传、模板语言缺失均必须验证后端接口；仅前端按钮显隐不算通过。
- 若产品明确以原型为准，需同步更新 PRD / 功能清单，再回写测试点和用例版本说明。
