# 会员体系优化：第二轮审计确认纪要

**文档日期**：2026-04-02
**背景**：基于 `superpowers.md` 的新增规约 Rule 5 (身份-计费强锚定) 与 Rule 6 (国家最高优先级)，进行的第二轮深度底层架构验证与业务规则确认。

---

## 一、 Rule 5 审计确认 (底层计费与精度)

### 1. 币种精度与外源汇率安全点
*   **审计场景**：JPY、USD 存储展现精度差异，与汇率转换的安全规则。
*   **业务确认原话**：「汇率问题，每天公司内部接口会调用一次外部汇率接口，取值在小数点后两位，公司会根据当日的汇率**再加一点确保安全**。」
*   **最终落地方案**：系统具有每日刷新的外源汇率机制。结算金额的转换将使用这套**“基于当日外源数据 + 平台安全溢价”**计算出的快照汇率。

### 2. 多节点闭环计费底座 (Absolute Consistency)
*   **审计场景**：加购与选配各阶段，前后端防止串价或篡改的强一致性校验底座。
*   **业务确认原话**：「涉及到业务逻辑，在用户加购物车后，下一步是选择附加项，然后再下单，**中间都是按照chn结算，直到下单这一步，会根据用户当地的币种汇率进行换算**，引导客户充值。」
*   **最终落地方案**：系统底层采用了极为优秀的**人民币 (CNY) 中轴计费架构**。即：无论用户身处何国、身处哪个业务环节（加购、选配服务），内部盘算的金额一律以基础货币 CNY 进行累加求和，直至收银台渲染的最后关口，才使用上述“带安全点数的快照汇率”换算为当地流转货币（JPY/USD）。**此架构从根本上杜绝了多节点流转中的汇兑精度损失与前端越权传参风险。**

## 二、 Rule 6 审计确认 (越界防线与环境清洗)

### 3. API 越权拦截与强鉴权 (Domain Isolation)
*   **审计场景**：利用工具抓包强行篡改参数（如 `country=KR`），企图以日本账号套用韩国站特权。
*   **业务确认原话**：「问题3，需要进行鉴权，**用户和国家信息是绑定的**。」
*   **最终落地方案**：底层网关已实现**强鉴权绑定隔离**。一旦请求头的 Token/签名国别属性与传入参数（如企图跨国操作）发生错配，系统直接抛出越权拦截。

### 4. 上下文串血清洗 (Session Reset)
*   **审计场景**：同设备下完成“A国账号退出 -> 登录B国账号”，因旧缓存未清空导致遗留的“大客专属优惠快照”或“A国专属服务项”污染B国用户。
*   **业务确认原话**：「选择退出后重新登录，**加载的内容是重新登录客户的信息**。」
*   **最终落地方案**：客户端与前端架构明确遵循了“随需随取”的重置加载机制。在鉴权 Token 更换后的首次重载时，所有跟“身份”、“权益”、“历史价格”相关的 Context 会被底层框架强制清空并重新灌入，**免疫缓存污染**。
