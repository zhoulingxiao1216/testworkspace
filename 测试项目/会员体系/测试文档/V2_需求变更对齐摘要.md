# 会员体系优化 V2 需求变更对齐摘要 
**引擎构建日期**：2026-04-14
**当前处于引擎状态**：模式 C【增量更新】

> **摘要声明**：本核心概要提炼自 `global-workspace/docs/pm/黑白名单及采购账号/会员体系优化PRD.md`，旨在确立 V2 增量执行周期的核心战略焦点，彻底消除重提与信息差。

---

### 1. 购物车/结算台的“强身份防线”（核权提单阻击）
* **修改前**：用户加入购物车及结算通常毫无身份阻碍。
* **修改后**：【普通用户】不仅被物理限流（APP端锁形图标置灰提交按钮），底层结算 API (`/api/order/checkout`) 强开启硬核拦截，越权直击将返回 ` Http 403` 异常阻断流。提单前提变成了：**必须持有充值有效的会员等级**。

### 2. 千人千面算价：爆炸级“复合计费模型”重构
* **修改前**：业务服务（正品数、贴标等）按最极简的底量“一口价”计费。
* **修改后**：引入了 **多维会员身份矩阵定价**。根据[开启N个国家的X级会员]，表单会强制裂解为数个独立平行配置框；且底层大盘直接上马了 6 大黑盒算费逻辑：普通、阶梯、起订量、按套、按时、相谈。阶梯价在此次更是直接追加了死控的防倒挂闭环审计墙。

### 3. 大客专属“红色警戒”强制告警法 (UID 定制价管控)
* **新增逻辑**：高净值的特定 UID 被允许绕过公盘大盘拿“专属客户折扣价”。
* **修改后底线**：即使定制极其过分，也**绝对不可以跌破内抛成本红线**；在终端展示与收银闭环，只要开启大客折扣的账号，其文本必须渲染在视觉上**极度刺眼的【纯红色】**，搭配灰度删除线的原公盘价，强推财务透明审计工作。

### 4. 核心补漏：历史对账 JSON 快照静态化定格 
* **重大架构修改**：以往由于公盘调价曾引发了“连环财务爆炸（查历史旧账发现单价随环境涨了）”。
* **修复结论**：任何订单与报价单到达【成交/定案】时间点后，该业务关联的当前这组算费参数将被序列化，硬塞进 `snapshot_data JSON` 中变成只读的冷冻库存档案，与大盘 2.3.1 系统产生永久性断联。

### 5. 入金与跨国审核：汇率汇兑结算锚点提档
* **规则修改**：汇率转换的判定时针从宽泛审核期强行往前钉死，变更为**【抓取用户前台点击提交/下定申请的那一秒的有效日汇率快照】**。对于半夜发票，次日财务才人工放款通过的隔夜流水账，坚决按昨日旧额度入账，杜绝大起大落下的汇率差额羊毛套路！

### 6. 逆向财务深水区：超长极大值残值的特殊退库 
* **新增逻辑**：当一个土豪用户的“一般会员”买到了 3650 天这种天际值，又试图在某天升级极短（如 1 个月期）顶配 VIP卡时，超大额度差将会往玩家 B2B Balance（余额库）产生 `1:1 的直接逆流入账退款`机制。防吞没且有极大潜在违规提取隐患（引擎提示：已让业务人员在线下财务审核侧单拉了预警拦截网）。
