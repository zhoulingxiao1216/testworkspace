1. 背景与目标

用户端 UI 优化不是单一页面改样式，而是对用户中心多个业务示例进行统一改版。每个示例都代表一个明确的优化场景，需要分别沉淀为产品需求，便于设计、前端和测试逐项落地。

所有章节和新增内容需与原有页面保持版心一致，版心范围为 1200px-1700px；页面宽度小于 1350px 时，表格出现左右滚动条，不压缩表格。注意：只对页面按钮、页面文字、鼠标悬浮、鼠标选中、点击弹框、抽屉进行统一，不改变业务逻辑。

产品目标

  1. 把设计页面中的每个示例拆成独立优化点。
  2. 每个优化点明确页面范围、优化目标和验收标准。
  3. 统一用户端列表、卡片、图片、字段、操作、详情跳转与多语言规则。
  4. 避免只输出通用规范，确保每个示例都能进入排期和开发验收。

体验目标

  1. 用户在不同业务页面看到一致的表格、按钮、状态和图片交互。
  2. 长文本、长编号、多语言文案不造成页面变形。
  3. 主操作、次操作、轻操作和详情入口层级清晰。
  4. 首页入口、列表状态、详情页之间跳转关系一致。

3. 优化点01：菜单栏示例

来源示例：菜单栏示例页面.html

来源示例：客户端UI设计规范.html

来源示例：客户端UI交互规范.html

优化目标

  1. 统一用户中心左侧菜单栏的文字展示、图标风格、选中状态和展开/收起交互。
  2. 解决菜单名称因列宽不足显示省略号的问题，确保一级菜单、二级菜单均可完整阅读。
  3. 在中文、英文、日文、韩文、繁体中文环境下，菜单栏不因文案长度造成布局错位。

优化要求

  1. 菜单栏宽度需满足现有菜单名称完整展示，禁止出现 B2B代行... 等省略号截断。
  2. 菜单图标沿用原系统线性图标，不新增、不替换为不同风格图标；图标尺寸、线宽和颜色保持一致。
  3. 一级菜单与二级菜单之间保持清晰层级，展开箭头、缩进、选中背景和文字权重需统一。
  4. 当前页面所属一级菜单和二级菜单需要同时呈现选中态，避免用户无法判断所在位置。

交互规则

交互项规则
展开/收起有子菜单的菜单项点击后切换展开和收起状态，箭头方向同步变化。
选中态点击一级菜单或二级菜单后，对应菜单项显示统一浅灰蓝背景和深蓝文字。
文字展示菜单文字允许自然换行完整展示，不得使用省略号；换行后不遮挡图标和箭头。
多语言英文菜单如 B2B Control、Optional Services 需完整展示，不挤压图标、不超出菜单栏。

验收标准

  • 打开菜单栏示例页面，左侧菜单中的“B2B代行管理”“发货配送”“推荐商品”“账户设置”等均完整显示。
  • 菜单栏中不出现省略号截断，不出现文字遮挡、图标错位或箭头丢失。
  • 展开和收起菜单时，二级菜单展示稳定，页面主体内容不抖动。
  • 菜单图标与现有系统风格一致，不出现不同线宽、不同视觉语言的图标混用。
  • 切换到英文菜单时，菜单文字仍完整展示，长文案可换行且不影响可读性。

4. 优化点02：WhatsApp咨询悬浮入口

来源示例：WhatsApp咨询悬浮入口示例.html

来源示例：客户端UI设计规范.html

来源示例：客户端UI交互规范.html

入口结构

  1. 页面右侧保留独立圆形 WhatsApp 咨询吸附入口，位于展开菜单和返回顶部入口上方，并与侧边入口紧凑排列。
  2. 默认状态使用白色圆形底、深蓝色耳机图标和轻阴影样式，尺寸与菜单、返回顶部按钮保持一致。
  3. 鼠标滑过或键盘聚焦 WhatsApp 图标时，图标切换为红色选中态，并在按钮左侧展开咨询卡片。
  4. 咨询卡片包含「售前咨询」标题、官方 WhatsApp 二维码、提示文案和电话入口，右侧箭头指向 WhatsApp 图标。

交互规则

  1. 鼠标移出 WhatsApp 图标后收起二维码咨询卡片；键盘失焦后同样收起。
  2. 展开时需要设置 aria-expanded="true"，收起时恢复为 false。
  3. 二维码卡片贴近 WhatsApp 图标左侧展示，不得遮挡主内容关键操作，不得与返回顶部、展开菜单等侧边入口重叠。
  4. 电话入口使用可点击链接，移动端可唤起拨号能力，桌面端保持可复制和可识别。

验收标准

  • 打开示例页时，右侧默认展示独立圆形 WhatsApp 图标，未 hover 时不展示二维码卡片。
  • 鼠标 hover 或键盘 focus 后，WhatsApp 图标变为红色选中态并显示二维码咨询卡片。
  • 鼠标移出或失焦后卡片自动收起，页面不会出现残留遮挡。
  • WhatsApp、展开菜单、返回顶部三个圆形按钮上下排列紧凑，视觉间距保持一致。
  • 二维码、提示文案和电话入口清晰可读，1366px 桌面宽度下不超出视口。
  • 该悬浮入口在首页、列表页、详情页等用户端页面表现一致。

5. 优化点03：商品详情页选中效果

参考页面：商品详情页选中效果示例-2.html

优化目标

  1. 让用户清楚识别当前已选择的颜色、尺码和 SKU 数量。
  2. 选中态不能过度抢眼，避免干扰商品主信息。
  3. 数量变化后，底部金额和已选件数实时联动。

优化要求

  1. 颜色选中使用柔和描边、浅红底和右下角小标识。
  2. 未选中项保持白底灰线，不使用大面积填充。
  3. 有购买数量的 SKU 行整行轻量高亮。
  4. 底部固定展示已选种类、总件数、商品金额和“加入购物车”。

验收标准

选中态颜色、尺码、SKU 数量选中后均有明确视觉反馈。
汇总联动用户增减数量后，底部总件数和商品金额实时更新。
布局稳定长规格、多个 SKU、不同图片尺寸不挤压底部主操作。

7. 优化点05：报价单页面

来源示例：报价单页面示例.html

页面目标

  1. 让用户在报价单列表中快速判断报价类型、审核状态、支付状态、费用构成和付款截止时间。
  2. 支持用户按报价单编号、支付状态、国际物流、下单日期、用户订单号进行筛选，筛选区保持单行高密度布局。
  3. 支持对待付款报价单进行批量支付或从单条报价单进入收银台，同时保留单条报价单详情入口。

数据范围

  1. 列表默认展示 20 条报价单数据，底部分页显示 共 20 条、20条/页。
  2. 状态 Tabs 展示 全部(20)、自助报价单(12)、审核中(4)、审核通过(8)、已取消(3)、已驳回(4)。
  3. 报价单类型仅允许展示 自动报价单、委托负责人报价 两类，由数据自动生成，列表中任选其一展示。

列表字段与展示规则

模块需求说明
