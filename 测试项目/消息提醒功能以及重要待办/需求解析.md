# 消息提醒功能以及重要待办 - 需求解析

## 一、需求来源

- 主需求来源：`消息提醒功能以及重要待办.docx`
- 本测试设计仅基于该 DOCX 正文进行解析，不混入其他项目需求。
- 项目边界：消息提醒功能以及重要待办，非“订单详情页优化”项目。

## 二、背景与目标

系统需要在有新订单、新发货单、新客户待处理、重要待办等场景下，通过分类标题右侧气泡、站内信或短信等形式提醒相关人员，降低待审核、待匹配、待处理事项遗漏风险。

预期目标：

- 对应模块添加角标或站内信提醒。
- 告知对应模块有新的订单或待办产生。
- 重要待办模块统一展示多个子模块的待办总数。
- 右侧导航展示消息、待办、订单相关数量。

## 三、范围

### 3.1 确定需求范围

1. 通用气泡规则：
   - 一级、二级分类标题右侧均可单独展示气泡。
   - 折叠、展开状态下气泡持续展示，不随分类折叠隐藏。
   - 一级分类气泡数量为对应二级分类待办数总和。
   - 二级分类气泡数量为该分类下目标待办数量。
   - 数字小于等于 99 展示实际数字，大于 99 展示 `99+`。

2. 管理系统 - 客户管理：
   - 一级分类“客户管理”展示所有二级分类待办数总和。
   - 二级分类“客户信息”展示待匹配业务采购客户经理的客户数量。
   - 客户未匹配客户经理时气泡持续展示。
   - 匹配完成后 1 秒内气泡自动消失。
   - 匹配后未消失时，每 5 秒轮询校验状态，连续 3 次仍异常时自动刷新页面并更新气泡。

3. B2B 系统：
   - 一级分类“订单管理”展示“报价单”与“代购订单”待审核数量总和。
   - 二级分类“报价单”展示待审核报价单数量。
   - 二级分类“代购订单”展示待审核代购订单数量。
   - 一级分类“发货配送”展示所有二级分类待办数量总和。
   - 二级分类“发货单列表”展示待审核发货单数量。
   - 待审核数为 0 时气泡隐藏。
   - 新增待审核订单、发货单时，二级气泡实时加 1，一级气泡同步更新。
   - 审核完成后气泡实时递减，为 0 时立即隐藏。

4. 气泡交互：
   - 点击一级分类气泡，自动展开该分类下所有二级分类。
   - 点击二级分类气泡，直接跳转至该分类的待办列表页。
   - 点击“重要待办”气泡，自动展开“重要待办”模块。

5. 异常处理：
   - 二级分类数据加载失败时，一级气泡暂不计入该二级分类数量，加载完成后自动补全总和。
   - 待办数量出现负数时，系统自动修正为 0，气泡数字显示 0 或隐藏。
   - 页面切换后自动拉取目标模块待办数据，2 秒内渲染气泡。
   - 多语言标题过长时，气泡保持与标题右边缘 5px 间距，不被标题遮挡。

6. 短信提醒：
   - 用户注册成功后，相关短信提醒到相关人员。
   - 相关人员可以进行配置选择。
   - 允许通知多人。

7. 重要待办：
   - “重要待办”模块标题右侧展示气泡。
   - 折叠、展开状态均持续展示。
   - 气泡数字为“问题确认”“测量 / 报告”“系统通知”3 个子模块待办数量之和。
   - 单个子模块数据未加载完成时，暂不计入总和，加载完成后自动更新。
   - 总和小于等于 99 展示实际数字，大于 99 展示 `99+`。
   - 展开状态气泡位于“重要待办”标题右侧，与标题文字右对齐。
   - 折叠状态气泡仍保留在折叠后的 `Important...` 标题右侧。
   - 子模块新增待办后气泡实时加 1，无延迟。
   - 子模块完成待办后气泡实时递减。
   - 页面刷新或重新登录后，页面加载完成 1 秒内渲染气泡数字。
   - 子模块数据加载失败时，该子模块不计入气泡数字，气泡旁临时展示 `?` 标识，悬浮提示“部分待办数据加载中，请稍后刷新”。
   - 气泡未实时更新时，页面每 30 秒自动拉取一次待办数据。
   - 多语言切换后自动重定位气泡。
   - 涉及多语言时在 B2B 多语言中配置。

8. 右侧导航：
   - 消息：展示未读消息条数。
   - 待办：展示未处理的全部条数。
   - 订单：展示全部的订单条数。

### 3.2 暂缓项

以下内容在 DOCX 中有方向性描述，但缺少可执行规则，建议暂不按确定需求验收：

- 站内信提醒的触发规则、展示入口、已读未读状态、消息内容模板。
- “对应模块添加角标或者站内信提醒”中“或者”的最终实现方式。
- 短信发送失败、重试、退订、发送频控、短信内容模板。
- “待办数量出现负数”时到底展示 0 还是直接隐藏，DOCX 写法为“显示 0（或隐藏）”。
- 重要待办多语言截断中的 `X` 个字符未明确。
- 右侧导航“订单：展示全部的订单条数”的订单范围、系统范围、状态范围。

### 3.3 需产品确认项

1. 气泡为 0 时：
   - B2B 待审核明确为隐藏。
   - 负数修正为 0 后是展示 0 还是隐藏，需要统一口径。

2. 实时更新定义：
   - B2B 订单、发货单“实时”是否有明确 SLA，例如 1 秒内、2 秒内或 WebSocket 即时更新。

3. 客户管理数据范围：
   - “待匹配业务采购客户经理的客户数量”的筛选条件是否包含禁用客户、审核中客户、历史客户。

4. 短信提醒：
   - “相关人员”的角色范围。
   - 是否按系统、组织、部门、客户类型配置通知人。
   - 多人通知是否需要去重。

5. 重要待办：
   - “问题确认”“测量 / 报告”“系统通知”三个子模块的待办定义和完成条件。
   - `?` 标识样式、展示时长、是否影响气泡点击。

6. 右侧导航：
   - 消息、待办、订单数量是否也遵循 `99+` 规则。
   - 数据刷新频率、点击跳转目标、权限过滤规则。

## 四、影响模块

- 管理系统：客户管理、客户信息、客户经理匹配。
- B2B 系统：订单管理、报价单、代购订单、发货配送、发货单列表、多语言配置。
- 重要待办：问题确认、测量 / 报告、系统通知。
- 全局导航：右侧导航消息、待办、订单计数。
- 通知配置：短信通知人员配置，多人通知。
- 数据同步与异常恢复：轮询、页面刷新、页面切换重新拉取、加载失败兜底。

## 五、核心业务规则

| 规则编号 | 规则名称 | 规则说明 |
| --- | --- | --- |
| BR-001 | 一级气泡汇总 | 一级分类气泡等于已加载二级分类待办数量总和 |
| BR-002 | 二级气泡计数 | 二级分类气泡等于该分类目标待办数量 |
| BR-003 | 数字上限 | 数量大于 99 展示 `99+` |
| BR-004 | 折叠可见 | 折叠和展开状态均展示气泡 |
| BR-005 | 加载失败不计入 | 子分类或子模块加载失败时暂不计入总数 |
| BR-006 | 数据补全 | 数据加载完成后自动补全总和 |
| BR-007 | 客户匹配消失 | 客户匹配客户经理后 1 秒内气泡消失 |
| BR-008 | 客户异常轮询 | 客户气泡未消失时每 5 秒校验，3 次仍异常后刷新 |
| BR-009 | 审核递增递减 | 待审核新增加 1，审核完成递减，为 0 隐藏 |
| BR-010 | 页面切换同步 | 页面切换后 2 秒内拉取并渲染目标模块气泡 |
| BR-011 | 重要待办汇总 | 重要待办为 3 个子模块待办数之和 |
| BR-012 | 重要待办加载 | 刷新或重新登录后 1 秒内渲染重要待办气泡 |
| BR-013 | 重要待办异常提示 | 子模块加载失败时展示已加载总和与 `?` 标识 |
| BR-014 | 多语言避让 | 标题过长或语言切换后气泡不遮挡、不错位 |
| BR-015 | 短信多人通知 | 用户注册成功后可向配置的多名相关人员发送短信 |
