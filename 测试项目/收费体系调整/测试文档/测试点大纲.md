# 收费体系调整 测试点大纲

## 背景说明

本需求围绕 Hubbuyer 收费体系调整，核心目标是统一前后台商品单价口径、强化报价单快照、明确代采手续费与平台服务费边界，并让后台订单清算形成可审计的计算、确认和记录闭环。测试设计按 Agent1 规范执行，优先覆盖金额、快照、权限、导出、异常降级和多语言配置。

## 测试前提

| 类型 | 准备项 | 说明 |

## 核心测试原则

1. 所有涉及“商品单价”的展示、计算、导出、打印和后台明细，必须以 1688 `promotionPrice` 为唯一来源。
2. 生成报价单后，`promotionPrice`、预估国内运费、代采手续费必须形成硬快照，后续价格和运费变更不得污染报价单和已支付订单。
3. “会员已省”“本店节省”“商品金额节省”“代采手续费节省”“人工交涉节省”只用于展示，不得作为二次抵扣项混入报价单支付金额、实际清算金额或订单差额。
4. 后台新清算公式固定为：`实际清算金额 = 实际支出 + 到付运费 + 退换货运费 + 店铺其他费用 + 实际检品费用 + 实际附加项费用 + 订单其他费用 + 实际代采手续费 - 店铺退款 - 店铺返现`；`订单差额 = 报价单支付金额 - 实际清算金额`。
5. 订单差额方向必须统一：差额 > 0 展示应退还客户，差额 < 0 展示客户需补，差额 = 0 展示无需处理；前台、管理端、清算记录和公式弹窗不得反向。
6. 平台服务费是第三方支付平台费用，不由 Hubbuyer 收取，不计入报价单金额和清算公式；退款通道、资金执行、导出文件格式不在本次页面级 PRD 范围内。
7. 已清算历史订单保留原已保存结果，不因打开订单详情、查询记录或查看公式自动重算；未清算历史订单缺少必要金额时禁止确认。
8. 店铺退款统一包含少货、退货、没货、商品不良等店铺退回金额，不得再拆成没货退款金额、不良退款金额或退换货退款重复计算。
9. 所有新增固定字段、按钮、状态、表头、提示、抽屉文案和 hover 文案必须从多语言配置读取，动态业务数据不翻译。

## 1. 前台商品 C-GOODS

### 1.1 商品列表与商品卡

- **【重点】** 商品卡价格源：有 `promotionPrice` 时展示 Hubbuyer 价格，并与 1688 原价形成明确层级。
- **【重点】** 价格异常降级：`promotionPrice` 缺失、为 0、非法格式、接口超时或 1688 异常时，不得回退旧单价，不得生成错误会员价。
- 商品入口一致性：首页、词搜、图搜、店铺内页、足迹、推荐等宫格列表入口使用同一商品卡结构和价格口径。
- 商品卡状态隔离：普通商品、会员价商品、下架商品、库存不足商品的价格、按钮、提示互不串扰。
- 金额精度：CNY/JPY 展示、换算、四舍五入和小数位符合页面现有规范。
- 多语言配置：商品卡新增字段、价格标签、提示和 hover 文案随语言切换。

### 1.2 商品详情页

- **【重点】** Hubbuyer 价格模块：展示 `promotionPrice`、1688 原价、SKU、库存、起订量和价格说明。
- **【重点】** 预估国内运费：选择 SKU 和数量后调用 `product.freight.estimate`，返回值只影响运费字段，不污染商品单价。
- 加购前校验：SKU 未选、库存不足、低于起订量、运费异常或价格异常时阻断加购并给出定位提示。
- 数量联动：修改数量后商品金额、预估国内运费和加购快照实时刷新。
- 异常态：运费接口失败、超时、参数不足时展示待确认或不可报价状态，不允许异常值进入报价。

## 2. 购物车与确认订单 C-CART

### 2.1 购物车页面

- **【重点】** 商品行单价：购物车中的商品单价必须沿用加购时 `promotionPrice` 快照。
- 商品行金额：数量增减、勾选/取消勾选、SKU 混合时，小计和总计按当前有效行实时计算。
- **【重点】** 会员已省：按 `1688原价金额 - Hubbuyer会员价金额` 汇总，只展示权益感知，不参与支付扣减。
- 预估国内运费汇总：多店铺、多商品、多 SKU 场景下按店铺/商品口径汇总，不与商品金额混加。
- 异常阻断：价格失效、运费待确认、库存不足、商品下架时阻断下一步，并定位到具体商品行。
- 普通账号与会员账号差异：普通账号不展示不适用的会员减免，会员账号展示会员权益和减免说明。

### 2.2 确认订单页面

- **【重点】** 费用一览：商品金额、预估国内运费、选项费用、代采手续费、报价单支付金额分项准确。
- 代采手续费：普通账号正常收取，会员账号按权益免除或减免，并展示减免来源。
- **【重点】** 平台服务费隔离：不得作为报价单金额组成部分展示或参与报价单支付金额计算。
- 快照生成前校验：点击下一步前必须校验价格、运费、手续费和协议勾选状态。
- 商品列表一致性：确认订单中的商品名、SKU、数量、单价、小计与购物车勾选结果一致。
- 多币种展示：CNY、JPY 或页面支持币种的换算和小数位保持一致。

## 3. 报价单与支付 C-QUOTE

### 3.1 报价单生成与列表

- **【重点】** 报价单快照：生成报价单瞬间固化商品单价、预估国内运费、代采手续费和汇率相关字段。
- 报价单列表字段：会员已省、报价单支付金额、状态、期限、支付入口展示准确。
- 查询和筛选：按状态、编号、时间筛选时，金额字段不丢失、不重新取实时价。
- 过期处理：待入金超过有效期或支付期限过期时禁用支付，不产生订单。
- 批量支付：批量支付合计金额与单笔报价单金额之和一致，平台服务费单列。

### 3.2 报价单详情与支付弹窗

- **【重点】** 快照隔离：生成报价单后，1688 `promotionPrice` 或预估国内运费变化，不影响待支付和已支付报价单。
- **【重点】** 支付弹窗金额：报价单支付金额、余额、汇率、期限、平台服务费和实付金额展示口径清晰。
- 支付成功成单：支付成功后生成订单，报价单支付金额作为清算公式对比基准。
- 支付失败保护：支付失败不生成订单，不写入可用于清算的报价单支付金额。
- 下载与打印：报价单下载、打印中的单价和金额与详情页快照一致。
- 篡改防护：前端篡改金额、数量、费用字段时，后端按快照校验并拒绝异常提交。

### 3.3 前台订单详情

- **【重点】** 订单差额卡：`订单差额 = 报价单支付金额 - 实际清算金额`，正数应退还客户，负数客户需补，0 无需处理。
- **【重点】** 前台费用一览：报价单支付金额、实际清算金额、订单差额和节省信息展开/收起后合计一致，不在前台重新计算清算结果。
- 前台费用明细弹窗：订单模式和店铺模式标题、统计金额、明细内容随入口变化，关闭后回到订单详情原位置。
- 店铺明细：店铺退款统一字段，商品金额节省、人工交涉节省和代采手续费节省只展示，不参与订单差额。
- 人工交涉节省异常：负数时保留真实金额并红色加粗，不改成 0。
- 清算状态：待清算、已清算、需补款、需退款、无差额状态展示和跳转准确。
- 清算透明提示：固定文案走多语言配置，关闭/恢复交互不影响金额展示。

## 4. 后台订单管理 A-ORDER

### 4.1 代购订单详情与实际费用维护

- **【重点】** 后台全单价覆盖：订单、报价单、全商品、发货订单、采购处理、仓库发货、清算弹窗中的商品单价均读取 `promotionPrice` 快照。
- 采购与客户价隔离：实际采购价、实际支出、客户价、商品单价字段独立，不能互相覆盖。
- **【重点】** 清算来源字段：实际支出、正品金额、国内运费、到付运费、退换货运费、店铺其他费用、店铺退款、店铺返现和人工交涉节省字段名称、用途和保存结果正确。
- **【重点】** 采购确认：采购确认后按钮变为置灰“已确认”并禁用，重复点击不重复提交。
- 计算公式入口：订单详情点击计算公式时居中打开，并与订单清算和清算记录使用同一套公式。
- 订单清算入口：点击订单清算后从右侧打开清算抽屉，关闭后恢复订单详情滚动。
- 商品状态流转：采购、到货、质检、不良、退换货、正品、入库、发货状态不改写商品单价快照。
- 实际费用边界：实际运费、质检费、附加项、订单其他费用支持 0、正数、小数，非法负数按规则拦截。
- 批量操作防漂移：一键发货、批量确认金额、重新计算等动作不回写旧单价。
- 操作日志：商品单价来源、费用维护、状态变更和操作人时间可审计。

### 4.2 后台权限与数据安全

- **【重点】** 清算权限：无权限账号不能打开确定清算、资金扣减、退款或导出敏感财务字段。
- 只读账号：只读角色可查看允许范围内字段，不可提交费用变更。
- 接口越权：绕过前端直接调用清算或导出接口时，服务端必须拒绝。
- 日志脱敏：审计日志不得泄露登录凭据、Token、Cookie 或支付敏感数据。

## 5. 订单清算 A-SETTLE

### 5.1 清算弹窗与公式试算

- **【重点】** 报价单支付金额公式：`商品金额 + 预估国内运费 + 预估检品费用 + 预估附加项费用 + 预估代采手续费`，组成与合计必须一致。
- **【重点】** 实际清算金额公式：`实际支出 + 到付运费 + 退换货运费 + 店铺其他费用 + 实际检品费用 + 实际附加项费用 + 订单其他费用 + 实际代采手续费 - 店铺退款 - 店铺返现`。
- **【重点】** 订单差额公式：`报价单支付金额 - 实际清算金额`，前台、后台、清算记录和计算公式弹窗必须一致。
- **【重点】** 差额方向：订单差额正数展示应退还客户，负数展示客户需补，0 展示无需处理；符号与文案不一致时禁止确认。
- 平台服务费隔离：平台服务费不得进入实际清算金额、报价单支付金额或订单差额公式。
- 人工交涉节省：`正品金额 + 店铺退款 + 国内运费 - 实际支出 + 店铺返现` 独立展示，不进入实际清算金额；负数红色加粗。
- 店铺退款合并：少货、退货、没货、商品不良等退回金额统一为店铺退款，不得重复拆分计算。
- 防重复录入：同一来源金额同时出现在店铺退款、店铺返现、订单其他费用或人工交涉节省时给出核对提示。
- 金额精度：多级小数、0.01 边界、汇率换算和四舍五入后公式结果一致。
- 重算来源：重新计算只读取已保存店铺费用结果，不读取未提交临时值；未保存费用或格式错误时停留当前抽屉并指出字段。
- 抽屉交互：右侧抽屉内部仅保留一个纵向滚动条，底层订单详情滚动锁定，关闭后恢复。

### 5.2 费用明细弹窗与订单其他费用

- **【重点】** 检品方式明细：从订单清算抽屉左侧打开，展示检品方式、单价、数量、合计，合计等于实际检品费用。
- **【重点】** 附加项明细：从订单清算抽屉左侧打开，展示附加项、单价、数量、合计，不出现“SKU 附加项”旧标题。
- 店铺其他费用明细：展示样品费用、托盘费用、辅材费用、其他费用四类及合计，未发生显示 0。
- **【重点】** 订单其他费用：支持托盘费用、叉车费用、仓储费用、其他；仅选择其他时显示自定义费用名称。
- 订单其他费用校验：非数字、0、负数、未选择类型或未保存行不得进入实际清算金额。
- 弹窗排列和拖动：四类费用弹窗可同时打开，按点击顺序从上到下排列，标题栏可拖动并保持在可视范围内，不遮挡右侧清算抽屉。
- 再次点击入口关闭：再次点击同一详情/添加入口关闭对应弹窗，不影响其他已打开弹窗。

### 5.3 确定清算、记录与历史兼容

- **【重点】** 确认清算：确认前必须展示报价单支付金额、实际清算金额、人工交涉节省、订单差额和方向；未重算、组成不一致或差额方向错误时禁止提交。
- **【重点】** 清算记录生成：确认成功后形成历史清算记录；取消或确认失败时不生成新的清算记录，不改变上一份已确认结果。
- **【重点】** 已清算历史订单：继续展示清算时保存的结果，不因打开订单详情、查询记录或查看公式自动重算。
- **【重点】** 未清算历史订单：必要金额完整后才按新逻辑重新计算；必要金额缺失时指出缺失项目并禁止确认。
- 历史退款字段：历史没货退款、不良退款等拆分字段合并展示为店铺退款，合并不导致重复计算。
- 并发控制：多个后台账号同时清算同一订单时，只有一个版本成功，其他提示已变更。
- 状态锁定：清算完成后普通费用字段不可随意编辑，确需重算必须走授权流程。
- 审计完整：清算版本、字段快照、操作人、时间、差额方向和确认结果完整记录；资金执行不在本次页面级 PRD 范围内。

## 6. 全局导出规则 G-EXPORT

### 6.1 表单下载、导出和打印

- **【重点】** 全表单单价：订单、报价单、全商品、发货订单、采购处理、仓库发货、清算弹窗、表单下载、导出、打印中所有“单价”列均取 `promotionPrice` 快照。
- 报价单下载：报价单支付金额、预估国内运费、代采手续费和商品明细与页面一致。
- 订单清算记录：客户信息、订单信息、订单业绩、清算结果、报价单支付金额、实际支出、质检/退款/返利和清算信息八组字段完整。
- 订单导出入口：按当前筛选范围触发导出页面动作并给出反馈；导出文件结构不在本次页面级 PRD 范围内。
- 权限导出：无财务权限账号导出时隐藏或拒绝敏感字段。
- 历史订单导出：历史快照不被当前价格、运费、会员权益变化影响。
- 文件格式：Excel/PDF/打印模板中的金额精度、币种、字段名和多语言文案符合当前语言。

## 7. 跨模块回归与风险观察

- **【重点】** 从商品详情 -> 购物车 -> 确认订单 -> 报价单 -> 支付 -> 管理端订单详情 -> 订单清算 -> 前台订单详情 -> 订单清算记录形成全链路对账闭环。
- **【重点】** 价格源、报价单快照、清算公式、清算版本和历史记录五类数据必须能通过订单号追溯。
- 前台多语言切换后，金额、订单号、商品名、店铺名等动态业务数据保持原值。
- 线上/测试环境数据隔离，支付、清算确认和历史记录验证必须使用沙箱或专用测试账户，不触发真实资金动作。
- 回归时优先执行 Critical 用例，再执行 High/Medium 用例；任何 Critical 失败不得给出上线通过结论。
