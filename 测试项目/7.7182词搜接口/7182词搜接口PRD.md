# 7182词搜接口产品需求文档

## 1. 项目背景与目标

### 1.1 项目背景

7182 客户已有樱花站开放接口对接经验，本次在全球站域名下分为两类交付：第一类是接口对接需求，仅包含 1688 词搜列表接口和商品详情接口，不开发客户侧词搜列表页或商品详情页；第二类是页面需求，包含前台商品数据查询页面、后台「API客户授权」页面、后台「调用日志记录」页面。商品数据查询页面背后的商品状态查询服务作为独立一级模块描述，使用同一套 Client Key / Client Secret / Bearer Token 做认证，但不混入词搜列表、商品详情接口章节。

当前需求有几个特殊点：

1. 接口使用全球站域名承接，建议对外域名为 `https://open.hubbuyer.com/open_api/v1`；如部署阶段 `open.hubbuyer.com` 尚未启用，可临时由 `api.hubbuyer.com` 反向代理，但对外文档应统一到开放接口域名。
2. 上游只对接 1688 官方开放平台两个能力：多语言关键词搜索、 多语言商品详情。
3. 7182 客户为日本客户，外部搜索关键词仅支持日文，返回商品可见信息统一为日文。
4. 鉴权、限流、日志延续樱花站开放接口的 JWT Bearer Token 方案，减少 7182 侧重新对接成本。
5. 后台维护沿用樱花站逻辑，客户凭据、Token、限流、启停状态集中在 API客户授权内维护，调用明细在调用日志记录中查询；前台商品数据查询页面面向 7182 日本客户，不放在后台左侧导航内。
6. 商品状态查询接口不调用 1688 上游，而是以全球站订单与全商品数据为准，重点读取 `b2b_order.status` 与 `b2b_order_detail.order_mark`，避免沿用樱花站与全球站不一致的状态文案。

**总备注：** 本项目涉及的接口鉴权、客户查询入口、商品状态查询交互和页面设计逻辑，可以参考樱花站现有设计逻辑执行；如樱花站逻辑与全球站数据状态、字段来源或安全要求冲突，以全球站实际业务数据和安全规则为准。

### 1.2 项目目标

1. 为 7182 提供全球站域名下的 1688 关键词搜索接口，支持分页、价格、销量、类目、发货时效、工厂认证、一件代发等筛选或排序。
2. 为 7182 提供商品详情接口，可根据搜索结果中的 `offer_id` 查询商品详情、SKU、价格、图片、供应商、服务标签等日文信息。
3. 支持“搜索 + 当前页补充详情”的组合能力，但限制每次详情补充数量，避免上游 1688 调用压力过高。
4. 将前台商品数据查询页面作为独立页面模块交付，支持 7182 日本客户操作人查询所有已导入商品的当前状态，状态以全球站订单和全商品为准。
5. 保证词搜列表接口、商品详情接口、商品状态查询服务复用一套 Client Key / Client Secret / Bearer Token，便于客户统一认证。
6. 在管理系统 API维护下只提供 API客户授权、调用日志记录两个后台页面；前台商品数据查询页面独立访问，页面参考樱花站查询逻辑，不进入后台导航。
7. 1688 上游字段、筛选能力、分页字段和商详入参不在 PRD 中精确固化，开发以 1688 控制台实际接口文档和联调返回为最终准则。

## 2. 【公共能力】统一认证与客户身份

### 2.1 MOD-001 统一认证节点

**① 核心业务逻辑介绍**

7182 客户先使用管理员提供的 `client_key` 和 `client_secret` 获取访问 Token。后续词搜列表接口、商品详情接口，以及独立商品状态查询服务，均在请求头中携带 `Authorization: Bearer <access_token>`。该方案沿用樱花站开放接口的鉴权内容，避免外部客户改造为复杂签名模式。

**② 字段级别功能描述与异常流程**

**(1) Token 获取接口**

| 字段/控件名称 | 功能展现描述 | 业务规则与异常边界处理 |
| --- | --- | --- |
| 接口地址 | `POST /open_api/v1/auth/token` | 基础地址为 `https://open.hubbuyer.com`。若实际部署前缀不同，必须在交付文档中统一更新。 |
| `client_key` | 客户标识 | 必填。由管理员发放，本期 7182 使用全球站客户ID `SKR7182`；不保留樱花站旧 key 映射。 |
| `client_secret` | 客户密钥 | 必填。只在 Token 获取接口提交，不进入日志明文；校验失败返回 401。 |
| `access_token` | JWT Token | 返回后用于后续接口。建议有效期 30 天，沿用樱花站方案；过期后重新获取。 |
| `token_type` | Token 类型 | 固定返回 `Bearer`。 |
| `expires_in` | Token 过期时间 | 返回 `YYYY-MM-DD HH:mm:ss`，便于 7182 侧提前刷新。 |

**(2) 业务接口请求头**

| 请求头 | 是否必填 | 规则 |
| --- | --- | --- |
| `Authorization` | 是 | 格式必须是 `Bearer` + 半角空格 + Token。Token 禁止放在网址查询参数、日志、异常消息或第三方跳转地址中。 |
| `Content-Type` | 是 | `application/json; charset=utf-8`。Token 获取接口若沿用樱花站 form-data，也需同时兼容 JSON。 |
| `X-Request-Id` | 否 | 外部可传；未传时服务端自动生成，用于链路追踪。 |

**③ 交互与跳转说明**

- 认证失败不进入 1688 上游调用，也不进入商品状态数据库查询。
- Token 过期时返回 401，message 使用日文：`認証トークンが期限切れです`。
- 客户被禁用时返回 403，message 使用日文：`APIアクセスが無効になっています`。
- Token 获取接口不需要认证请求头，其他接口必须带认证请求头。

**接口状态、异常与失败处理**

| 状态 / 异常 | 触发条件 | 对外反馈 | 后端 / 审计处理 |
| --- | --- | --- | --- |
| 缺少凭据 | `client_key` 或 `client_secret` 为空 | HTTP 400，`client_key と client_secret は必須です` | 写失败日志，不记录密钥明文。 |
| 凭据错误 | 客户标识或密钥不匹配 | HTTP 401，`認証情報が無効です` | 记录 client_key、IP、失败原因分类。 |
| 客户禁用 | `open_api_client.status=0` | HTTP 403，`APIアクセスが無効になっています` | 记录禁用访问日志。 |
| Token 缺失 | 业务接口无 Authorization | HTTP 401，`認証トークンが必要です` | 不调用业务服务。 |
| Token 无效 | JWT 校验失败 | HTTP 401，`認証トークンが無効です` | 记录 token 摘要，不记录原 token。 |
| Token 过期 | 超出有效期 | HTTP 401，`認証トークンが期限切れです` | 提示重新获取 Token。 |

**④ 关联的隐藏后端模块及解决方案**

| 关联模块 | 影响点 | 解决方案 |
| --- | --- | --- |
| 开放接口客户配置 | 需要维护 7182 客户 key、secret、JWT key、限流、状态 | 复用樱花站 `open_api_client` 思路；全球站可新建等价表或迁移到现有开放接口客户配置。 |
| Token 服务 | 需要支持 30 天有效期、过期重取、客户禁用 | JWT 载荷 中包含 `client_id/user_id/client_key/exp`，后端以客户配置表为权限真相。 |
| 请求日志 | 所有认证成功/失败都要可追踪 | 复用 `open_api_log` 思路，密钥、Token、1688 access_token 脱敏。 |

## 3. 【接口对接需求】词搜列表接口（无页面）

### 3.1 MOD-002 词搜列表接口

**① 核心业务逻辑介绍**

本模块不开发页面，仅作为 7182 客户系统对接的接口需求。7182 客户输入日文关键词后，全球站开放接口服务校验参数与权限，统一将上游展示语言设置为日文，调用 1688 多语言词搜列表接口，返回商品列表。搜索结果必须包含可用于详情查询的 `offer_id`，并尽量返回日文标题、主图、价格、销量、起订量、供应商、服务标签、商品链接等核心字段。

接口建议：

```text
POST https://open.hubbuyer.com/open_api/v1/product/search
```

**② 字段级别功能描述与异常流程**

**(1) 请求参数**

| 字段/控件名称 | 功能展现描述 | 业务规则与异常边界处理 |
| --- | --- | --- |
| `keyword` | 搜索关键词 | 必填，仅支持日文关键词。去除首尾空格后长度 1-100 字符；不支持空关键词。 |
| `keyword_language` | 关键词语言 | 可选，默认 `ja`，仅允许 `ja`。传 `zh/en/ko/es` 等其他值返回 400。 |
| `response_language` | 返回语言 | 固定为 `ja`，可不传。商品可见信息统一返回日文。 |
| `page` | 页码 | 默认 1，从 1 开始。对外统一用 `page`，内部适配 1688 的 `beginPage/pageNo`。 |
| `page_size` | 每页条数 | 默认 20，最大 50。若 `include_detail=true`，建议最大 20。 |
| `include_detail` | 是否补充详情 | 默认 `false`。为 `true` 时，对当前页商品逐个调用商详接口补充核心详情；最多补充 20 个商品。 |
| `price_min` | 最低价格 | 可选，单位人民币元。必须大于等于 0；不得大于 `price_max`。优先透传上游价格筛选。 |
| `price_max` | 最高价格 | 可选，单位人民币元。必须大于等于 0；不得小于 `price_min`。 |

## 9. 筛选、排序与语言规则

### 9.1 RULE-001 筛选条件规则

| 规则ID | 规则说明 | 风险与处理 |
| --- | --- | --- |
| RULE-001 | 所有筛选字段必须白名单校验；未知字段返回 400。 | 避免客户误以为无效筛选已生效。 |
| RULE-002 | 价格区间优先使用上游筛选；若上游不支持，使用本地过滤并在 `filter_notes` 标记。 | 本地过滤可能导致 total 不精确。 |
| RULE-003 | 销量排序优先使用上游 `monthSold desc`；销量最低值若上游不支持，使用本地过滤。 | 不承诺跨 1688 全量的绝对精确排序。 |
| RULE-004 | 发货时效、认证工厂、一件代发、7天上新、1688严选通过 `filter` 组合传递。 | 多筛选为 AND 关系。上游不支持的筛选需在备注中说明。 |
| RULE-005 | 起订量、复购率、店铺评分属于采购质量筛选，若上游不支持则按候选集本地过滤。 | 返回 `filter_notes` 说明候选集过滤。 |

### 9.2 RULE-006 排序规则

| `sort` 值 | 含义 | 上游映射建议 | 备注 |
| --- | --- | --- | --- |
| `relevance` | 综合相关性 | 不传或使用上游默认 | 默认值。 |
| `sales_desc` | 月销量从高到低 | `monthSold desc` | 若上游不支持，按返回列表本地排序。 |
| `price_asc` | 价格从低到高 | `price asc` | 使用可比较的最低价。 |
| `price_desc` | 价格从高到低 | `price desc` | 使用可比较的最低价或主价格。 |

### 9.4 RULE-014 商品状态查询规则

### 10.4 安全与审计规则

| 风险点 | 要求 |
| --- | --- |
| Token 泄露 | Token 只能放在认证请求头；日志中只记录摘要，不记录原值。 |
| 1688 密钥泄露 | 1688 AppKey、AppSecret、access_token、refresh_token、签名不得返回给 7182。 |
| CORS | 开放接口面向服务端调用，生产环境不使用 `*`；如 7182 有固定来源，可配置白名单。 |
| 限流 | 默认每客户 60 次/分钟，可按 `open_api_client.rate_limit` 配置；上游 1688 另设内部调用限速。 |
| 参数注入 | 所有筛选、排序字段使用白名单；keyword 限长并做日志脱敏。 |
| 日志敏感信息 | 不记录密钥、Token、完整上游响应中的敏感字段；仅记录错误分类和 trace_id。 |
| 上游异常 | 不把 1688 原始堆栈、签名字符串、完整请求 URL 返回给客户。 |
