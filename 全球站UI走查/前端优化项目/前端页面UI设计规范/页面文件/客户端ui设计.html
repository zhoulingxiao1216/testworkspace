用户中心全页面 UI 统一优化方案

根据确认需求，本方案聚焦用户中心所有业务页面：报价单、我的订单、交易明细、重要待办、表格列宽、图片展示、字段字号与色号。目标是把页面从“各模块各自设计”统一为“同一套业务系统界面”。

一、通用基础规范：全球用户与多语言适配

Hubbuyer B2B 面向全球用户，界面不能只按中文长度、人民币格式和中国地址格式设计。用户登录后根据注册时选择的国家/地区自动匹配语言、币种、时区和地址规则；顶部工具区统一保留语言切换控件，中文与英文页面必须能双向切换。

适配项 设计要求 页面影响
语言长度 中文、英文、日文、韩文、繁体中文均需验收。英文文案通常比中文长 30% 到 60%，按钮和表头不能固定中文宽度。 导航、筛选项、状态标签、表格表头、弹窗标题、详情页面。
状态翻译 状态翻译按普通文字规范展示，不使用按钮或胶囊标签；展示文案根据用户注册地区自动匹配，例如“已发货 / Shipped / 発送済み / 배송됨”。 报价单、订单、商品、国际配送、资金审核、重要待办。
金额与币种 金额列必须同时支持 CNY、USD、JPY、KRW 等币种；币种符号与数字分开排版，金额右对齐，小数位按币种规则展示。 报价单费用、支付金额、交易明细、物流费用、余额。
时区与日期 列表显示注册地区对应时区，详情中保留原始业务时间。日期格式按语言地区自动显示，例如 2026-06-01、Jun 1, 2026、2026/06/01。 订单时间、支付时间、物流节点、交易流水、消息时间。
地址格式 地址表单按国家切换字段顺序和必填项，不能只使用“省市区详细地址”的中国式结构。 我的地址、进口商地址、收货地址、发货配送地址确认。
姓名和联系方式 支持不同姓名顺序、国际手机号区号、邮编、州/省、税号/VAT/EORI 等字段。 账号信息、地址、进口商、发票、售后服务。
文案回退 缺少某语言翻译时优先回退英文，不显示空白、不显示代码 key，不破坏表格布局。 全部页面。
列宽原则

状态列、操作列、金额列需要预留多语言长度；长文案统一省略，鼠标悬停显示完整翻译。

测试语言

至少按简体中文、英文、日文、韩文、繁体中文检查页面是否换行、遮挡、超出、按钮变形。

用户设置

账户设置展示注册国家/地区、系统识别语言、默认币种、时区、地址格式规则；语言不作为前台手动切换项。

二、通用基础规范：搜索栏与筛选器

用户中心所有列表页搜索区必须统一。搜索栏不只是输入框，还包括文本输入、下拉选择、状态筛选、时间范围、国家/地区选择、搜索与重置操作。所有筛选项需要支持多语言长度和不同地区日期格式。

控件类型 使用场景 UI 规范
文本输入框 报价单编号、订单编号、商品名、物流单号、交易流水号、用户订单号。 高度 32px，圆角 4px，边框 #D8DFEB；placeholder 使用 #98A2B3；输入文字 14px / #1F2937；支持清空图标。
单选下拉 支付状态、审核状态、物流方式、交易类型、账号状态、地址类型。 高度 32px，右侧箭头图标；选中项单行省略，悬停显示完整文案；下拉层宽度不小于触发器宽度。
多选下拉 多状态组合筛选、多物流渠道、多商品分类。 选中后显示“已选 3 项 / 3 selected”，不要把多个标签全部挤在输入框内；下拉内用复选框。
时间范围筛选器 下单日期、支付日期、提交时间、发货时间、交易时间、通知时间。 开始时间和结束时间放在同一控件内，中间使用短分隔符；宽度 260-320px；日期格式按注册地区自动展示。

状态 Tabs 报价单、我的订单、重要待办、国际配送等高频状态分组。 放在搜索筛选区下方、列表表格上方，用于快速切换状态分组。Tab 高度 44-46px，圆角 7px 7px 0 0，间距 8-10px；3 个以内可用等宽大按钮，单项最小宽度约 170px；状态较多时按整行网格均分或横向滚动，文案不换行。当前选中项使用深蓝底 #022559、白字、字重 800；未选中项使用浅灰底 #DCE3EC / #DFE5EE、深色文字、字重 650。数量统一跟在状态文案后并使用半角括号，例如“全部 (29) / 进行中 (15) / 已清算 (14)”，数量为 0 也保留展示。Tabs 只承担高频状态分组，不替代下拉筛选；首页状态入口跳转后必须与对应 Tab 状态保持一致。
搜索按钮 执行当前筛选条件。 主按钮，高度 32px，宽度 76-88px，深蓝底 #022559，白色文字；可带搜索图标。
重置按钮 清空所有筛选条件。 次级按钮，高度 32px，浅灰边框或浅灰底，不使用大面积深灰实心按钮；文案按地区自动翻译。

如果详情页需要进入关联业务页，放在详情页底部作为“查看关联业务”入口，不替代“查看详情”。

四、通用基础规范：表格列宽、字号、色号

该表格规范应用到用户中心所有列表页面，保证列宽、表头、单元格、状态、金额、操作视觉一致。列表总宽度不能超过当前显示器/内容区宽度；字段内容超过当前列宽时统一显示省略号，鼠标悬停、键盘聚焦或选中文本时显示完整信息。

表头设计规则

表头使用浅灰蓝底，文字居中，14px / 700 / #1F2937；列与列之间使用 #CFD8E6 细分割线；表头高度 40px，表头文字不换行。

宽度硬性规则

主列表宽度必须控制在 100% 内容区内。桌面端不允许因为文字过长出现页面级横向滚动；表格内部也不应要求用户横向滚动才能完成主要任务。

操作列宽度规则

列表操作列固定为 12% 宽度；“查看详情 / View details / 詳細を見る”等操作入口必须完整显示且不换行。操作列内容居中展示，按钮或文字入口优先保障可读。

字段显隐规则

商品数据、质检数据、仓库数据、交易金额等组合字段只展示有业务数据的内容；数值为 0、空值、-- 的字段不展示，不占用一行。内容文字行统一使用 #f3f6fa 浅蓝灰底色承载；若同一字段组全部无数据，该单元格保持留白或展示轻量占位，不重复列出 0。

最小屏幕验收

按 1366px 桌面宽度验收主列表，页面内容区内不得溢出；较小屏幕时仍按当前列宽省略，不压缩文字和按钮。

横向滚动限制

横向滚动只能作为极端兜底，不作为常规交互方案。报价单、我的订单、我的商品、国际配送、仓库列表都必须在一屏宽度内完成识别、判断和查看详情。

八、商品详情选中

商品详情页的颜色、尺码、SKU 数量选择需要让用户清楚知道当前选择，但选中态不能过度抢眼。选中反馈使用柔和描边、轻背景和右下角小标识；数量发生变化的 SKU 行同步展示选中态，并在底部汇总已选种类、总件数和商品金额。

颜色选中当前色块使用柔和描边、浅红底和右下角小标识；未选中项保持白底灰线，不用大面积填充。
尺码选中有购买数量的 SKU 行整行轻量高亮，连续选中时边框合并，方便用户确认多个规格。
汇总联动底部固定展示已选种类、总件数、商品金额和主操作，避免长规格内容挤压按钮。

十二、发货配送页面

发货配送覆盖我的仓库、提交发货单、国际物流、物流详情、发票。重点是物流状态、商品图、物流号、渠道和金额的统一展示。

我的仓库

按商品图、商品信息、库存/在库数量、仓库状态、操作分组；状态色与国际配送保持一致。

托管使用说明

“使用说明”属于帮助入口，不使用主按钮、描边圆角按钮或大面积高亮样式。建议放在“开启托管”文案右侧，使用 14px 灰蓝文字链接或问号图标 + tooltip；点击后跳转使用说明页面。

托管操作优先级

托管开关/确认托管是主操作；使用说明只是辅助解释。视觉权重应低于托管开关、搜索、提交发货等业务操作，避免用户误以为说明是下一步主流程。

提交发货单

商品信息和 SKU 必须完整；底部提交栏固定，金额与操作不被长商品名挤压。

国际物流

“更多”和首页状态卡跳转到同一套状态 Tabs；物流号、渠道、状态、操作列统一。

物流详情 / 发票

详情页延续列表状态色；发票金额右对齐，文件下载使用次按钮。

查看详情

发货配送相关列表中的“查看详情”统一跳转物流详情页；详情页底部可提供“查看完整物流详情”入口。

十三、资金管理页面

资金管理覆盖余额、充值、提现、汇款记录、转账、交易明细、费用明细。重点是金额右对齐、交易类型颜色、审核状态和时间列统一。

余额 / 充值 / 转账

金额是主信息，币种与数字分开排版；主要动作使用主按钮，说明文字保持弱化。

提现 / 汇款记录

审核状态使用统一胶囊标签；拒绝原因和凭证支持悬停完整展示。

交易明细 / 费用明细

交易类型、流水号、时间、金额列固定层级；“查看详情”使用浅蓝描边圆角入口，“交易明细”作为业务跳转入口。

查看详情

资金记录、交易明细、费用明细中的“查看详情”统一跳转详情页。

十四、购物车与确认订单页面

购物车和确认订单是高风险操作页，重点是商品信息、SKU、附加项、金额和底部提交操作的稳定布局。

购物车

商品图、标题、SKU、数量、单价、小计层级固定；删除等轻操作文字化或图标化。数量、单价、小计三列数字统一居中并加粗显示，字号 14px、字重 800、使用等宽数字；数量数字使用 #1F2937，单价和小计使用 #B4272B。

附加项

检品、服务费、附加项目需要区分已选和可选状态，避免和商品规格混在一起。

确认订单

底部金额和提交按钮固定；长地址、长商品名、多币种金额都不能遮挡主按钮。

查看详情

购物车和确认订单内的附加项、费用说明、商品服务详情统一跳转对应详情页或说明页。
