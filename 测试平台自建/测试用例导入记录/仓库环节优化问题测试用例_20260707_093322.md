# 仓库环节优化问题 测试用例

## 1. PDA 正品录入
### 1.1 扫描异常提示

#### TC-PDA-PR-001 【异常】扫描捆绑商品条码正确提示

| 字段 | 内容 |
|:--|:--|
| **测试点** | 扫描捆绑商品条码时的语音播报及文本提示语验证 |
| **优先级** | Medium |
| **前置条件** | 准备一个捆绑商品的条码；用户进入 PDA 首页 -> 正品录入界面 |
| **操作步骤** | 1. 在条码扫描区扫描该捆绑商品条码 |
| **预期结果** | 1. 页面提示：“该条码是捆绑商品，无需正品操作” <br> 2. 语音同步播报：“该条码是捆绑商品，无需正品操作” |

### 1.2 详情页信息扩充

#### TC-PDA-PR-002 【正向】详情页展示贴纸及FBA信息

| 字段 | 内容 |
|:--|:--|
| **测试点** | 详情页成功渲染贴纸信息及 FBA 相关属性 |
| **优先级** | Low |
| **前置条件** | 订单包含具体的贴纸和 FBA 信息；用户进入 PDA 首页 -> 正品录入界面 |
| **操作步骤** | 1. 扫描正常非捆绑商品 <br> 2. 进入商品详情页查看信息 |
| **预期结果** | 1. 详情页可以清晰看到贴纸相关信息与 FBA 相关字段 |

## 2. PDA 配货模块
### 2.1 新订单触达提醒

#### TC-PDA-AL-001 【正向】新配货单接收与多重提醒

| 字段 | 内容 |
|:--|:--|
| **测试点** | 新配货单下发时语音播报、气泡数及列表红字的正确展示 |
| **优先级** | High |
| **前置条件** | 用户 A 停留在 PDA 待配货列表；后台新建一个配货单推送到 PDA |
| **操作步骤** | 1. 后台确认推送新配货单 <br> 2. 观察用户 A 的 PDA 端响应 |
| **预期结果** | 1. PDA 语音播报：“您有新的配货订单请跟进处理” <br> 2. “待配货”标签右上角消息气泡数字 +1 <br> 3. 待配货列表中该新订单单号呈现红色高亮 |

#### TC-PDA-AL-002 【正向】未读状态消除机制

| 字段 | 内容 |
|:--|:--|
| **测试点** | 点击红色未读单据详情后，未读状态消除颜色恢复 |
| **优先级** | Medium |
| **前置条件** | 用户 A 待配货列表中存在一个红色的新配货单 |
| **操作步骤** | 1. 用户 A 点击该红色订单单号进入详情页 <br> 2. 返回待配货列表 |
| **预期结果** | 1. 消息气泡数字对应减少 <br> 2. 列表该单号颜色恢复为正常默认颜色 |

### 2.2 并发锁定与状态流转

#### TC-PDA-AL-003 【并发】[SmokeTest]多用户并发抢单锁定机制

| 字段 | 内容 |
|:--|:--|
| **测试点** | 多人并发点击配货请求的数据竞争拦截，状态变更为配货中 |
| **优先级** | Critical |
| **前置条件** | 一笔待配货新订单同时存在于 UserA 和 UserB 的列表中 |
| **操作步骤** | 1. UserA 点击该单据的“配货”按钮 <br> 2. UserB 尝试同时或稍后点击同一单据的“配货”按钮 |
| **预期结果** | 1. UserA 成功认领，单据状态变更为“配货中” <br> 2. UserB 操作失败，提示已被他人接单或刷新后该单据从列表中消失 |

### 2.3 数据视图隔离

#### TC-PDA-AL-004 【权限】[SmokeTest]配货中状态的数据视图隔离

| 字段 | 内容 |
|:--|:--|
| **测试点** | "配货中"单据仅操作人可见，其他人不可见，PC 端回显操作人 |
| **优先级** | Critical |
| **前置条件** | 订单 X 被 UserA 接单，状态为“配货中”；UserA, UserB 均登录 PDA；管理员登录 PC 端 |
| **操作步骤** | 1. UserA 查看待配货列表 <br> 2. UserB 查看待配货列表 <br> 3. 管理员在 PC 端查看配货列表 |
| **预期结果** | 1. UserA 的列表中展示订单 X 且带有“配货中”状态标识 <br> 2. UserB 的列表中完全无订单 X 的数据 <br> 3. PC 端显示订单 X，状态为配货中，且配货员字段固定显示为 UserA，且不可修改 |

## 3. PDA 打包模块
### 3.1 自动打印触发机制

#### TC-PDA-PK-001 【正向】创建与新增箱子自动触发打印

| 字段 | 内容 |
|:--|:--|
| **测试点** | 首次点击创建箱子或新增箱子时自动调用打印机 |
| **优先级** | Medium |
| **前置条件** | 打印机已连接；单据进入待打包状态，UserA 进入打包详情页 |
| **操作步骤** | 1. 点击“创建箱子”按钮 <br> 2. 后续再点击“新增箱子”按钮 |
| **预期结果** | 1. 点击后自动触发打印机打印该箱子的箱码，无需二次确认 <br> 2. 页面同步渲染出发货箱列表 |

### 3.2 并发锁定与流转

#### TC-PDA-PK-002 【权限】[SmokeTest]多人装箱并发数据隔离控制

| 字段 | 内容 |
|:--|:--|
| **测试点** | 扫描装箱第一个商品即触发认领锁定，其他账号不可见 |
| **优先级** | Critical |
| **前置条件** | 订单 Y 处于待打包，UserA 和 UserB 的列表中均可见 |
| **操作步骤** | 1. UserA 针对订单 Y 的首个商品扫描装箱操作 <br> 2. UserB 刷新待打包列表 |
| **预期结果** | 1. UserA 扫描成功，单据状态变更为“打包中”，责任人绑定为 UserA <br> 2. UserB 的待打包列表中该单据 Y 消失 <br> 3. PC 端打包员强制记录为 UserA 且不可修改 |

### 3.3 完结提示与页面流转

#### TC-PDA-PK-003 【正向】装箱完结多路提示及准确跳转

| 字段 | 内容 |
|:--|:--|
| **测试点** | 最后一个商品装箱完后的语音、弹窗双提示，以及停留详情页 |
| **优先级** | High |
| **前置条件** | UserA 在打包中，只剩最后一个商品未扫码装箱 |
| **操作步骤** | 1. 扫码最后一件商品装箱完成 <br> 2. 确认装箱完结触发 |
| **预期结果** | 1. 语音播报：“该订单打包完成” <br> 2. PDA 界面弹出弹窗：“装箱单打包完成” <br> 3. 页面不会退出到待打包列表，而是自动停留在本订单的打包详情页中 |
