#### TC-IM-AUTH-001 【重点·异常】未登录状态下IM访问被拦截及接口401验证

| 字段 | 内容 |
|:--|:--|
| **测试点** | 1.1 未登录拦截：点击IM图标弹出登录引导弹窗，IM对话区无任何会话和消息内容；直接调用消息查询API返回401/403 |
| **优先级** | Critical |
| **前置条件** | 浏览器处于未登录状态（已清除Cookie/Session）；全球站首页正常加载 |
| **操作步骤** | **场景一（UI层弹窗拦截）**：1. 点击页面右侧IM图标 <br> 2. 观察是否弹出登录引导弹窗 <br> 3. 检查弹窗内按钮文案 <br> 4. 打开DevTools → Network，过滤消息相关API，确认是否有接口请求被触发 <br> **场景二（接口层401拦截）**：5. 使用DevTools或Postman，不携带Token直接调用IM消息查询API <br> 6. 查看接口响应状态码与响应体内容 |
| **预期结果** | 场景一：1. 弹出登录引导弹窗，IM对话区不展示任何会话和消息内容 <br> 2. 弹窗内同时包含「去登录」和「去注册」两个操作按钮 <br> 3. 弹窗期间DevTools Network中无任何消息API调用记录 <br> 场景二：4. 接口返回HTTP 401或403 <br> 5. 响应体不含任何用户数据（无用户ID、消息内容等敏感信息） |

#### TC-IM-CHAT-002 【Critical·数据追溯】先下单后分配业务员的订单信息追溯验证

| 字段 | 内容 |
|:--|:--|
| **测试点** | 原则6 数据追溯一致性：用户先下单（尚未分配业务员），后续分配业务员时，订单信息须同步推送给对应业务员，不出现订单信息孤岛 |
| **优先级** | Critical |
| **前置条件** | 准备一个已成功下单但尚未分配业务员的客户测试账号；后台管理员账号可执行业务员分配操作；业务员账号B处于登录状态 |
| **操作步骤** | 1. 确认客户账号已成功下单，订单状态正常，此时无业务员分配记录 <br> 2. 后台管理员登录，将该客户分配给业务员账号B <br> 3. 分配完成后切换至业务员账号B的IM界面 <br> 4. 查看与该客户的会话中是否收到该订单的关联信息/推送通知 <br> 5. 验证订单信息归属是否正确（订单关联至业务员B） <br> 6. 若客户有多笔历史订单（分配前下单），检查所有历史订单是否均完整同步 |
| **预期结果** | 1. 业务员B的IM会话中收到该客户历史订单的同步推送，不出现订单孤岛 <br> 2. 订单信息完整，包含订单ID、下单时间、商品信息等关键字段 <br> 3. 分配关系建立后，订单归属立即更新至业务员B名下，无延迟 <br> 4. 多笔历史订单（分配前下单）均完整同步至业务员B，无遗漏 |
| **备注** | 来源：原则6「先下单后分配」核心场景；需同时验证分配时间节点前后的订单均正确归属 |
