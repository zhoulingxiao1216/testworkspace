# 测试用例查询工作流

当用户要求查看、查询或讨论某条测试用例（如 TC-XX-NNN）时，执行以下步骤：

## 前置加载

- 先读取 `.agent/dependencies.yaml`，并使用 `deps.<alias>` 解析本文所有依赖路径。

## 0. 定位所属项目

根据用例编号前缀或用户上下文，确定该用例所属的项目目录。项目根目录统一位于 `deps.test_workspace_root` 下，每个项目的文档结构遵循以下约定：

```
{deps.project_root_pattern}\
├── 测试文档\
│   ├── 测试用例.md        ← 测试用例集
│   └── 测试点大纲.md      ← 测试点大纲
├── {项目名}PRD.md          ← PRD文档（或类似命名）
└── ...
```

如果无法从用例编号判断项目归属，则：
// turbo
1. 用 `rg` 或同等搜索工具在 `deps.test_workspace_root` 下搜索用例编号（如 `TC-SV-004`），定位到具体文件路径
2. 从文件路径反推项目目录

## 1. 定位测试用例原文
// turbo
在该项目的 `deps.project_test_cases_pattern` 对应文件中，搜索并展示该用例的完整内容（含测试点、优先级、前置条件、操作步骤、预期结果）。

## 2. 关联测试点大纲
// turbo
在该项目的 `deps.project_test_outline_pattern` 对应文件中，根据用例的"测试点"字段关键词进行搜索，定位并展示对应的大纲条目及其上下文层级关系（父级模块 → 子模块 → 具体测试点）。

## 3. 关联PRD文档依据
// turbo
在该项目根目录下搜索 PRD 文档（文件名含 `PRD` 或 `prd`），然后在 PRD 中搜索与该用例相关的关键词（如功能名称、计费模式、页面名称、字段名称等），定位并展示 PRD 中的原始需求描述，包括：
- 所属 PRD 章节编号与页面名
- 字段级功能描述
- 业务规则与异常边界处理

如果项目下没有 PRD 文档，则跳过此步骤并说明。

## 4. 输出格式

按以下结构输出查询结果：

### 用例原文
> （展示测试用例完整表格内容）

### 关联测试点（测试点大纲）
> （展示大纲中对应的层级路径和测试点描述）
> 来源：`deps.project_test_outline_pattern` 第 X 行

### PRD文档依据
> （展示 PRD 中的原始需求描述）
> 来源：`{项目名}/{PRD文件名}` 第 X-Y 行
