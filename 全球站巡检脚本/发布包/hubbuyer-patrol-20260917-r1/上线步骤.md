# 上线与回滚步骤

## 发布前

1. 暂停巡检计划任务，确认没有旧巡检进程正在运行。
2. 核对 ZIP 的 SHA-256 与同目录 .sha256 文件一致；解压后按 manifest.json 核对文件。
3. 在服务器本地备份 payload 中列出的 6 个目标文件和 config/data/purchase_order_ops.json。记录原本不存在的测试文件；备份留在服务器，不上传凭据或整个配置目录。
4. 确认目标项目已包含：core/path_manager.py 的 normalize_purchase_order_ops_config、normalize_purchase_order_shipping_config，checker/api/shipping_context_store.py，checker/api/quote_order_store.py 和 checker/api/purchase_order_audit.py。若版本明显不同，先比对接口依赖再发布。

## 应用更新

1. 将 payload/ 内文件按相对路径覆盖到线上 hubbuyer 根目录。不要把整个发布包覆盖配置目录。
2. 将 config_steps.merge.json 中的 steps 字段逐项、逐字段合并到线上 config/data/purchase_order_ops.json。对象递归合并，数组替换为本包列表；保留本文件未指定的字段。
3. 保留线上 enabled 开关、order_no、环境域名、headers、仓库和库位。json 仅合并 offline_admin_id=0，不删除其他已有字段。正品接口必须为 /admin_b2b/orderDetailUpdate/updateGenuineQty，payload_mode 必须为 single_detail。
4. 不覆盖 config/settings.py、config/data/login_data.py、Token、Cookie、付款及提交订单记录、发货上下文、日志等环境配置或运行数据。不操作 Global 后台。

## 验证

在目标项目已有虚拟环境中，使用对应的 Python 解释器执行：

```text
python -m unittest discover -s tests -p "test_add_cart_taobao.py"
python -m unittest discover -s tests -p "test_purchase_order_ops_genuine.py"
```

两个测试文件合计应为 15 项通过，测试使用模拟请求，不下单。

检查线上开关和账号后，执行一次真实巡检：

```text
python -u main.py
```

该命令会按线上开关创建报价、支付、入库、清算和发货，并可能按通知配置发送消息。需按现有巡检操作规范使用专用账号和样本。

验收：淘宝加购通过；正品直接成功，或保留首次失败 WARN 后重试一次成功且数量复核通过；持续失败不得判为成功；后续仓配和发货使用本轮订单。检查日志中的 WARN，不能只看成功总数。

验证完成后恢复计划任务。部署新脚本只需下次巡检进程加载，无需修改或重启 Global 后台服务。

## 回滚

暂停巡检，恢复发布前备份的 4 个业务脚本、2 个测试文件及 purchase_order_ops.json；原本不存在的测试文件仅移除本次新增文件。核对配置和语法后恢复计划任务。

回滚仅恢复代码与配置，不回退已经产生的真实订单、支付、库存或发货记录。保留线上原有运行数据，避免上下文错配。
