# 1688 开放平台应用流量监控方案

## 1. 目标

对 1688 开放平台应用流量进行定时监控，每 2 小时检查一次指定应用的“应用流量”。

监控入口：

```text
https://open.1688.com/console
```

目标应用示例：

```text
appKey: 9466082
应用名称: 樱花代购さくら代行
```

页面展示示例：

```text
应用流量：30049/1600000（单位：次/天）
```

## 2. 总体方案

本方案不放入当前 Global 项目代码库，作为独立监控任务部署。

推荐架构：

```text
独立服务器 / 云主机 / 自动化运行机
  -> Node.js + Playwright
  -> 持久化 Chrome 浏览器用户目录
  -> 人工首次登录 1688 开放平台
  -> cron / 计划任务每 2 小时执行一次检查
  -> 读取应用详情页“应用流量”
  -> 按阈值返回正常信息或告警信息
```

## 3. 登录策略

不建议每 2 小时重新登录，而是每 2 小时复用登录态访问页面。

推荐方式：

1. 第一次运行脚本时打开有界面浏览器。
2. 人工登录 `https://open.1688.com/console`。
3. 登录成功后，浏览器登录态保存到固定目录。
4. 后续定时任务复用该浏览器目录直接访问页面。
5. 如果登录态失效，任务返回 `login_required`，提醒人工重新登录。

示例目录：

```text
/opt/1688-monitor/browser-profile/
```

Windows 示例目录：

```text
D:\1688-monitor\browser-profile\
```

注意：`browser-profile` 中可能包含 Cookie、LocalStorage 等登录态数据，不能提交到 git，不能外传。

## 4. 定时任务

执行频率：每 2 小时一次。

Linux cron 示例：

```cron
0 */2 * * * node /opt/1688-monitor/check-traffic.mjs >> /opt/1688-monitor/logs/traffic.log 2>&1
```

Windows 计划任务执行命令示例：

```powershell
node D:\1688-monitor\check-traffic.mjs
```

## 5. 检查流程

每次任务执行流程：

1. 启动 Playwright，使用固定 `browser-profile`。
2. 打开 1688 开放平台控制台或应用详情页。
3. 判断是否仍处于登录态。
4. 如果未登录，返回登录失效告警。
5. 进入目标应用详情页。
6. 读取页面中的“应用流量”。
7. 解析用量，例如 `30049/1600000`。
8. 与阈值 `300000` 对比。
9. 输出正常信息或告警信息。

优先访问目标页面：

```text
https://open.1688.com/develop/app/detail?appKey=9466082
```

如果该地址受跳转参数影响，也可以先进入控制台，再按应用名称或 `appKey` 点击“查看应用”。

## 6. 阈值规则

阈值：

```text
300000/1600000
```

判断逻辑：

```text
used < 300000   正常
used >= 300000  告警
```

说明：

- `used` 表示当前已使用次数。
- `limit` 表示每日总额度，示例为 `1600000`。
- 当前规则只看 `used` 是否达到 `300000`，不按百分比判断。

## 7. 返回格式

### 7.1 正常返回

```json
{
  "code": 200,
  "msg": "normal",
  "data": {
    "appKey": "9466082",
    "appName": "樱花代购さくら代行",
    "used": 30049,
    "limit": 1600000,
    "threshold": 300000,
    "unit": "次/天",
    "message": "1688 应用流量正常"
  }
}
```

### 7.2 告警返回

```json
{
  "code": 200,
  "msg": "warning",
  "data": {
    "appKey": "9466082",
    "appName": "樱花代购さくら代行",
    "used": 320000,
    "limit": 1600000,
    "threshold": 300000,
    "unit": "次/天",
    "message": "1688 应用流量已达到或超过 300000，请关注"
  }
}
```

### 7.3 登录失效返回

```json
{
  "code": 401,
  "msg": "login_required",
  "data": {
    "appKey": "9466082",
    "message": "1688 登录态已失效，需要人工重新登录"
  }
}
```

### 7.4 页面解析失败返回

```json
{
  "code": 500,
  "msg": "parse_failed",
  "data": {
    "appKey": "9466082",
    "message": "未能从页面解析应用流量，可能是页面结构变化或网络异常"
  }
}
```

## 8. 告警出口

可选告警出口：

1. 控制台输出 JSON。
2. 写入本地日志文件。
3. 企业微信机器人。
4. 钉钉机器人。
5. 邮件。
6. 调用内部监控接口。

推荐第一版：

```text
JSON 输出 + 日志文件 + 企业微信或钉钉机器人
```

如果后续需要接入内部后台，可以把脚本结果 POST 到内部接口。

## 9. 配置建议

独立任务目录示例：

```text
/opt/1688-monitor/
  check-traffic.mjs
  config.json
  browser-profile/
  logs/
```

`config.json` 示例：

```json
{
  "consoleUrl": "https://open.1688.com/console",
  "appDetailUrl": "https://open.1688.com/develop/app/detail?appKey=9466082",
  "appKey": "9466082",
  "appName": "樱花代购さくら代行",
  "threshold": 300000,
  "browserProfileDir": "./browser-profile",
  "headless": true,
  "notify": {
    "type": "webhook",
    "webhookUrlEnv": "MONITOR_WEBHOOK_URL"
  }
}
```

注意：

- 不在配置文件中保存账号、密码、Cookie、AppSecret。
- Webhook 地址如含 token，建议通过环境变量传入。
- `browser-profile/` 和 `logs/` 不提交到 git。

## 10. 稳定性设计

页面选择器建议采用多级兜底：

1. 优先按文本 `应用流量` 定位。
2. 再解析同一行或附近文本中的数字结构。
3. 支持 `30049/1600000`、`30049 / 1600000` 等空格变体。
4. 解析失败时截图留存，便于排查页面是否改版。
5. 页面超时、网络错误、登录失效分别返回不同错误类型。

建议保留最近若干次运行结果：

```text
logs/traffic.log
logs/latest-result.json
logs/screenshots/
```

截图中可能包含后台信息，需按敏感文件处理。

## 11. 风险与处理

| 风险 | 说明 | 处理方式 |
|---|---|---|
| 登录态过期 | 1688 可能要求重新登录 | 返回 `login_required`，人工重新登录一次 |
| 页面改版 | DOM 或文案变化导致解析失败 | 使用文本定位和正则兜底，失败时截图排查 |
| 风控 | 高频访问可能触发风控 | 每 2 小时一次频率较低，不做自动破解登录 |
| 敏感信息泄露 | 浏览器目录保存登录态 | `browser-profile/` 不提交、不外传、限制服务器权限 |
| 网络异常 | 1688 页面加载失败 | 设置重试和超时，失败时返回错误 |

## 12. 结论

该方案可行。

推荐落地方式是：独立部署 `Node.js + Playwright` 定时任务，首次人工登录后长期复用浏览器登录态，每 2 小时读取一次应用流量。当已用量低于 `300000/1600000` 时返回正常用量信息；当已用量达到或超过 `300000` 时返回告警信息。
