Agent 1 · 测试设计师
从静态需求中提炼规则、设计覆盖面、生产可交接测试资产
P1
需求解析与 7 维审计全量扫描 PRD/原型，检查数据精度、权限边界、状态一致性、国际化、作用域、异常降级、模板一致性。
P3
Superpowers 规约演化沉淀项目高危规则、模块缩写字典、测试数据画像，并用规则依赖图固定审计顺序。
P4-5
大纲与用例实例化三级测试点大纲、TC 锚点、优先级决策、SmokeTest 打标，输出可执行用例集。
P6-7.5
自审、工期与交接清单完成规则映射自审，量化工期，并生成执行交接清单 YAML 供 Agent2 稳定解析。
边界：不登录活体系统
产出：MD / YAML / 验收报告
R0 质量闸口
cross_agent_review 闭环
A
Agent2 评审按六维度审计用例可执行性：步骤精细度、中文输入、环境可达、数据自愈、SmokeTest 队列、YAML 完整性。
B
Agent1 修补根据 F-N 反馈修补用例步骤、导航路径、API 参数、数据依赖与凭据引用。
C
复审通过全部反馈项解决后，才允许进入 E1 环境预检与正式执行。
Agent 2 · 测试执行官
在真实环境中后台执行、客观取证、生成执行报告与缺陷清单
E1
环境预检 Gate校验 URL、登录态、测试数据画像与环境截图；失败则输出阻塞报告。
E2
队列编排优先级顺序：Critical SmokeTest → Critical → High → Medium → Low，并等待人工确认执行范围。
E3
三层混合静默执行根据用例路由选择最稳执行层，避免抢占键鼠焦点。
