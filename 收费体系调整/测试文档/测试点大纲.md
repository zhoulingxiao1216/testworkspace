# 测试点大纲 - 收费体系调整

## 1. 前台商品 (C-GOODS)
### 1.1 商品列表页
- 宫格列表统一布局渲染：验证首页、搜索页、店铺内页、足迹的商品列表卡片使用统一新版样式
- 有会员价的商品卡展示：验证 `promotionPrice` 存在时高亮展示 Hubbuyer 价格及原价划线
- 无会员价的商品卡展示：验证无会员价时展示空态，不得回退并展示旧单价
- 【重点】价格异常降级：接口异常/格式非法时，卡片必须平滑降级为普通无会员价商品态
- 多语言适配校验：卡片上的固定提示文案需支持国际化切换

### 1.2 商品详情页
- 会员价模块区域显示：验证 1688 原价与高亮 Hubbuyer 会员价（`promotionPrice`）正确排布
- SKU 数量与价格联动：验证随数量变动，商品总金额能基于单价正确换算
- 【重点】预估国内运费拉取：验证选择完整 SKU 和数量后能成功拉取预估运费并实时展示
- 运费拉取失败阻断：验证接口失败时展示待确认字样，不得混入异常数值
- 加入购物车快照生成：确认加购动作会将单价、预估运费冻结为快照传递至购物车

## 2. 前台购物车与确认订单 (C-CART)
### 2.1 购物车页面
- 商品行价格状态区分：验证会员价商品与普通商品的价格/样式呈现隔离展示
- 底部汇总金额计算：商品总额正确累加所有行的小计
- 【重点】会员已省汇总：验证 `会员已省 = 1688原价对应金额 - Hubbuyer会员价对应金额` 正确累加，且普通商品不被计入
- 状态变更同步刷新：改变数量/勾选状态时，汇总金额、预估运费和会员已省需实时刷新
- 下一步拦截与放行：验证存在价格失效、预估运费未返回异常时，精准阻断并定位到商品

### 2.2 确认订单页面
- 费用一览加载快照：验证从购物车顺利透传预估国内运费及单价快照
- 【重点】代采手续费展示：验证会员账户展现代采手续费免除/减免逻辑，非会员正常收取
- 报价单支付金额计算：验证由商品金额、预估国内运费、选项费用和代采手续费累加的总额精准无误
- 平台服务费概念剥离：确认页面及提示未将平台服务费混入当前报价金额总计中

## 3. 前台报价单与支付 (C-QUOTE)
### 3.1 报价单列表与支付弹窗
- 列表页会员已省展示：验证每条报价单上的“会员已省”精准读取订单内商品节省之和
- 【重点】支付弹窗金额校验：验证弹窗的报价单金额必须等同于确认订单时的口径，外加平台服务费单列
- 支付通道拉起验证：平台服务费与报价单金额合计发起收银台，验证无丢精度问题

### 3.2 报价单详情页
- 快照持久化读取：验证详情页严格锁死下单时刻的 1688原价与 Hubbuyer价，不受后续大盘价格变动影响
- 【重点】跨端防篡改：修改 1688 线上价格后刷新已生成的报价单详情，验证金额坚挺不变
- 取消与下载操作：验证取消逻辑正常，且下载导出的文件金额与页面展示口径一致

### 3.3 订单详情页 (前台回显)
- 费用一览（报价视角）：验证完整复现报价单支付金额构成
- 费用一览（实际清算视角）：验证正确读取后台生成的实际清算金额（含正品金额、实际运费等）
- 【重点】订单差额处理卡：验证差额公式 `订单差额 = 实际结算金额 - 报价单支付金额 - 采购差额` 展示及正负补退款文案正确
- 订单与店铺明细下探：验证下钻的单品维度节省与全单总节省能够对账
- 【重点】本店节省计算逻辑：验证 `本店节省 = 本店商品金额节省 + 本店人工交涉节省` 且空值兼容

## 4. 后台订单管理 (A-ORDER)
### 4.1 后台代购订单详情页
- 【重点】全局单价霸权覆盖：验证订单明细内的商品单价**必须且仅能**呈现 `promotionPrice`
- 实际费用录入边界：维护质检、退换货、国内运费等字段的正负极值和边界小数
- 【重点】批量操作价格防漂移：执行一键发货、批量确认金额后，验证商品单价未被老旧单价污染复写

## 5. 后台清算与资金处理 (A-SETTLE)
### 5.1 后台订单清算弹窗计算
- 店铺清算明细拉取：校验自动拉取的正品金额、实际运费、不良退款金额默认值正确
- 实际结算金额联动试算：在明细中输入/修改数据，验证试算总额立刻反馈更新
- 【重点】清算公式引擎对账：代入边界值（零费用、负费用、多级小数），验证弹窗执行硬公式：`实际结算金额 = 客户价 + 附加项费用 + 质检费用 + 订单其他费用 + 代采手续费`
- 提示预警：模拟同一条业务数据同时填入差额与退款中，验证“核对来源”防重复录入警告触发

### 5.2 确定清算动作
- 【重点】清算审计强确认：点击“确定清算”，校验需执行二次确认，并强制写入清算快照与审计版本日志
- 【重点】差额补款引擎触发：构造 差额 > 0 场景，验证静默扣减客户账户余额，余额击穿时扣成不足金
- 差额退款引擎触发：构造 差额 < 0 场景，验证触发账务退款并标记退款单
- 平账放行：构造 差额 = 0 场景，验证纯写入日志而未发生任何资金冻结或流水流转

## 6. 全局导出规则 (G-EXPORT)
### 6.1 全局单价导出校验
- 【重点】全表单价格透传验证：生成订单、报价单、全商品、发货订单及采购处理表单下载件，验证所有涉及“单价”列的值均来源于 `promotionPrice`，与前台展示严格对齐。
