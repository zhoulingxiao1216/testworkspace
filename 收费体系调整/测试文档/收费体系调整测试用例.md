# 收费体系调整 - 测试用例

## 1.1 前台商品列表与详情 (C-GOODS)

#### TC-C-GOODS-001 【正向】有会员价的商品卡展示
| 字段 | 内容 |
|:--|:--|
| **测试点** | 有会员价的商品卡展示：验证 promotionPrice 存在时高亮展示 Hubbuyer 价格及原价划线 |
| **优先级** | Medium |
| **前置条件** | 1. 客户账号登录前台<br>2. 系统存在 1688 原价与 `promotionPrice` 均有效的商品（Item-A） |
| **操作步骤** | 1. 进入搜索页/首页商品列表<br>2. 找到对应商品卡片 |
| **预期结果** | 1. 1688原价呈弱化或划线状态<br>2. Hubbuyer会员价（`promotionPrice`）高亮展示<br>3. 价格旁展示等值的 USD/CNY 折算 |

#### TC-C-GOODS-002 【异常】价格异常降级展示 [SmokeTest]
| 字段 | 内容 |
|:--|:--|
| **测试点** | 价格异常降级：接口异常/格式非法时，卡片必须平滑降级为普通无会员价商品态 |
| **优先级** | Critical |
| **前置条件** | 1. 客户账号登录前台<br>2. 系统存在 `promotionPrice` 返回为 null、0 或格式异常的商品（Item-B） |
| **操作步骤** | 1. 浏览包含该商品的列表页<br>2. 点击进入该商品详情页 |
| **预期结果** | 1. 列表页卡片不展示 Hubbuyer价格区块（或展示为“无”）<br>2. 严禁回退展示旧版本商品单价<br>3. 详情页 Hubbuyer 价格同样降级为空态 |

#### TC-C-GOODS-003 【正向】详情页预估国内运费拉取 [SmokeTest]
| 字段 | 内容 |
|:--|:--|
| **测试点** | 预估国内运费拉取：验证选择完整 SKU 和数量后能成功拉取预估运费并实时展示 |
| **优先级** | Critical |
| **前置条件** | 1. 客户进入有效商品（Item-A）详情页 |
| **操作步骤** | 1. 选择有效的商品规格 (SKU)<br>2. 调整购买数量（≥最小起订量）<br>3. 观察页面预估国内运费加载状态 |
| **预期结果** | 1. 根据当前选中条件，成功调用 `product.freight.estimate` 接口<br>2. 页面正确渲染并展示预估国内运费<br>3. 商品金额随数量变动实时刷新 |

## 2.1 前台购物车与订单确认 (C-CART)

#### TC-C-CART-001 【正向】购物车会员已省金额汇总 [SmokeTest]
| 字段 | 内容 |
|:--|:--|
| **测试点** | 会员已省汇总：验证会员已省正确累加，且普通商品不被计入 |
| **优先级** | Critical |
| **前置条件** | 1. 购物车内同时包含一个会员价商品（Item-A）和一个普通商品（Item-C）<br>2. 二者均被勾选 |
| **操作步骤** | 1. 观察各商品行的价格展示<br>2. 观察底部汇总栏的“会员已省”与“预估国内运费” |
| **预期结果** | 1. Item-A 行展示高亮会员价及省钱提示，Item-C 行仅展示普通单价<br>2. 底部“会员已省”精准等于 Item-A 的 (1688原价金额 - 会员价金额)<br>3. Item-C 的价格差额未混入该汇总项 |

#### TC-C-CART-002 【正向】确认订单代采手续费展示 [SmokeTest]
| 字段 | 内容 |
|:--|:--|
| **测试点** | 代采手续费展示：验证会员账户展现代采手续费免除逻辑，非会员正常收取 |
| **优先级** | Critical |
| **前置条件** | 1. 分别使用 Account-Normal（非会员）和 Account-VIP（企业会员）登录<br>2. 从购物车结算进入确认订单页 |
| **操作步骤** | 1. 查看费用一览模块 |
| **预期结果** | 1. Account-Normal 页面展示并计算标准的代采手续费<br>2. Account-VIP 页面展示代采手续费划线并提示减免，实际计算该项为 0<br>3. 平台服务费不在此处混淆 |

## 3.1 前台报价单与支付 (C-QUOTE)

#### TC-C-QUOTE-001 【正向】支付弹窗金额校验与防伪 [SmokeTest]
| 字段 | 内容 |
|:--|:--|
| **测试点** | 支付弹窗金额校验：验证弹窗的报价单金额等同于确认订单时的口径，外加平台服务费单列 |
| **优先级** | Critical |
| **前置条件** | 1. 客户处于待支付状态的报价单列表<br>2. 报价单金额由 `promotionPrice` 汇总而成 |
| **操作步骤** | 1. 点击“立即支付”唤出收银台弹窗 |
| **预期结果** | 1. 弹窗明细显示的商品总额与原报价单完全一致<br>2. 支付总金额 = 报价单支付金额 + 平台服务费<br>3. 平台服务费明确单列展示，不污染原报价单金额 |

#### TC-C-QUOTE-002 【正向】报价单快照跨端防篡改 [SmokeTest]
| 字段 | 内容 |
|:--|:--|
| **测试点** | 跨端防篡改：修改 1688 线上价格后刷新已生成的报价单详情，验证金额坚挺不变 |
| **优先级** | Critical |
| **前置条件** | 1. 客户成功生成一张待入金的报价单<br>2. 模拟 1688 侧商品 `promotionPrice` 发出价格变更 |
| **操作步骤** | 1. 刷新报价单详情页<br>2. 执行报价单下载动作 |
| **预期结果** | 1. 页面商品单价、商品金额及总价牢牢锁定下单时快照，未发生变动<br>2. 下载的 PDF/Excel 中单价依然等于下单时快照金额 |

#### TC-C-QUOTE-003 【正向】订单差额与节省回显校验
| 字段 | 内容 |
|:--|:--|
| **测试点** | 订单差额处理卡：验证差额公式及本店节省计算逻辑展示无误 |
| **优先级** | High |
| **前置条件** | 1. 一笔已完成清算的订单，具有退款/补款金额<br>2. 店铺维度内存在人工交涉节省与会员价节省 |
| **操作步骤** | 1. 进入订单详情页<br>2. 展开店铺明细抽屉及本店节省字段 |
| **预期结果** | 1. 订单差额处理卡正确展示 `差额 = 实际结算 - 报价单支付 - 采购差额`<br>2. 本店节省 = 本店商品金额节省 + 本店人工交涉节省，且空值兼容展示无异常 |

## 5.1 后台清算与资金处理 (A-SETTLE)

#### TC-A-SETTLE-001 【正向】清算公式引擎对账计算 [SmokeTest]
| 字段 | 内容 |
|:--|:--|
| **测试点** | 清算公式引擎对账：验证弹窗执行硬公式进行实际结算金额及差额试算 |
| **优先级** | Critical |
| **前置条件** | 1. 财务账户进入订单清算弹窗<br>2. 针对指定订单填写各维度清算输入（含正副向金额） |
| **操作步骤** | 1. 录入质检、实际运费及其他选项费用<br>2. 点击“重新计算”按钮 |
| **预期结果** | 1. 系统即时吐出试算结果：`实际结算金额 = 客户价 + 附加项 + 质检 + 其他 + 代采手续费`<br>2. 同步计算出：`订单差额 = 实际结算金额 - 报价单支付金额 - 采购差额` |

#### TC-A-SETTLE-002 【异常】防重复录入预警
| 字段 | 内容 |
|:--|:--|
| **测试点** | 提示预警：模拟同一条业务数据同时填入差额与退款中，验证防重复警告触发 |
| **优先级** | High |
| **前置条件** | 1. 财务进入订单清算弹窗 |
| **操作步骤** | 1. 在“采购差额”与“店铺返现”两个字段输入高危相似数值<br>2. 尝试试算 |
| **预期结果** | 1. 系统抛出软提示警告，提醒“请核对金额来源，避免重复录入”<br>2. 确认知晓后允许流转，但不阻止人工强行通过 |

#### TC-A-SETTLE-003 【正向】差额自动扣款引擎触发 (补款) [SmokeTest]
| 字段 | 内容 |
|:--|:--|
| **测试点** | 差额补款引擎触发：构造差额>0场景，验证静默扣减客户账户余额及不足金击穿 |
| **优先级** | Critical |
| **前置条件** | 1. 一笔已试算完成且 `差额 > 0` 的订单<br>2. 客户余额分为充足与不足两种场景 |
| **操作步骤** | 1. 点击“确定清算”并完成二次权限校验 |
| **预期结果** | 1. 系统记录清算版本快照、操作人与审计日志<br>2. 若余额充足，自动静默扣减补差款<br>3. 若余额不足，将部分或全部差额转为客户“不足金”待追缴账单 |

#### TC-A-SETTLE-004 【正向】差额退款及平账放行引擎
| 字段 | 内容 |
|:--|:--|
| **测试点** | 差额退款/平账：构造差额<0或=0场景，验证退款或仅沉淀日志 |
| **优先级** | High |
| **前置条件** | 1. 分别准备 `差额 < 0` 和 `差额 = 0` 的待清算订单 |
| **操作步骤** | 1. 点击“确定清算”并确认 |
| **预期结果** | 1. `< 0` 场景触发账务退款逻辑，生成退款流水映射<br>2. `= 0` 场景不发生任何真实资金流转，仅写入已清算完毕状态及日志审计 |
