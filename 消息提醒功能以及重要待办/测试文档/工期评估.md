# 消息提醒功能以及重要待办 - 工期评估

## 一、估算前提

| 前提 | 说明 |
|:--|:--|
| 环境 | 测试环境可访问管理系统与 B2B 系统 |
| 账号 | 至少具备客户管理、B2B 订单管理、发货配送、重要待办、短信配置、右侧导航权限 |
| 数据 | 可创建或预置客户、报价单、代购订单、发货单、重要待办、消息、短信接收人 |
| 短信 | 有真实测试短信通道，或有可查的短信发送记录/Mock 通道 |
| 多语言 | B2B 多语言配置入口可用 |
| 范围 | 不包含性能压测、安全测试、短信运营商问题排查和站内信模板验收 |

## 二、建议排期

| 阶段 | 工时 | 工作内容 |
|:--|--:|:--|
| 需求确认与产品问题澄清 | 2h | 明确 0 值展示、实时 SLA、统计范围、短信人员、重要待办定义 |
| 测试数据准备 | 3h | 准备客户、客户经理、报价单、代购订单、发货单、重要待办、消息、短信接收人 |
| P0 主流程执行 | 6h | 执行气泡汇总、显示隐藏、实时增减、客户匹配、重要待办、短信、导航核心用例 |
| P1 异常与交互执行 | 5h | 执行加载失败、轮询、页面切换、多语言、点击跳转、多人短信、权限范围 |
| P2 稳定性抽样 | 2h | 刷新恢复、多标签、并发一致性抽样 |
| 缺陷复测与小回归 | 4h | 复测修复缺陷，回归核心计数与跳转链路 |
| 测试总结 | 1h | 输出执行结论、风险、遗留问题 |

合计：约 23 小时，按每日有效测试 8 小时折算，建议预留 3 个工作日。

## 三、压缩口径

| 压缩目标 | 执行策略 | 风险 |
|:--|:--|:--|
| 2 个工作日 | 只完整执行 P0 + 部分 P1 | 多语言、弱网、并发、短信异常覆盖不足 |
| 1.5 个工作日 | 只执行 SmokeTest 和最高风险数据一致性 | 右侧导航权限、重要待办异常、短信多人可能遗漏 |

## 四、延期触发条件

| 触发条件 | 预计影响 |
|:--|:--|
| 测试环境或账号不可用 | 延期 0.5 到 1 天 |
| 待审核订单/发货单/重要待办无法造数 | 延期 0.5 到 1 天 |
| 短信通道不可用且无发送记录替代 | 短信用例 Blocked 或延期 |
| 产品确认项影响 P0 判定 | 延期至口径确认后执行 |
| 多语言配置不可用 | 多语言用例 Blocked 或延期 |
