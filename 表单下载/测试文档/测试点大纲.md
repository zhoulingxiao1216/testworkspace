## 1. 用户端 — 移动端

### 1.1 货物核对 — 扫码入口
- 📋 验证货物核对为**独立 H5 页面**（非 APP 内嵌页面）
- 扫描有效箱子二维码：验证能否正常触发核对流程，获取对应发货单号和箱内商品信息
- 扫描无效/损坏二维码：验证系统异常处理
- 扫码后网络中断：验证断网场景提示

### 1.2 货物核对 — 登录判断
- 【重点】未登录状态扫码：验证自动跳转登录页
- 登录后自动恢复流程：验证登录成功后继续核对（非重新扫码）
- Token 过期状态扫码：验证是否要求重新登录

### 1.3 货物核对 — 商品归属判断
- 【重点】扫到非当前用户商品：验证显示提示页，不泄露他人数据
- 扫到当前用户商品：验证正常展示核对页面
- 当前用户无订单时扫码：验证空状态提示

### 1.4 货物核对 — 核对页面功能
- 商品列表展示：验证商品 ID、图片、名称、数量字段完整回显
- 🆕 商品详情字段（原型补充）：验证颜色/尺码/MySKU/订单编号均展示
- 🆕 导航栏 MySKU 展示：验证 navbar 显示当前用户 MySKU 和"扫描箱码"按钮
- 🆕 订单信息卡片：验证发货单编号、箱号、"共N箱，已核对M箱"统计
- 🆕 提示横幅：验证页面顶部展示核对提示（如有问题请联系客服）
- 图片加载失败：验证显示默认占位图
- 单个商品勾选/取消勾选：验证选中态变化（选中背景色 #e3f2fd）
- 全选复选框：验证全选/全取消功能（含 indeterminate 半选状态）
- 已核对统计：验证实时更新"已核对数量/总数量"
- 商品种类数和总数统计：验证数值准确性
- 🆕 响应式布局：验证 375px 小屏幕下图片/字体自适应缩放

### 1.5 货物核对 — 确认核对与状态保存
- 【重点】确认核对后状态持久化：验证刷新页面/重新扫码后核对状态保留
- 取消选择后保存：验证取消勾选的商品恢复为"未核对"
- 全选后取消部分再确认：验证仅未勾选的商品被取消核对
- 🆕 一个商品都未选择时点击确认：验证提示"请至少选择一个商品进行核对"
- 未核对全部商品时点击确认：验证系统提示
- 📋 【重点】箱级核对统计：箱中商品**全部**完成核对后，该箱才记录为"已核对"（共N箱，已核对M箱）
- 📋 部分核对场景：箱中仅部分商品核对 → 该箱不计入"已核对X箱"
- 核对完成后弹窗："扫描下一个箱子" → 继续/取消

### 1.6 货物核对 — 跨端同步
- 【重点】移动端核对后 PC 端状态同步：验证核对结果实时一致

## 3. 管理端 — 发货单详情

### 3.1 表单下载专区 — 布局与交互
- 表单下载专区位置：验证位于发货单详情页面右上角

- 配货单导出按钮：验证功能可用
- 🆕 物流公司下拉：验证物流公司选择（如 OCS）与面单生成的关联
- 🆕 运费明细区域：验证基本运费/燃油附加/税费/合计的展示和计算
- 🆕 附加项区域：验证附加项名称/数量/单价/小计 + "+添加其他费用"功能
- 🆕 收货地址/进口商地址选择器：验证地址下拉与表单填充的联动
- 🆕 关税缴纳方式：验证"物流公司代付" vs "进口商关税账号"单选切换
- 🆕 商品搜索和状态筛选：验证商品ID搜索 + 配货状态下拉筛选功能

### 3.2 表单下载专区 — 纳品书
- 纳品书下拉默认提示："请选择纳品书"
- 纳品书下载：验证文件生成 + 字段填充完整
- ZOZO 纳品书下载：验证 ZOZO 专用字段（品番/カラー/サイズ/上代）
- 带地址和附加项纳品书：验证发货地址附加信息

- 用户端纳品书导出（个人中心 → 配送管理 → 国际配送 → 详情）

### 3.3 表单下载专区 — 商业发票
- 发票下拉默认提示："请选择发票"
- OCS 发票下载：验证字段（OCS NO/收发件人/商品/签名等）
- TW 发票下载：验证 TW 专用字段（进口商法人番号/ASIN/FNSKU/箱号等）
- 流通王发票下载：验证三方信息（发件/进口/收货）+ 贸易方式
- 海源发票下载：验证海源专用字段（Email/FN/箱号尺寸重量等）
- LDX 发票下载：验证 LDX 专用字段（服务渠道/进口商完整信息/声明等）
- 【重点】商业发票合并：验证跨订单同规格同价格商品合并为一条
- 【重点】商业发票合并 — 金额一致性：合并后金额 = 单价 × 合并数量 = 原各条目金额之和
- 商业发票合并 — 不合并场景：仅规格相同价格不同/仅价格相同规格不同
- 【重点】7182 商业发票：验证客户 ID 显示为 `JPN7182`

### 3.4 表单下载专区 — 面单

## 4. 技术支撑层

### 4.1 模板字段映射
- 【重点】30+ 种表单模板字段与 PRD "项目对应字段" 列的 1:1 对齐验证
- 🆕 【重点】`字段获取.json` 与 Excel 模板的交叉验证：JSON 中声明的字段列表必须与实际 Excel 模板列头完全一致
- 可空字段（如 `product.usage`）空值时不导致模板渲染异常
- 模板占位符替换完整性：MUST NEVER 出现 `null`/`undefined`/未替换变量

### 4.2 数据填充引擎
- 【重点】数值精度：金额字段保留 2 位小数，无浮点误差
- 数据获取接口异常：接口超时/返回空数据时的降级处理
- Excel 文件生成：文件格式正确、可正常打开

### 4.3 权限与接口验证
- 登录状态检查接口 (`user/login/check`)
- 商品归属验证接口 (`order/goods/owner`)
- 核对状态保存接口 (`order/goods/verify`)
- 核对状态批量保存接口 (`order/goods/verify/batch`)
- 表单数据获取接口 (`order/export/data`)
- 表单生成接口 (`export/generate`)
- 英文品名材质获取接口 (`goods/english/info`)

### 📋 4.4 多语言验证（会议纪要 #2）
- 【重点】日本用户：表单标签（如"公司名称""邮编""电话"等）显示**日文**
- 【重点】其他国家用户：表单标签显示**英文**
- 标签 vs 内容区分：表单标签多语言显示，但**实际内容（如商品名称）仍显示中文**
- 多语言覆盖范围：所有 30+ 种表单模板均需验证多语言标签
- 语言切换不影响数据精度：切换语言后金额/数量等数值不应改变

### 📋 4.5 模板数量与规范验证（会议纪要 #5）
- 【重点】模板总数验证：7 个面单模板 + 19 个其他模板 = **26 个模板**，需按照模板规范严格执行
- 模板文件完整性：28 个 Excel 文件中覆盖全部 26 个业务模板
- 每个模板的列头/格式/布局必须与 PM 提供的模板文件 100% 一致
