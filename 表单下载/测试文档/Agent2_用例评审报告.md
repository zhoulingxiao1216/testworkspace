### 2.1 操作步骤精细度审计（SKILL 约束 #1：严格按步骤执行）

Agent 2 **必须逐步执行操作步骤，不得跳步或合并**。以下用例的步骤颗粒度不足，Agent 2 执行时可能产生歧义：

| # | 用例 | 当前步骤描述 | 改进建议 | 严重度 |
|---|------|------------|----------|--------|
| E-1 | TC-FD-015 | "逐模板下载/打印" | 建议明确：步骤拆分为 "1. 下载纳品书 → 2. 下载 ZOZO 纳品书 → 3. 下载 OCS 发票 → …"，或标注 "按交接清单中 26 个模板逐一执行" | 中 |
| E-2 | TC-FD-018 | "下载所有类型表单" | 同上，Agent 2 需明确 "所有" 的范围 = YAML 中 26 个模板 | 中 |
| E-3 | TC-MV-007 | "等待 Token 过期或手动修改 Token" | 建议明确：改为 "打开 DevTools → Application → Cookies → 修改 Token 值为 `expired_xxx`" | 低 |
| E-4 | TC-FD-003 | "通过 API 工具直接调用下载接口" | 建议补充具体接口路径和参数样例，如 `curl -X POST /api/export/generate?orderId=INVALID` | 低 |
| E-5 | TC-MV-021 | "将浏览器窗口调至 375px 宽度" | 建议明确：Chrome DevTools → Toggle Device Toolbar → Width: 375 | 低 |
| E-6 | TC-PM-008 | "查看订单详情页面" | 建议补充导航路径："管理端 → 订单管理 → 找到该商品所在订单 → 点击详情" | 低 |
| E-7 | TC-OD-006 | "逐字段对比语义映射" | 建议提供预期的映射表（已在预期结果中部分给出，但不完整） | 低 |

> **改进建议等级说明**：
> - "中" = Agent 2 执行时会暂停并需人工确认范围
> - "低" = Agent 2 可自行推断执行，但可能产生录屏不一致

### 2.2 中文输入限制适配（SKILL 约束 #7：纯文本限制）

Agent 2 的浏览器交互 **不支持原生中文键盘输入**，以下用例涉及中文输入需标注 JS 注入方案：

| 用例 | 涉及中文输入 | JS 注入方案 |
|------|-------------|------------|
| TC-PM-004 | 修改中文品名 | `document.querySelector('.product-name-input').value = '测试品名'; dispatchEvent(new Event('input'))` |
| TC-PM-005 | 统一修改中文材质为"纯棉" | 下拉选择方式（非文本输入），代码层面无需 JS 注入 ✅ |
| TC-PM-008 | 修改品名为"测试品名A" | 同 TC-PM-004 方案 |
| TC-MV-006 | 输入正确账号密码 | 建议使用 ASCII 账号，避免中文用户名 ✅ |

> ⚠️ **建议 Agent 1 补充**：在 TC-PM-004 和 TC-PM-008 的操作步骤中加注 `（注：Agent 2 通过 JS 注入设置值）`。
