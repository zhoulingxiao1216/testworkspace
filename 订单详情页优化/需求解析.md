生成日期：2026-05-21

## 1. 需求背景

全球站 1.0 上线后，业务部门反馈代购订单详情页和进行中列表存在定位效率问题：商品多时缺少商品级筛选，采购无法快速找到问题商品、未确认金额订单、未购买订单。DOCX 提到本需求汇总包含任务 `1001257`、`1001254`。

## 2. 需求范围

| 模块 | 路径 | 需求点 | 状态 |
| --- | --- | --- | --- |
| 订单详情页筛选栏 | 全球站后台 → B2B系统 → 订单管理 → 代购订单 → 进行中 → 详情 | 新增商品 ID、商品状态、采购状态、质检状态筛选 | 明确 |
| 采购确认 | 全球站后台 → B2B系统 → 订单管理 → 代购订单 → 进行中 → 详情 → 采购确认 | 采购差价为负数时点击采购确认弹窗提醒，不允许确认 | DOCX 标记“暂缓” |
| 店铺返现二次确认 | 订单详情页采购相关字段区域 | 店铺返现新增二次确认，未确认不进入采购差价，确认后锁定 | DOCX 标记“看开发评估” |
| 进行中列表金额确认筛选 | 全球站后台 → B2B系统 → 订单管理 → 代购订单 → 进行中 | 新增“金额是否确认”：全部、已确认、未确认 | 明确 |

## 3. 功能规则

### 3.1 订单详情页筛选栏

| 筛选项 | 默认值 | 选项/规则 |
| --- | --- | --- |
| 商品 ID | 空 | 商品的 SKU，支持精确匹配 |
| 商品状态 | 全部 | 全部、待入库、部分入库、已入库 |
| 采购状态 | 全部 | 全部、待采购、部分到货、暂不购买 |
| 质检状态 | 全部 | 全部、有不良、有待定、有退货、有换货、待检品 |

状态判定：

| 状态 | 判定规则 |
| --- | --- |
| 待入库 | 正品数量更新后和已入库数量不同，且已入库数量为 0 |
| 部分入库 | 正品数量和已入库数量不相同，且已入库数量不为 0 |
| 已入库 | 正品数量和已入库数量相同，发货数量为 0 |
| 待采购 | 允许采购审核完成后，还未更新采购数据的商品状态 |
| 部分到货 | 到货数小于采购数 |
| 暂不购买 | 通过“暂不购买”按钮展示对应状态 |
| 有不良/有待定/有退货/有换货/待检品 | 对应数量大于 0 时展示 |

测试重点：默认全部、精确匹配、无结果空态、多条件交集、多店铺多商品、大订单性能、刷新返回不串单。

### 3.2 采购差价负数采购确认

规则：当采购差价为负数时，点击采购确认直接弹窗提醒，文案为“采购差价不允许为负数，请核对后再确认！”，且不允许完成采购确认。该项 DOCX 标记“暂缓”，执行前需确认是否进入本次版本。

测试重点：负数和 `-0.01` 边界、0 和正数不误拦截、拦截后状态不更新、后端接口防绕过。

### 3.3 店铺返现二次确认

规则：店铺返现字段新增二次确认按钮；未确认时红色，确认后绿色；未确认前填写金额只在店铺返现栏中，不同步到采购差价；二次确认后采购员无权限再次修改。该项 DOCX 标记“看开发评估”。

测试重点：未确认金额持久化、不影响采购差价、确认后锁定、采购员权限、其他角色是否可改需确认、金额输入边界。

### 3.4 进行中列表金额是否确认筛选

规则：进行中列表新增“金额是否确认”下拉框，默认全部，选项为全部、已确认、未确认。金额是否确认指订单中包含“采购确认”按钮未点击确认商铺的订单。多商铺订单中，只要有一个商品未采购确认，该订单也归纳到金额未确认。筛选未确认时，还需满足 `采购数 = 不良数 + 正品数`，两个条件任一不满足都不展示。

测试重点：已确认/未确认、多商铺任一未确认、数量公式满足与不满足、列表详情一致、筛选分页联动。

### 3.5 进行中列表购入数排序

规则：在购入数字段添加排序按钮，点击后购入数量为空的订单自动排到最上面。该项 DOCX 标记“开发评估”。

测试重点：空值置顶、0 与空值区分、多页全量排序、与金额确认筛选联动、恢复默认排序。

## 4. 影响模块

| 模块 | 影响说明 |
| --- | --- |
| 全球站后台 B2B 代购订单详情页 | 新增商品筛选栏，影响商品列表、状态展示、操作入口 |
| 全球站后台 B2B 代购订单进行中列表 | 新增金额确认筛选，购入数排序可能影响查询接口和分页 |
| 采购确认流程 | 采购差价负数拦截影响金额确认状态 |
| 店铺返现/采购差价计算 | 未确认返现不进入采购差价，确认后锁定 |
| 权限体系 | 采购员确认后不可修改店铺返现，其他角色权限待确认 |
| 接口与数据口径 | 商品 SKU 精确匹配、状态筛选、金额筛选、排序均可能涉及后端查询 |
