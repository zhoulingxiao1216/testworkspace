# 测试引擎行为基准（Test Engine Rules） - 采购员篇

> **核心导向**：本库已升级为自动化测试引擎判断基准。所有规范均围绕底层四维法则（连贯性、大盘降维、视觉防御、心理安全）输出明确断言，直接作为 Dify 等 AI 引擎生成用例的第一指引。

---

## 1. [视觉防御法则] 去伪按钮化的防误点击排雷原则

- **法则定义**：对于操作频率极高的底层采买干系人，对高对比度实底块色系的识别肌肉记忆极速。在任何页面，如果标签、文字或被禁用的非交互区域被设计出类似“可按压按钮”的外形伪装，必定激起无效连点尝试，造成强烈操作挫败及歧义断流。
- **引擎 Prompt / 测试断言用例**:
  - **前置动作**：打开任何具有复杂数据或禁售通道状态的商品页/订单页。
  - **操作步骤**：模拟视觉扫描所有展示区域，包括标签 Tag 和非交互警告区。
  - **Assert 预期条件**：
    - `Assert.True(label_tag.has_no_padding_shadow() or label_tag.is_outlined())` — 纯展示状态不能出现厚重阴影与全包裹按钮级强实底填色。
    - `Assert.False(disabled_area.looks_like_clickable_button())` — 切断所有类似交互暗示的视觉陷阱，严格遵循可点与不可点 UI 层级差法则。

---

## 2. [连贯性法则] 瀑布流大修备注悬浮框视觉规避防侵扰机制

- **法则定义**：处理大规模商品/网单时，面对成百上千行记录进行逐一“大修备注添加、补充记录等”流水操作，用户的视线向下位移呈现高度紧密的连续瀑布流。哪怕在第 N 行触发的浮动弹层短暂侵入/掩盖第 N+1 行的任何数据元，都会引爆怒火与操作连贯性的绝对崩盘。
- **引擎 Prompt / 测试断言用例**:
  - **前置动作**：进入附带超过数百长明细行且可逐一备注的数据大表页（如采购车、打回修改列表）。
  - **操作步骤**：于连续三列触发修改状态拉起弹层组件。
  - **Assert 预期条件**：
    - `Assert.False(popover[line_N].overlaps(data_cell[line_N+1]))` — 当前激活的扩展备注编辑气泡绝对不允许悬伸甚至遮盖下文邻近可视数据区，务必设计为视口自适应规避/嵌入式下拉。
