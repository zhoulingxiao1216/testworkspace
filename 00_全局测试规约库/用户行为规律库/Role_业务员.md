# 测试引擎行为基准（Test Engine Rules） - 业务员篇

> **核心导向**：本库已升级为自动化测试引擎判断基准。所有规范均围绕底层四维法则（连贯性、大盘降维、视觉防御、心理安全）输出明确断言，直接作为 Dify 等 AI 引擎生成用例的第一指引。

---

## 1. [连贯性法则] 弹窗多标签/长表单的局部保存驻留断言

- **法则定义**：在面对多维度分组或多页签弹窗表单（如复杂的账单填写、多维附加项记录）时，系统不能自作主张中断人类的连贯数据输入，【局部保存】动作绝对不能触发【大窗口关闭】。
- **引擎 Prompt / 测试断言用例**:
  - **前置动作**：触发带有子页签(Tab)或长步骤组合的模态弹窗表单。
  - **操作步骤**：在局部页签A内填入数据，点击弹窗页面内提供的“保存/确定/下一步”基础功能按钮。
  - **Assert 预期条件**：
    - `Assert.True(modal.is_visible())` — 主弹窗结构必须维持开启状态不被粗暴销毁。
    - `Assert.True(focus.is_active(modal))` — 用户视觉焦点不被强行剥脱，系统须引导或允许平滑进入下一页签。

---

## 2. [大盘降维法则] 工作台操作坐标系强绑定断言

- **法则定义**：高频批处理业务流水线中，业务员深度依赖特定区域的“肌肉盲操”。同类业务实体在处理不同状态、不同关联店铺分支时，其核心操作按钮台（保存、挂起、打印等）的位置必须固定咬死。
- **引擎 Prompt / 测试断言用例**:
  - **前置动作**：载入任何 B 端工作台性质的详情单页面（如代购大单处理工作台）。
  - **操作步骤**：模拟用户高频切换不同状态的单据记录，或调整账单分类数据。
  - **Assert 预期条件**：
    - `Assert.Equals(control_panel.bounding_box(), reference_box)` — “功能工作台区域”在页面局部刷新发生后，不准发生 X轴/Y轴的乱序跳帧位移。

---

## 3. [大盘降维法则] 无操作列表格极简化断言

- **法则定义**：在屏宽被严重压缩办公场景下（如 1366x768 笔记本、150% DPI 缩放），列表中绝不允许以单独扩展单列的形式存在冗余的“修改/删除”列。必须将空间让给业务数据，利用“复选框+底栏悬浮”做到批单合一。
- **引擎 Prompt / 测试断言用例**:
  - **前置动作**：渲染超过 8 个关键业务列属性的长列表页（如购物车页、流转处理单）。
  - **操作步骤**：锁定浏览器环境至横纵空间最狭窄的临界值，验证操作可行度。
  - **Assert 预期条件**：
    - `Assert.False(table.has_column_named('操作'))` — 数据表末尾不允许设置独立的低效操作列。
    - `Assert.True(page.has_sticky_bottom_bar())` — 底部悬浮栏必须处于一直可见状态，统一承担批处理与单条打回的责任归集。

---

## 4. [视觉防御法则] 源单数据穿透防遮挡法则

- **法则定义**：当涉及数据对账比对时，如果底层展示关键原始数据（如订单初始价金额），此时弹出的修改修正小窗禁止强制居中从而遮挡工作台上层依赖性对照点。
- **引擎 Prompt / 测试断言用例**:
  - **前置动作**：打开详情页的核心数据区域。
  - **操作步骤**：点击数值旁的“修改 / 填报附加信息 / 输入差值”拉起输入侧边栏或弹窗。
  - **Assert 预期条件**：
    - `Assert.False(modal.bounding_box().overlaps(source_key_data.bounding_box()))` — 用户当前用于验证计算的被依赖基准字号，绝对不能被弹窗从Z轴物理遮盖（应采用偏置弹窗抽屉解决）。
