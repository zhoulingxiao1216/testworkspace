# 缺陷报告编写规范

> **适用范围**：所有项目测试执行过程中发现的缺陷记录。
> **配套文档**：与《测试执行报告规范》配合使用。

---

## 一、文件命名与存放

| 规则 | 说明 |
|------|------|
| 文件名格式 | `缺陷清单_YYYY-MM-DD.md` |
| 存放路径 | `{项目}/测试文档/执行报告/` |
| 缺陷编号格式 | `BUG-{模块缩写}-{三位序号}` |
| 模块缩写来源 | 必须从项目 `superpowers.md` 的【模块缩写配置表】中读取 |

---

## 二、缺陷模板

```markdown
## BUG-{模块}-{序号} {标题}

| 字段 | 内容 |
|------|------|
| **严重等级** | {Critical / Major / Minor / Trivial} |
| **关联用例** | {TC-XX-NNN} |
| **测试环境** | {环境 URL / 系统版本 / 浏览器 / 测试账号} |
| **复现步骤** | 1. ... <br> 2. ... <br> 3. ... |
| **预期结果** | {引用用例中的预期结果} |
| **实际结果** | {实际观察到的现象，含具体数值/状态} |
| **复现率**   | {必现 / 高概率 / 偶现 / 仅一次} |
| **截图**     | ![](screenshots/BUG-XX-001.webp) |
```

---

## 三、严重等级判定标准

| 等级 | 判定条件 | 示例 |
|------|---------|------|
| **Critical** | 系统崩溃/数据丢失/资金错误/安全漏洞/核心流程中断 | 订单金额计算错误、越权访问、支付失败 |
| **Major** | 核心功能不可用但有 workaround / 数据展示严重错误 | 会员等级价显示错误、拦截弹窗未触发 |
| **Minor** | 非核心功能异常 / UI 显示轻微偏差 | 按钮文案错误、排版错位 |
| **Trivial** | 纯视觉瑕疵 / 建议优化 | 颜色不一致、间距微调 |

---

## 四、字段书写规范

### 4.1 标题
- 格式：`[现象动词] + [具体对象] + [异常表现]`
- 长度：≤ 30 字
- 示例：`日本站附加项价格展示为 USD 而非 JPY`

### 4.2 复现步骤
- 使用数字序号 + `<br>` 分隔（与测试用例格式一致）
- 每步骤只写**操作**，不写预期
- 必须包含：从哪个页面开始、用什么账号、点击什么按钮

### 4.3 预期结果 vs 实际结果
- **预期**：直接引用关联用例的预期结果（可简写核心部分）
- **实际**：写明**具体观察到的数值/状态/页面表现**，严禁笼统写"异常"或"报错"
- 如有控制台错误信息，附加在实际结果下方用代码块包裹

### 4.4 截图
- 必须附加至少一张截图
- 截图应圈标或箭头标注问题区域（如果工具支持）
- 命名遵循 `BUG-{模块}-{序号}.webp` 格式

---

## 五、缺陷与用例关联

| 规则 | 说明 |
|------|------|
| 1:1 关联 | 每个缺陷必须关联至少一条用例编号 |
| 反向标记 | 在执行报告的对应用例日志中标注 `关联缺陷：BUG-XX-NNN` |
| 新发现缺陷 | 执行过程中发现用例未覆盖的问题，缺陷仍需记录，关联用例填 `N/A - 探索性测试` |

---

## 六、一致性自检清单

- [ ] 缺陷编号 `BUG-{模块}-{序号}` 格式正确且序号连续
- [ ] 模块缩写来自 `superpowers.md` 字典表
- [ ] 所有必填字段非空（严重等级/关联用例/环境/步骤/预期/实际/复现率/截图）
- [ ] 复现步骤使用数字序号
- [ ] 实际结果包含具体数值或状态，非笼统描述
- [ ] 截图已附加且命名规范
- [ ] 严重等级与判定标准表一致
- [ ] 执行报告中对应用例已反向标记缺陷编号
