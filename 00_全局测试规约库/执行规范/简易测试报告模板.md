# 简易测试报告模板

> 本模板参考 `C:\Users\Administrator\Desktop\简易模板.xlsx` 的轻量字段结构。  
> 适用场景：小需求、Bug 修复回归、快速上线验收。  
> 固定只保留 5 个部分：**测试结论、项目基础信息、测试环境、测试范围、缺陷明细**。

## 1. 适用范围

| 场景 | 是否适用 | 说明 |
|:--|:--:|:--|
| Bug 修复回归 | 是 | 用于快速记录问题、修复结果、测试范围和结论。 |
| 小需求上线验收 | 是 | 用例数量少、范围清晰、缺陷闭环简单时使用。 |
| 快速回归测试 | 是 | 用于轻量记录测试环境、范围和结果。 |
| 大型项目正式验收 | 否 | 应使用 `上线验收测试报告规范.md` 的完整版结构。 |

## 2. 字段要求

| 章节 | 必填内容 | 说明 |
|:--|:--|:--|
| 测试结论 | 测试结论、当前阶段、发布建议 | 必须放在报告最前面。 |
| 项目基础信息 | 项目名称、测试类型、项目类型、项目描述、测试人员、测试时间、数据来源 | 从需求、Bug 链接、执行结果或人工确认中提取。 |
| 测试环境 | 测试环境、浏览器及版本、操作系统、测试分辨率、测试客户端 | 未提供时可写“未提供”，不要虚构。 |
| 测试范围 | 覆盖模块、覆盖页面/接口/流程、核心测试点、结论 | 只写本轮实际覆盖范围。 |
| 缺陷明细 | 缺陷 ID、严重程度、状态、问题摘要、上线影响 | 无缺陷时写“本轮未发现开放缺陷”。 |

## 3. 结论判定口径

| 结论 | 判定条件 | 写法 |
|:--|:--|:--|
| 测试通过 | 有效范围全部通过，无开放阻塞缺陷 | `测试通过，具备上线条件` |
| 附条件上线 | 核心范围通过，但存在非阻塞遗留项且有规避方案 | `附条件上线，需按遗留风险跟进` |
| 暂缓上线 | 核心范围失败，或存在未关闭 Critical/High 缺陷、权限/数据安全风险 | `暂缓上线，修复并回归后再评估` |

## 5. 使用要求

- 简易报告不得额外增加“用例执行统计、质量与缺陷统计、Superpowers 审计、风险建议、变更记录”等长章节。
- 结论必须放在第一章，且必须明确写“测试通过 / 附条件上线 / 暂缓上线”。
- 未提供的信息写“未提供”，不要虚构环境、浏览器、版本提交次数或执行数据。
- 没有执行结果来源时，只能生成待执行模板，不能写正式“测试通过”。
- 如存在未关闭 Critical/High 缺陷、核心范围失败、权限或数据安全风险，结论必须写“暂缓上线”。
