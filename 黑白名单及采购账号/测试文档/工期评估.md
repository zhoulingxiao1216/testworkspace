## 四、重点说明

**核心互斥测试要求（高优先级）**
- **单点生效校验**：同一平台下（比如淘宝），严禁存在 ≥2 个处于“启用”状态的采购账号，变更动作具备事务强一致性。
- **脏数据自保测试**：通过人工打入冲突的脏数据后，一键采购调用动作必须强制熔断并触发对应的异常告警弹窗，而不是“随机”挑选。

**权限与底层隔离边界验证**
- **强行调用绕过拦截测试**：必须构造非授权节点的 API 越权直连测试，验证中间件层物理拦截机制未出现缝隙。
- **沙箱隔离验证**：1688 与淘宝的 Token 更新回调不得混淆、或者互相串改已绑定的状态机数据。

**测试环境高频前提阻塞预警清单**
- 由于黑白名单测试强依赖物理级别的 IP 鉴权，必须提前准备装有大量独立代理节点配置的 `Clash Verge`。
- 测试过程中由于采购系统需要高频调试并记录 Token 时效，必须预留至少 3 个 1688、淘宝真实且通过实名验证的企业采购测试账号。
