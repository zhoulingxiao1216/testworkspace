# 国内快递签收模块 — 完整技术方案 & 接口文档

> **后端控制器**：`DomesticExpressController` / `DomesticExpressConfigController`  
> **后端服务层**：`DomesticExpressService`  
> **异步队列**：`ExpressTraceQueue`（Redis Queue）  
> **数据来源**：测试服线上代码，2026-05-19  
> **请求方式**：全部 `POST`，需 `Authorization: Bearer <admin_token>`  
> **响应格式**：`{ "code": 200, "msg": "success", "data": { ... } }`

---

## 一、核心数据模型

### 主表：`b2b_domestic_express`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | int | 主键 |
| `package_no` | varchar | 快递单号（唯一索引） |

| `receipt_time` | datetime | 签收时间 |
| `receipt_admin_id` | int | 签收人 |
| `shipping_time` | varchar | 发货时间（从轨迹反推，异步写入） |
| `takeover_time` | datetime | 初检部揽收时间 |

## 三、技术方案

### 3.1 签收流程状态机

```
[扫码/录入 package_no]
        ↓
 库中是否已存在？
    ↙           ↘
  是               否
  ↓                ↓
有 receipt_time？  调 DomesticExpressService::matchOrder()
  ↙       ↘         ↓ 通过 china_waybill 反查
 有         无      matched？
  ↓         ↓      ↙      ↘
返回       写入   是         否
already   签收   is_private=0  is_private=1
receipted 时间   handle_status=100  handle_status=200
                (待处理)          (私人，默认已处理)
                  ↓
            插入 b2b_domestic_express
                  ↓
          投递 express_trace_queue
         (异步获取轨迹 + 补全 shipping_time)
```

**状态字段说明**

| `handle_status` | 含义 |
|----------------|------|
| 100 | 待处理（签收后默认） |
| 200 | 已处理（调用 `takeover` 或 `handle` 后设置） |

---

### 3.2 轨迹查询缓存设计（traceInfo）

```
前端调用 traceInfo(package_no)
         ↓
1. 从 b2b_domestic_express 取 platform_order_no
         ↓（如空）
2. 从 china_waybill WHERE package_no=? 取 platform_order_no
         ↓（如仍空）
返回错误：缺失平台订单号，无法查询
         ↓（有 platform_order_no）
3. 查 china_waybill 缓存（WHERE order_no=? AND (package_no=? OR platform_order_no=?)）
         ↓
┌────────────────────────────────────────┐
│  trace_status = 'delivered'（已签收）    │ → 直接返回缓存（永不过期）
├────────────────────────────────────────┤
│  trace_status = 'fetched'              │
│  + trace_updated_at < 6小时前          │ → 直接返回缓存
├────────────────────────────────────────┤
│  无缓存 / 缓存已过期                     │ → 调 1688 API（实时拉取）
└────────────────────────────────────────┘
         ↓（实时拉取后）
4. 判断最后一条轨迹是否包含"签收"字样
   → 是：trace_status = 'delivered'（永久缓存）
   → 否：trace_status = 'fetched'（6小时缓存）
         ↓
5. 更新 china_waybill（trace_data / trace_status / trace_updated_at）
         ↓
6. 从轨迹第一条（最早一步）提取 acceptTime → 写入 b2b_domestic_express.shipping_time
         ↓
返回轨迹数据给前端
```

**TTL 汇总表**

| `trace_status` | 触发条件 | 有效期 | 策略 |
|---------------|---------|--------|------|
| `delivered` | 轨迹最后步骤含"签收" | 永久 | 不再重复调用 1688 |
| `fetched` | 正常获取但未签收 | 6 小时（21600s） | 6 小时后重新实时拉取 |
| 无缓存 | 首次查询 | — | 直接实时拉取 |

---

### 3.3 异步队列：ExpressTraceQueue

**触发时机**：`receipt`（扫码签收新包裹）、`addManual`（手工录入）  
**Queue 名**：`express_trace_queue`（Webman Redis Queue）  
**连接**：`default`

**投递 Payload**

```json
{
  "express_id": 123,
  "package_no": "SF1234567890",
  "platform_order_no": "1688xxxxx",
  "order_no": "ORD20260519001"
}
```

**消费者执行流程（ExpressTraceQueue::consume）**

```
收到消息
    ↓
platform_order_no 为空？
    ↓ 是
从 DomesticExpressOrder / ChinaWaybill 补充 platform_order_no
    ↓ 仍为空
终止任务（无法调 1688）
    ↓ 有
调 FreightService::logisticsTraceInfo('B2B', platform_order_no, package_no)
    ↓ 失败
终止
    ↓ 成功
1. 写入/更新 china_waybill.trace_data + trace_status + trace_updated_at
2. 从轨迹提取 shipping_time → 若 b2b_domestic_express.shipping_time 为空则写入
```

---

### 3.4 超时判断规则（DomesticExpressService::isTimeout）

**规则**

| 签收日期 | 超时阈值 | 备注 |
|---------|---------|------|
| 周一 ～ 周五 | `timeout_weekday_hours`（默认 24h） | 可通过配置接口修改 |
| 周六 | `timeout_saturday_hours`（默认 48h） | 可通过配置接口修改 |
| 周日 | **永不超时** | 硬编码逻辑 |
| 法定节假日 | **永不超时** | 从 `holidays` 配置项读取 |

**触发时机**

- 每次调用 `list` 接口，`DomesticExpressService::refreshTimeoutStatus()` 自动遍历所有未处理包裹，实时计算并更新 `is_timeout` / `timeout_hours` 字段
- 调用 `takeover`（揽收）时，以签收时间 → 揽收时间计算一次并写库

---

### 3.5 订单匹配策略（DomesticExpressService::matchOrder）

```
传入 package_no
    ↓
SELECT * FROM china_waybill WHERE package_no = ?（可能多条，一包多单）
    ↓ 为空
返回 matched=false（私人包裹）
    ↓ 有记录
汇总所有关联订单信息
提取 primary_order_no（第一条）
提取 primary_platform_order_no（第一个非空）
提取 primary_logistics_name + logistics_id（第一个非空）
    ↓
返回 { matched:true, order_no, platform_order_no, data:[...多订单] }
```

---

### 3.6 列表页数据拼装（多表关联，非 JOIN）

```
1. b2b_domestic_express 主表按条件分页（EXISTS 子查询实现跨表筛选）
2. 批量取所有 package_no → china_waybill 中批量查（IN 查询）
   └ 拼装：logistics_name / platform_order_no / send_time / orders[]
3. 对 logistics_name 缺失的兜底再查一次 china_waybill
4. 批量取关联的 admin_id → admin 表批量查 IN
   └ 拼装：takeover_admin_name / sale_admin_name / purchase_admin_name
5. 实时计算 handle_duration_text（接手时间 - 签收时间）
```

> 设计原则：**不用 JOIN**，用 PHP 层组装，避免 N+1，批量 IN 查询。

## 四、测试重点清单

| # | 测试项 | 关注点 |
|---|--------|--------|
| 1 | 签收新包裹 | `china_waybill` 有记录时能否正确匹配订单 |
| 2 | 重复扫码签收 | 已有 `receipt_time` 时应返回 `already_receipted`，不重复写库 |
| 3 | 私人包裹扫码 | `is_private=1`，`handle_status=200`，不进待处理队列 |
| 4 | traceInfo 缓存命中 | `delivered` 状态下永远不调 1688，返回缓存 |
| 5 | traceInfo 缓存过期 | `fetched` + 超过 6h，需重新调 1688 |
| 6 | traceInfo 缺 platform_order_no | 报错 `"缺失平台订单号，无法查询详细物流轨迹"` |
| 7 | 超时判断——周日签收 | 无论多久都不超时 |
| 8 | 超时判断——法定节假日 | `holidays` 配置内的日期不超时 |
| 9 | 手工录入不传 order_no | 自动走 `matchOrder` 匹配，需验证匹配结果 |
| 10 | 手工录入重复单号 | 报错 `"该快递单号已存在"` |
| 11 | 异步队列消费 | 签收/录入后验证 `shipping_time` 是否在队列处理后被写入 |
| 12 | 列表跨表筛选 `create_date` | 筛的是 `china_waybill.send_time`，不是主表时间 |
| 13 | `takeover` 揽收后超时计算 | 验证 `timeout_hours` = 揽收时间 - 签收时间 |
| 14 | `handle` 处理私人包裹 | 应报错拦截 `"私人包裹无需处理"` |
| 15 | `handle` 处理已处理包裹 | 应报错拦截 `"该包裹已处理"` |
